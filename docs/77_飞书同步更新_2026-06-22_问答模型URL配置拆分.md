# 飞书同步更新：问答模型 API URL 与 Ollama URL 配置拆分

## 背景

本轮修正设置页和后端运行时中“API Provider URL / 本地 Ollama URL 共用同一字段”的问题。

旧实现里只有 `ollama_base_url` 一个字段：

- 当 provider 是 `openai-compatible` 时，它实际保存 `https://api.siliconflow.cn/v1`。
- 当 provider 是 `ollama` 时，它又需要保存 `http://127.0.0.1:11435`。

这会导致切换 provider 或测试连接时两个 URL 互相覆盖。

## 本轮完成

- 后端新增 `api_base_url` 字段。
- `ollama_base_url` 只表示本地 Ollama 服务地址。
- `api_base_url` 只表示 OpenAI-compatible / API Provider 地址。
- 运行时按 provider 类型选择 URL：
  - `provider_type=ollama` -> `ollama_base_url`
  - `provider_type=openai-compatible` -> `api_base_url`
- 后端启动迁移会处理旧数据：
  - 旧的 API 地址从 `ollama_base_url` 迁移到 `api_base_url`。
  - `ollama_base_url` 恢复为 `http://127.0.0.1:11435`。
- 设置页“问答模型”区域改为两个输入框：
  - `API Base URL`
  - `Ollama Base URL`
- 设置保存、连接测试、模型列表读取、聊天运行时、记忆建议运行时均已接入新逻辑。

## 验证结果

测试账号 `1528713326@qq.com` 当前配置：

```text
api_base_url=https://api.siliconflow.cn/v1
ollama_base_url=http://127.0.0.1:11435
```

验证通过：

- API provider 测试连接成功，使用 `https://api.siliconflow.cn/v1`，返回 90 个模型。
- Ollama provider 测试连接成功，使用 `http://127.0.0.1:11435`，返回 6 个模型。
- 保存设置后两个 URL 不互相覆盖。
- Playwright 设置页冒烟通过：
  - 页面显示 `API Base URL`。
  - 页面显示 `Ollama Base URL`。
  - console error 为空。
  - request failure 为空。
