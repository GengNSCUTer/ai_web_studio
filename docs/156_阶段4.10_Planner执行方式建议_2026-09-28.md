# 阶段 4.10：Planner 执行方式建议

## 当前行为

Planner 的 JSON 除工具调用外可输出 `execution_mode=sync|durable_candidate` 和 `execution_reason`。旧版 JSON 没有这两个字段时默认为 `sync`；模型 JSON 无效或超时仍走原有确定性兜底。代码在完成参数解析与计划增强后复核建议：只有至少两个实际可执行步骤、所有工具均为低风险只读，且当前显式 Skill 允许 Durable，才保留 `durable_candidate`；其余统一降为 `sync`。这一判断不授予权限，也不替代 Durable Handoff 的服务端检查。

普通 Chat 保持既有同步执行和有界轮数，不会因为 Planner 的建议自动创建 `AgentRun`。Tool Trace 展示建议与简短原因，并明确提示：用户选择后台预览后，是独立重新执行同一组低风险只读步骤，可能重复本轮查询。预览不入队，确认时只提交签名 token；后端再次检查项目/会话归属、Skill、工具风险、依赖 DAG、参数和幂等，再创建 Run。写入类 Tool 仍走 Diff、Approval 和 Revision CAS，不进入这个只读 Handoff。

历史会话的 Handoff 现在从 Tool Trace 中的 `skill_activation` 读取当时激活的 Skill，不再使用当前输入框的选择；从“全部工作区”进入历史会话时，ChatThread 使用该会话实际的项目归属，因此预览不会因当前侧边栏筛选为空而消失。

## 实现位置

- `backend/app/services/tools/schemas.py`：ToolPlan 保存并公开执行方式建议。
- `backend/app/services/tools/planner.py`：提示模型、解析 JSON、校验低风险只读和 Skill 资格；确定性回退保持同步。
- `frontend/src/components/tool-trace-panel.tsx`：展示建议、重执行提示、预览/确认和 Run 状态；从历史事件恢复 Skill。
- `frontend/src/components/chat-app.tsx`：历史会话的真实工作区归属传入聊天线程。
- `frontend/src/lib/types.ts`：前端 Tool Plan 和 `skill_activation` 事件类型。
- `scripts/stage410_online_planner_smoke.py`、`scripts/stage410_planner_advice_smoke.py`：真实在线 Planner 与浏览器/数据库交接验证。

## 验证

后端 PostgreSQL 全量回归 `488 tests OK`；Python `compileall`、前端 ESLint 和 `npm run build` 通过。在线 Provider 真实调用中，双城天气得到两个高德天气步骤并建议 `sync`；多步骤工作区审阅得到文件列表和搜索步骤并建议 `durable_candidate`。浏览器烟测确认建议和重复查询提示可见、预览前后 Run 数量均为 0、确认后为 1，桌面和移动端无溢出/console 错误。独立真实 Chat 烟测完成在线 LLM Planner、工作区文件 list/search/read 和最终回答落库为 `done`。

## 后续边界

本阶段尚不是“模型在执行前自动切换同步/后台”的两阶段交互。当前建议是同步回答后的显式只读 Handoff 入口；将其改成执行前分流需要新增用户选择、计划冻结和同步恢复协议，不能靠模型字段直接决定。这是刻意保留的安全边界，不是 4.10 的故障。Worker 外部告警和自动扩容同样属于部署层，不在本地工作台本阶段范围内。4.11 处理审计导出与安全回放，不以继续增加 Tool 数量为目标。
