# Skill 显式执行主链与端到端验证

更新时间：2026-07-31

## 1. 本轮目标与结论

本轮将此前只有“目录、安装状态和开关”的 Skill 能力接入真实 Chat 主链。用户现在可以在输入区显式选择已安装且就绪的 Skill，后端会在每次执行时重新校验安装、启用、工作区、Tool 和凭据状态，再用 Skill 声明的 Tool 白名单约束 Candidate Selector、LLM Planner 与确定性降级路径。代码负责真正执行 Tool，结果返回最终模型生成回答；Skill 的输出契约同时约束最终回答结构。

本轮没有安装来源不明的第三方可执行代码。公开候选的安装量和来源可信度不足，因此当前采用项目内置、经过审核的声明式 Manifest。Skill 只能编排已有 Tool，不能包含 Python、Shell、URL 或凭据，也不能绕过 Executor 的安全校验获得新权限。

## 2. 已安装的内置 Skill

| Skill Key | 中文名称 | 主要能力 | 必需 Tool | 关键边界 |
| --- | --- | --- | --- | --- |
| `research.web-brief` | 联网研究简报 | 联网检索并生成带来源的研究简报 | Tavily Search | 必须展示证据、来源与不确定性 |
| `workspace.document-review` | 项目文档审阅 | 在明确工作区内检索和阅读文件并给出审阅意见 | File List / Search / Read | 只读，不包含 Apply Edit |
| `travel.route-planner` | 出行路线规划 | 地理编码和驾车路线规划，可按能力补充天气、距离、步行、公交、POI 与联网搜索 | Geo / Driving | 缺少必需凭据时不可执行，可选 Tool 缺失不阻断 |
| `agent.artifact-review` | Agent 产物复盘 | 读取 Durable Agent 产物并给出复盘结论 | Artifact List / Read | 只允许当前用户和工作区可见的产物 |

四项 Skill 已为固定测试用户写入 `UserSkillInstallation` 并启用。安装过程没有读取或输出已有 API Key，也没有把账号、密码、Token 或凭据写入仓库。

## 3. 完整执行主链

```text
用户在输入区显式选择 Skill
  -> 前端提交 skillKey
  -> SkillCatalog.resolve_for_execution
       校验 Manifest 审核状态
       校验当前用户已安装并启用
       校验 project/workspace 归属
       校验必需 Tool、工作区开关和凭据
       收敛本轮 allowed_tool_keys
  -> Candidate Selector
       只在 Skill allowlist 内评分和召回
  -> LLM Planner
       读取候选 Tool 合同与 Skill planner instructions
       输出受 JSON Schema 约束的 ToolPlan
  -> Deterministic Fallback（仅 Planner 失败时）
       仍受同一 Skill allowlist 和依赖约束
  -> Tool Workflow / Executor（代码执行）
       校验 Schema、权限、风险、依赖和 Result Binding
       发起真实 Tool 调用
  -> Tool Result 作为不可信 evidence 返回最终 LLM
  -> Skill output contract 作为可信 system instruction 约束回答
  -> Assistant Message、ToolRouteRun Trace 和运行指标落库
```

其中 LLM 只负责在受限候选中规划 Tool 调用以及基于结果生成最终回答。安装校验、候选范围、安全校验、HTTP/MCP 调用、Result Binding、持久化和 Trace 均由代码执行。即使 Planner 超时、生成非法 JSON 或拒绝调用 Tool，规则降级也不能使用 Skill 未声明的能力。

## 4. 安全边界

### 4.1 Manifest 边界

- Manifest 使用严格字段白名单，未知字段直接拒绝加载。
- Skill key、版本、指令长度、输出契约长度和 Tool 数量均有限制。
- required 与 optional Tool 不允许重叠。
- Skill 不允许携带可执行代码、任意 URL、凭据或新权限。

### 4.2 运行时边界

- 前端只展示 `is_installed && is_enabled && is_ready` 的 Skill，但前端不是权限边界。
- 后端在每轮执行时重新校验，防止安装状态、凭据或工作区配置变化后继续使用旧权限。
- Candidate Selector 的评分和 Web fallback 均在 allowlist 内进行，不能通过降级逻辑绕过。
- Planner 只能输出候选列表中的 Tool；Executor 继续执行 Schema、ACL、风险与业务校验。
- 可选 Tool 不可用时只从本轮列表移除；必需 Tool 不可用时 Skill fail-closed。
- 最终 Prompt 将 Skill instructions 与 Tool/RAG/Memory evidence 分层，外部内容不能伪装为系统指令。

当前仍不开放 Bash、Shell、SQL、删除文件、任意本机文件写入、支付、邮件发送、外部发布和任意 HTTP 写接口。工作区文件修改仍需经过 Patch Draft、用户 Approval、one-time continuation 与 FileRevision CAS，不能由 Skill 静默获得写权限。

## 5. Trace 与指标

`ToolRouteRun.events_json` 新增两类事件：

- `skill_activation`：记录 Skill key/version、显式激活、允许的 Tool 和是否要求真实 Tool 执行。
- `skill_result`：记录最后的 Planner、计划 Tool、来源数量、实际轮数和 success/empty/error 状态。

`ChatRuntimeMetric.stats_json` 记录 `skill_active`、`skill_key` 和 `skill_version`。运行时指标接口聚合最近 500 条 ToolRouteRun，按 Skill、Run 状态和 Tool Call 状态展示观察窗口数据。该窗口用于运行诊断，不等同于永久统计仓库。

## 6. 前端交互

- Chat 输入区新增 Skill 选择器，默认“不使用 Skill”。
- 根据当前 `projectId` 请求后端 Skill 列表，项目切换时重新加载。
- 使用 AbortController 避免旧项目请求晚返回后覆盖新状态。
- 新聊天、重新生成、编辑最后一条用户消息后重答均透传 `skillKey`。
- Skill 选择目前是当前 ChatThread 的临时状态，不自动写成会话默认配置。
- 390px 移动端菜单改为右对齐并限制为视口宽度，避免越出屏幕。

## 7. 验证结果

后端最终全量回归共运行 272 项，结果 `OK`，其中 3 项因需要特定 PostgreSQL 测试环境而条件跳过；`compileall` 通过。前端相关 ESLint 与 Next.js production build 通过。

真实在线端到端验证使用隔离的前后端端口，走通以下链路：

1. 浏览器打开真实 Chat 页面并显式选择“联网研究简报”。
2. 前端 `/api/chat` 请求包含 `skillKey`。
3. 在线模型完成受限 Planner，计划中只有 `web.tavily.search`。
4. Executor 使用真实 Tavily Tool 返回搜索结果。
5. 最终模型基于结果生成回答，Assistant Message 以 `done` 状态落库。
6. 数据库 Trace 同时存在 `skill_activation` 和 `skill_result`。
7. 桌面与 390px 移动端页面通过浏览器冒烟检查，未发现 console error。

端到端脚本位于 `scripts/verify_skill_flow.py`。脚本不硬编码邮箱、密码、API Key、JWT 或固定用户 ID；它从数据库选择已安装目标 Skill 的用户，并由服务端生成短期测试 JWT。

## 8. 下一步优化顺序

1. 建立 Skill 与 Tool Selector Gold Set，统计 Skill 推荐 Recall@k、Tool Recall@k、Planner 选择正确率、参数正确率和端到端任务成功率。
2. 增加“系统推荐 Skill、用户确认激活”，继续禁止模型自动安装或静默扩大权限。
3. 建立签名、来源、版本锁、兼容性、升级回滚和供应链审核后，再考虑开放第三方 Skill 市场。
4. 将适合长任务的低风险 Skill 与 Durable Agent Run 关联；同步 Chat 仍维持有界轮数。
5. 完善 Skill 级失败对账、DLQ 管理、受控重放与告警。

当前阶段可以准确描述为“内置声明式 Skill 已接入受限 Planner + Tool Workflow 主链并完成真实 E2E”，不能描述成“允许任意第三方代码运行的插件市场”或“全权限自主 Agent”。
