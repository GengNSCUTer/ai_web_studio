# Chat 摘要覆盖与独立回答

本次落实摘要问题 11.1–11.6。默认 Chat 先验证历史覆盖，再读取记忆、知识库和工具资料。已有会话仍然使用 PostgreSQL 中的消息、滚动摘要和后台重建任务。

## 从历史预检到模型调用

- [预检](../backend/app/services/chat_summary_coverage.py)使用本轮用户消息和已验证摘要边界作为读取区间，以会话顺序分页。字符和 Token 均有余量时，保留边界后的完整原文。`conservative`、`balanced`、`long-context` 的 10、16、24 条仅用于预算紧张时选择压缩目标。同步只处理一批，最多 48 条，超出单批或需要分片时登记后台 Job。已有 Job 的目标可扩展，保留已提交进度。
- [上下文组装](../backend/app/services/chat_context_assembly_service.py)在召回前执行预检，组装最终 Prompt 前再次复核会话版本、生成版本和原文。最终预算治理保留摘要与未覆盖原文，裁剪可选资料并完整复算输入预算。摘要生成的等待期间释放数据库事务。同步摘要补全和格式修正共享 20 秒期限，后台同一批共享 90 秒期限。
- [摘要校验](../backend/app/services/summary_output.py)检查固定五节、完整节正文、字符及 Token。无效输出最多修正一次，仍失败则保留原有边界。后台每批最多三次有界尝试，失败可使用会话摘要恢复入口显式重试。迁移标识历史 `fallback` 及其后续旧版本，按需回退到安全版本并重建。其他历史摘要标为 `legacy`，后续通过校验的摘要写为 `model`。
- 明确约束、超时与重试参数、资源标识以来源消息 ID、原文片段和事实键保存在摘要版本，长消息只在完整消费后加入事实。提取只接受能在用户原文逐字核对的片段，并复用敏感信息判定。后续可识别的同一数值参数优先使用新值。来源删改沿用会话修订号和摘要回退事务。首版通过保守规则识别事实，复杂转述和隐含变更仍依赖原文或滚动摘要。

## 独立回答

普通 Chat 因摘要重建失败时，最后一轮提供「仅用本轮问题回答」。后端的重生成接口接收 `history_mode=current_turn_only`，核验会话归属、最新生成版本、失败代码及原有功能选择。该模式使用本轮问题、系统指令和本轮授权附件，跳过旧历史、摘要、长期记忆、知识库和工具。ChatRun、SSE 快照与消息历史记录该模式，页面刷新后显示「仅使用本轮内容」。新问题继续使用默认完整历史策略。

## 观测与上线

`summary_preflight_ms`、`summary_refresh_ms`、`summary_refresh_input_tokens` 随上下文指标记录，`first_answer_delta_ms` 从 Worker 开始执行量到收到首段正文。预检阻断和格式校验失败以固定错误类别记录在日志，后台最终失败原因可通过摘要状态接口读取。首段正文延迟和线上校验失败率需要上线后有足够实际流量再评估。

上线前用隔离 PostgreSQL 恢复和演练 `20261127_02` 到 `20261127_03`，包括历史版本标记、消息模式和分片草稿迁移。停写窗口备份数据库、上传和索引，复用当前 Supervisor 重启应用服务。保留现有 PostgreSQL 和 Redis 实例及 SSE 通知配置。

验收通过 187 项后端回归，含真实 PostgreSQL 和历史迁移测试。`compileall`、改动文件的 ESLint、前端生产构建和 Playwright 通过。浏览器验证摘要阻断时回答模型调用次数为 0、独立回答只使用本轮问题、刷新后恢复标记、跨用户重生成请求被拒绝，控制台错误数为 0。结构化事实测试连续压缩 20 批后仍保留 30 秒和最多重试 3 次的原文，明确更新超时后以新值为准。

当前实例已升级到 `20261127_03`。升级前后均为 68 个会话、366 条消息和 1 条 ChatRun。Supervisor 角色与 SSE 监听正常，前端代理的历史、摘要状态和 ChatRun 读取已通过上线检查。
