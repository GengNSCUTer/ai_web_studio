# 阶段 4.8：Durable 结果回写与会话收口（2026-09-22）

## 本阶段目标

阶段 4.7 已经可以把普通 Chat 中的低风险只读 Tool Plan 交接给 Durable Worker，但用户还需要离开会话去查询 Run 才能看到最终结果。本阶段补齐终态结果回写：Run 成功或失败后，把可理解的摘要写回原始 conversation，并保证重复刷新、重复收口不会创建重复消息。

## 本次实现

`backend/app/services/durable_tool_runtime.py` 在所有 Step 进入终态、Run 状态确定后执行会话投影：

- `succeeded`：汇总 `AgentArtifact.preview`，生成助手完成消息；
- `failed` / `dead_letter` / `cancelled`：汇总失败 Step 的错误码、错误信息和已经成功的 Artifact，生成失败消息；
- 消息带有 `durable_run` 来源元数据，前端可以继续通过 Run ID 查询详情；
- 结果消息 ID 和投影时间写入 `AgentRun.planner_state_json`；
- 终态判断前锁定 `AgentRun` 行，串行化并发分支的最终收口，避免两个 Worker 同时通过投影幂等检查；
- Run 终态、结果消息和投影标记在同一数据库事务提交，进程在提交前退出时会一起回滚；
- 已经存在投影标记时直接跳过，重复 worker 收口或前端刷新不会产生重复消息；
- 如果原始会话已经不存在或不属于 Run 用户，则不越权写入，并保留 Run 状态供诊断。

前端 `tool-trace-panel.tsx` 在刷新到 `succeeded`、`failed`、`dead_letter` 或 `cancelled` 后重新加载当前会话消息，因此用户可以在原聊天中看到最终结果；Run 面板仍保留 Step、错误和 Artifact 明细。

## 代码入口

- `backend/app/services/durable_tool_runtime.py`：终态判断、成功/失败摘要和幂等会话投影；
- `backend/app/repositories/message_repo.py`：复用会话行锁和消息序号分配；
- `frontend/src/components/tool-trace-panel.tsx`：终态刷新后触发会话消息重载；
- `frontend/src/components/chat-message-list.tsx`、`frontend/src/components/chat-thread.tsx`：传递会话刷新回调。
