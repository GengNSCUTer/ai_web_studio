# 阶段 5.2：前端运行模式选择与预算展示

## 结论

阶段 5.2 已完成。同步 Chat 不再只有后端隐藏的运行模式配置，用户可以在发送前明确选择受控的工具运行模式；默认仍为 `quick_chat`，最多 5 轮，不会因为选择 Skill 或模型自行扩大权限与预算。

可选模式为：

- 快速对话：5 轮、最多 10 次工具调用；
- 研究模式：8 轮、最多 16 次工具调用；
- 工作区审阅：6 轮、最多 12 次工具调用；
- 编辑提案：4 轮、最多 6 次工具调用。

`durable_task` 仍不是同步 Chat 的选项，需要后续用户确认的 Durable handoff 设计。

## 代码链路

1. `backend/app/schemas/message.py` 用 `Literal` 限制请求值；新消息、重生成、编辑重答使用同一字段。
2. `ChatExecutionService` 和 `ChatContextAssemblyService` 将模式传给 `ExternalContextService`，由代码侧 `resolve_tool_run_policy()` 生成不可变 Policy。
3. Next API 代理将 `toolRunMode` 转成后端的 `tool_run_mode`；没有字段时显式回退 `quick_chat`。
4. `ChatThread` 持有选择状态，`ChatComposer` 提供轻量下拉选择器；生成和编辑期间禁用切换。
5. 后端 diagnostics/details 透传脱敏 Policy/Budget，前端上下文面板显示已用轮数、调用数、剩余重规划次数和剩余工具阶段时间。

## 安全边界

运行模式只改变代码侧预算，不改变 Tool Catalog、ACL、审批、SSRF 或 Executor 安全边界。Planner、Skill、Tool 返回都不能修改预算；前端没有自动切换到更长模式的逻辑。

## 验证

- 后端相关测试：28 项通过；`compileall` 通过。
- 前端变更文件 ESLint 通过；`npm run build` 通过。
- Playwright 登录后浏览器冒烟：模式选择器默认值为 `quick_chat`，可切换到 `guided_research` 并显示“最多 8 轮 / 16 次工具调用”；console error 和 request failure 均为空。
