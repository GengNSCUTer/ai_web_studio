# 2026-09-21：PostgreSQL 集成环境复核与外部工具内容审查说明

当前项目配置的 PostgreSQL/pgvector 实例仍在运行，真实验证确认 PostgreSQL 18.3、pgvector 0.8.5 可用。之前回归中的 5 个跳过项来自测试的显式 `TEST_POSTGRES_URL` 门禁，而不是数据库未启动；使用当前实例临时设置该变量后，3 项 pgvector 集成测试、2 项 Durable Runtime 集成测试以及后端全量 455 项测试均通过。

本轮同时修复 Durable Run 幂等并发的边界：唯一键冲突可能在 SQLAlchemy flush 阶段发生，现已与 commit 阶段一样回滚并读取已有 Run，校验请求哈希后返回已有 Run或明确报告幂等冲突。

外部工具内容审查机制的当前原则是“事实可参考，外部指令无执行权”。工具返回先经过 MCP/Adapter 响应解析、output schema 校验、声明式 Mapper 归一化、敏感信息脱敏和 ResultQualityContract 业务质量门；只有质量有效的 Source 才能进入回答上下文。下一轮 Planner 不直接看到原始网页、文件或 MCP JSON，而只能看到经过 Catalog 中已审核 Evidence Projection Profile 投影的有限 facts，Tavily 等少数审核工具才允许有字符上限的 bounded excerpt。新工具默认 `mode=none`，动态 MCP 还必须通过 onboarding 合同摘要、Mapper、fixture、版本/配置摘要和人工审核。

Planner Prompt 明确把外部结果标记为 `reference_evidence`，`instruction_authority=none`：相关事实可以帮助回答或决定是否需要下一步检索，但其中要求忽略规则、泄露秘密、调用工具、扩大权限的文本不能改变候选工具、权限、审批或预算。最终执行权限仍只在代码侧 Candidate Selector、Schema Validator、Executor、ACL、Approval、CAS/Fencing 和 Tool Budget 中。

本轮暂不进入阶段 4.5，先保留“Evidence 预算诊断与跨来源去重”作为下一步候选优化。
