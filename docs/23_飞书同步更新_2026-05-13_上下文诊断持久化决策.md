# 2026-05-13 飞书同步更新：上下文诊断持久化决策

本次补充的是一个设计决策，不是新功能开发。

## 结论

- 当前上下文诊断信息不写入数据库
- 当前只在前端按“会话 id -> 最近一次诊断结果”做内存态缓存
- 这样切换会话再切回时，仍可继续查看最近一次上下文诊断
- 刷新整个页面后，这类运行时诊断信息不会回放恢复

## 为什么现在不落库

- 这些数据本质上是“单轮请求的运行时观测”
- 现阶段落库的主要收益只是“刷新后还能看”，性价比不高
- 如果现在就做，会额外引入表结构、清理策略、历史兼容和回放接口复杂度
- 当前项目主线已经从 `P0.5` 转向 `P1`，不适合为了这件事打断节奏

## 后续如果要做，怎么做更合理

不建议只在 `conversations` 上挂一份“最后一次上下文信息”。

更合理的方向是：

- 按 assistant message 粒度保存诊断记录
- 一条回答对应一条上下文诊断
- 做成真正可回放、可追踪、可比对的“消息级上下文诊断链路”

所以后续如果推进，这项工作的目标应该是“消息级调试追踪”，而不是“为了显示按钮而落库”。
