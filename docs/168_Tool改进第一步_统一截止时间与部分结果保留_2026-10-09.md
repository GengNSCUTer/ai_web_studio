# Tool 改进第一步：统一截止时间与部分结果保留

日期：2026-10-09。对应 [167 工具调用审查](167_工具调用审查与主流方案对标_2026-10-09.md)的第一项和第五项。四步中的第一步已实现，其余步骤尚未开始；本轮不增加工具、不改变权限或轮数、不迁移文件数据库访问。

## 一、用户能看到什么变化

以前两个工具并发时，一个已经完成、另一个超时，整轮被取消可能连成功结果一起丢失。现在到工具阶段的截止时间后，保留已完成且通过质量门的结果，未完成调用记为超时，还没开始的依赖步骤记为阻断；最后仍可根据可靠证据回答，并明确说明没有完成的部分。

规划模型也受同一个总截止时间约束。首次规划超时不再被当成“没有开启工具”或“正常不需工具”，有诊断和持久化轨迹；续轮规划超时仍保留之前拿到的证据。统计区分规划、执行和总时延。

截止时间只覆盖 Tool 阶段的规划、执行和观察收口；最终答案模型仍使用 Chat 原有首包、空闲和总时长超时。Python 异步取消是协作式的，清理连接可能有小量额外时间，不能强行中断阻塞的同步代码；文件工具的同步阻塞留在第二步解决。

## 二、代码如何实现

```text
ToolRunBudget 创建单调时钟 deadline
    → Planner 的外层等待使用剩余时间
    → Workflow 按同一 deadline 等待并发调用
    → 收集已完成结果，只取消尚未完成调用并等待清理
    → 每个步骤形成成功、失败、超时、取消或阻断终态
    → 保留质量有效的证据，汇总实际尝试次数
    → 截止时停止重规划，产生部分回答或无证据停止动作
    → 系统执行状态和有效证据一并进入最终模型输入
    → 工具轨迹保存部分状态；最终回答按 Chat 自身结果保存
```

| 文件 | 本轮具体职责 |
| --- | --- |
| `backend/app/services/tools/run_policy.py` | 给预算增加单调时钟截止时间，续轮不重新计时 |
| `backend/app/services/tools/workflow.py` | `_execute_batch` 保留截止前完成的调用；清理剩余任务，生成超时终态，阻止依赖下游；超时/取消指纹禁止本请求静默重发 |

## 三、成功、失败、超时和取消的区别

- 工具成功但质量无效：沿用原有质量门，不注入最终回答，也不能解锁严格依赖。
- 某个工具普通失败：沿用受限重规划、部分收口等策略，独立成功分支不被抹掉。
- 总时间耗尽：未完成调用记为 timed_out，不再启动后续调用；有证据则 finalize_partial，无证据则 stop。这些动作结束工具阶段，不等于强制把整个 Chat 标失败。
- 取消任务后晚到的输出：不当作截止前成功结果，不注入模型。
- 上游取消整个准备任务：清理子任务，继续抛出 CancelledError，占位消息按本代 generation 保存为 cancelled；不能伪装成正常部分回答。

浏览器点击停止或断网是否能在每个阶段触发上游任务取消，仍取决于当前 HTTP/代理生命周期。本轮补的是收到取消后的收口，不声称新增了独立取消 API、后台生成或断点续流。
