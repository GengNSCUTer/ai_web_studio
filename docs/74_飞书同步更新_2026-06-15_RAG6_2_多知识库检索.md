# 飞书同步更新：RAG-6.2 多知识库检索

更新时间：2026-06-15

## 本轮完成

- 已安装并验证 Playwright 浏览器自动化能力，后续可用于本地前端冒烟测试。
- 聊天页知识库选择器从单选升级为多选。
- 前端 `/api/chat`、`/api/chat/regenerate`、`/api/chat/edit-last-user` 均支持传递 `knowledgeBaseIds`。
- 后端聊天 schema、执行服务和上下文装配服务均支持 `knowledge_base_ids`。
- `KnowledgeContextService` 支持多知识库检索：
  - 单库请求保持原路径。
  - 多库请求并行独立检索。
  - 每个知识库使用自己的检索和 rerank 配置。
  - 多库结果按最终分数全局合并。
  - 合并后重新生成全局 `[KB1] / [KB2]` 来源编号。
- 检索日志兼容多知识库：
  - 每个知识库仍生成独立 retrieval log。
  - 同一轮问答会回写到所有相关 retrieval logs。
  - 来源卡片继续可按 `retrieval_log_id` 查看来源片段和日志摘要。
- 已补充单测覆盖多知识库上下文合并。

## 当前边界

- 当前多知识库检索是“每库独立召回 + 全局按分数合并”，还不是跨库统一索引。
- 当前没有跨库统一 rerank。
- 当前没有 BM25 / Hybrid / RRF。
- 当前多库上下文预算是字符级粗预算，后续需要 token 级预算和跨库配额。
- 当前多库选择状态是前端运行态，暂未持久化为用户偏好。

## 下一步建议

1. `RAG-6.3`：BM25 / lexical retriever。
2. `RAG-6.4`：Hybrid Search + RRF。
3. 检索观测增强：展示多库贡献分布、跨库合并前后排序和单次 retrieval log 详情。
