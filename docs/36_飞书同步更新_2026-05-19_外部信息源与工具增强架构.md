# 2026-05-19 外部信息源与工具增强架构同步

本次更新是对“联网搜索按钮”的架构修正。

结论：`联网搜索` 不应该只等价于 Tavily。更合理的设计是新增一层 `External Context / Tool Layer`，把网页搜索、天气、地图、知识库召回和 MCP 工具统一接入。

## 1. 为什么要修正

如果只做 Tavily 搜索，短期能跑，但长期会有明显问题：

- 天气、地图、路线、POI、金融等垂直问题不适合普通网页搜索。
- OpenAI / Gemini / Claude 的原生搜索工具和 Tavily / Brave / SerpAPI / Exa 这类应用层搜索 API 差异很大。
- MCP 工具会进一步扩大工具生态，如果没有统一抽象，聊天接口会堆满 provider-specific 逻辑。
- 后续工作区知识库召回也需要和网页来源共用来源展示、上下文预算和 Trace。

因此，必须从架构层面设计，而不是继续堆功能。

## 2. 主流实现方式

调研后，主流 AI 网页端和 API 大致分四类：

1. 模型厂商原生搜索工具。
   OpenAI Responses API 的 web_search、Gemini Grounding with Google Search、Claude web search tool 都属于这一类。优点是体验好，缺点是绑定 provider。

2. 带搜索能力的模型 API。
   Perplexity / Sonar 这类 API 把搜索和回答合并到模型服务中。接入简单，但可控性弱。

3. 应用层搜索 API。
   Tavily、Brave Search、SerpAPI、Exa 都属于这一类。优点是 provider 无关，本地 Ollama 也可用；缺点是应用自己要做清洗、引用、预算和 Trace。

4. 垂直 API / MCP 工具。
   天气、地图、路线、GitHub、数据库、飞书等更适合做工具调用。MCP 提供了更标准的工具发现和调用方式。

## 3. 新架构

推荐新增：

```text
Tool Registry
  工具注册、工具 schema、权限、配置

Tool Router
  判断本轮应该调用哪些工具

External Context Channel
  执行 web / weather / map / knowledge / mcp 调用

External Context PostProcessor
  去重、归一、来源编号、预算裁剪、rerank

ExternalSource
  统一承载网页、天气、地图、知识库、MCP 结果

Tool Trace
  记录工具调用、耗时、错误、进入 Prompt 的内容
```

架构流程：

```text
User Message
  -> Tool Router
  -> External Context Engine
  -> External Context Channels
  -> PostProcessors
  -> Context Governance
  -> Prompt Builder
  -> LLM
  -> Source / Tool Result UI
```

## 4. 和 Ragent 的关系

Ragent 的 `SearchChannel + MultiChannelRetrievalEngine + SearchResultPostProcessor` 非常值得借鉴。

我们要做的是把这个思路扩展成更通用的通道：

- WebSearchChannel
- WeatherToolChannel
- MapToolChannel
- WorkspaceKnowledgeChannel
- CurrentAttachmentChannel
- MCPToolChannel

后处理器复用同一套思路：

- Deduplicate
- ScoreNormalize
- CitationBuild
- BudgetTrim
- Rerank

## 6. 新的推荐实施顺序

建议：

1. 深度思考按钮 MVP
2. 结构化事件流
3. ExternalSource / ExternalContextChannel 抽象
4. Web Search MVP，Tavily 作为第一个 provider
5. Weather Tool MVP
6. Map Tool MVP
7. RuleBased Tool Router
8. MCP Client MVP
9. 回到 P3 工作区知识库索引和跨历史召回

这样后续接 Brave、SerpAPI、Exa、OpenAI 原生 web_search、Gemini grounding、Claude web search、高德地图 MCP，都不会破坏聊天主流程。
