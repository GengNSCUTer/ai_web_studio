# 长期记忆分片抽取与冲突复核

## 提取和记忆请求

Chat 完成后仍由持久化触发记录启动扫描。`memory_trigger_policy.py` 的 `rules-v4` 将明确表达的长期条件偏好、今天已正式作出的长期决定及时入队。外部引文、禁存和敏感内容优先处理。本轮要求跳过，真正的未决表述继续缓冲。候选生效仍依赖逐条原话、时效、风险、当前授权及冲突审核。

`memory_candidate_runtime.py` 先对整个用户消息脱敏，再由 `memory_extraction_policy.py` 按句子和空白附近切片。每片最多 1,000 字符，相邻片重叠 320 字符。单次提取按模型窗口、8,192 Token 上限、12,000 字符上限和输出预留封包，可覆盖最后一段。引文必须实际出现在该次发送的片段中。多片任务直接进入受控提取，语义价值判断只用于能完整放入单次输入的短缓冲批次。

`memory_extraction_graph.py` 从任务读取上次分片位置。每个成功分片在租约、最新开关、项目归属和消息快照检查后暂存去重候选。中断后从已保存位置重领。最后一次统一做冲突审查，再在同一事务写入候选、推进提取游标并消费缓冲。删除或编辑来源、关闭权限或终态失败会丢弃失效草稿。手动预览建议接口继续使用有界请求，核验范围为输入中实际出现的片段。完整抽取走持久化任务。

## 冲突复核和队列

| 位置 | 实现 |
| --- | --- |
| `memory_conflict_service.py`、`memory_service.py`、`memory_repo.py` | 无歧义的长期默认回复语言按用户、精确项目范围、Active 状态和事实键读取。人工确认或自动保存时，在现有用户锁内重查同键新增、删改和版本变化。旧记录缺少事实键时重新识别，同键有歧义或时效差异时走通用审核。停用的 Active 行仍参与冲突复核。 |
| `memory_conflict_service.py`、`memory_repo.py` | 通用冲突在 SQL 限定范围后保留既有判断和版本校验。`MEMORY_CONFLICT_SHADOW_ENABLED` 默认关闭，可利用 GIN 和 pgvector 记录候选交集和耗时，每路最多 16 个候选。索引结果只用于观测，复用现有候选向量，日志记录计数和耗时。 |
| `memory_candidate_runtime.py`、`memory_job_repo.py` | 任务身份绑定会话、项目、动作、手动模式及全部来源的 ID 和内容版本。兼容旧任务记录。语义缓冲等待新合格消息或旧来源编辑，普通问答与仅删除来源不会唤醒。队列满时仍可执行提取释放空间。 |
| `memory_candidate_runtime.py`、`memory_index_service.py` | 同一个 Worker 每连续执行四个抽取单元，分别给项目整理和向量索引一次执行机会。抽取空闲时检查两队列。每分钟采样未完成任务数、可领取索引数和最旧任务等待时间。 |

隔离 PostgreSQL 合成测试中，每组测量 10 次。数据为同一项目中带 256 维向量的合成事实，进程同时在跑项目回归。下表是数据库查询及应用载入的中位数，通用冲突模型调用、业务流量与真实召回质量需另行测量。

| 范围内 Active 行数 | 通用快照 | 精确事实键 | 索引影子候选 |
| ---: | ---: | ---: | ---: |
| 1,000 | 33.52 ms | 4.41 ms | 16.07 ms |
| 10,000 | 323.22 ms | 5.41 ms | 33.65 ms |

两组均召回构造的相关事实，候选各 16 条。通用冲突与撤销历史仍有范围内扫描成本。长消息发给模型用于提取，模型可能遗漏证据，提取覆盖测试按输入和持久化行为验收。

## 部署

迁移 `20261127_04` 为抽取任务加分片位置、来源集合和草稿字段，并创建 `ix_memory_conflict_fact`。旧任务按分片位置 0 读取，原任务、消息和记忆版本继续可用。应用前排空 Chat 并备份，使用既有 Supervisor 进程和端口，恢复后检查健康接口、记忆队列和浏览器入口。
