# 阶段 2.3A：低风险只读 MCP Tool 接入合同与审核边界

日期：2026-09-15
范围：为用户新增的远程 Streamable HTTP MCP Tool 定义一份可校验的接入合同；不开放新的高风险能力，不发送网络请求，也不因为合同存在而自动启用 Tool。

## 1. 要解决的问题

阶段 2.2 已让内置 Tavily/高德等 Provider 走专用 Mapper 和 `ResultQualityContract`。但一个新 MCP Tool 的输出 JSON 往往各不相同：若把“远端返回非空”直接作为可用证据，模型会把任意文本/JSON 注入上下文，且无法判断它是否有业务意义。

本阶段将接入信息收敛为一份固定合同：

```text
Tool identity
  + QualityContract/Profile
  + 受限 Canonical Mapper 声明
  + fixture bundle 摘要
  -> 后续 Mapper / fixture 验证 / 人工审核共用
```

## 2. 合同形态和允许范围

合同版本固定为 `tool_onboarding_v1`，必须包含：

```json
{
  "version": "tool_onboarding_v1",
  "tool": {
    "tool_key": "mcp.demo.search.1234567890",
    "provider": "demo_search",
    "category": "web_search",
    "adapter_type": "mcp_http",
    "source_type": "mcp_server",
    "risk_level": "low",
    "read_only": true
  },
  "quality_contract": {
    "semantic_profile": "web_search",
    "profile_mapping": { "...": "阶段 2.2 的受限 Profile 映射" }
  },
  "canonical_mapper": {
    "type": "collection",
    "collection_path": "/items",
    "display_text_path": "/snippet",
    "url_path": "/href",
    "canonical_fields": {
      "content": "/snippet",
      "url": "/href"
    },
    "max_items": 8,
    "max_chars": 1200
  },
  "fixture_manifest": {
    "format": "tool_onboarding_fixture_v1",
    "bundle_digest": "<64 位小写 SHA-256>",
    "case_ids": ["success", "malformed"]
  }
}
```

当前只允许：

- `adapter_type=mcp_http`、`source_type=mcp_server`；
- `read_only=true`，风险等级仅 `low` 或 `medium`；
- 已存在的固定 `semantic_profile` 和 `profile_mapping`；
- `object` / `collection` 两类 Mapper、确定性的 JSON Pointer、最多 16 个 canonical 字段、最多 16 个 collection item、单条文本最多 1,600 字符；
- fixture 至少覆盖 `success` 和 `malformed`，可额外覆盖 `empty`、`request_mismatch`。

当前明确拒绝：

- Bash、Shell、SQL、删除、任意本机写入、支付、邮件、外部发布、任意 HTTP 写；
- `expression`、`script`、`template` 或未声明 Mapper 字段；
- JSON Pointer 根路径、通配符、空路径段、尾斜杠和非法 `~` 转义；
- 动态远端 MCP 将 `allow_empty=true` 或 `empty_answer` 自称为正常结果；
- 在 canonical metadata 中写入 `raw`、`metadata`、`result_semantics` 等保留字段。

## 3. 实际代码入口与边界

- `backend/app/services/tools/onboarding.py`
  - `validate_tool_onboarding_contract()` 是合同入口；组合阶段 2 的 `validate_quality_contract()`，并校验 Tool 身份、Mapper、fixture 摘要。
  - 该函数只返回经归一化的合同和稳定 SHA-256 digest；不请求 MCP，不执行 Mapper，不让 Tool 进入候选集。
- `backend/app/services/tools/quality.py`
  - `validate_json_pointer()` 统一 JSON Pointer 转义与空路径段校验，避免“加载期接受、运行时默默找不到字段”。

因此，2.3A 不是“用户填 JSON 就有执行权限”。它只是后续每层使用相同、可重算、可绑定的输入合同。

## 4. 验证

`backend/tests/test_tool_onboarding.py` 覆盖：完整只读合同、稳定 digest、非只读/高风险/非 MCP 拒绝、远端 `allow_empty` 拒绝、动态表达式/通配符/保留字段拒绝、fixture 摘要与必要 case 拒绝、未知字段和缺 Profile 拒绝。所有新增注释、docstring 和测试说明使用中文。

后续 2.3B 执行受限 Mapper，2.3C 用 fixture 实际验证，2.3D 再把审核状态绑定到动态 MCP 的数据库和 Candidate Catalog。
