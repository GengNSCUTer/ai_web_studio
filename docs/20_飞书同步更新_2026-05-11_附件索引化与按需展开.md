# 2026-05-11 更新：附件索引化与按需展开 v1

## 本次完成

- 新增 `AttachmentContextService`。
- 当前轮文档附件不再全文直接注入 Prompt。
- 后端会把文档解析文本切成片段，并按当前用户问题做关键词级相关性选择。
- `ContextPromptBuilder` 只把选中的附件片段注入最后一条用户消息。
- 前端上下文诊断面板新增附件片段统计。
- 上下文诊断面板已收敛为“概览 + 高级诊断”结构，并增加最大高度与内部滚动，避免指标过多时遮挡顶部内容。

## 当前流程

1. 上传阶段解析 `txt / md / pdf / docx` 得到 `parsed_text`。
2. 发送消息时读取当前用户消息绑定的文件附件。
3. 每个文件按约 `1200` 字符切块，并保留约 `160` 字符重叠。
4. 从当前问题中提取中英文关键词。
5. 对附件片段做规则级相关性打分。
6. 按 `budget.max_attachment_chars` 选择预算内片段。
7. 只把选中的片段注入模型上下文。

## 新增诊断指标

- `attachment_files_seen`
- `attachment_chunks_total`
- `attachment_chunks_selected`
- `attachment_context_chars`
- `attachment_truncated_chunks`
- `attachment_truncated_chars`
- `prompt_attachment_context_injected`

## 当前边界

- 当前是运行时轻量索引，不是持久化附件索引表。
- 当前是关键词级规则打分，不是 embedding 向量检索。
- 当前只处理当前轮上传附件，不做跨历史附件召回。
- 当前前端只展示诊断统计，还没有做片段预览、点击展开或来源定位。

## 下一步建议

- 做附件片段可视化预览与点击展开。
- 或做 tokenizer 级预算与摘要质量观测。
- 后续如果进入文档问答/RAG，再引入持久化索引表、embedding 检索和跨会话文档库。
