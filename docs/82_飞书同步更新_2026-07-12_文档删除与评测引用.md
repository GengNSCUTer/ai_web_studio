# 2026-07-12 后端源码审查：文档删除与评测引用

本轮继续 RAG 索引的数据生命周期专题，只聚焦 `KnowledgeDocument` 被评测用例引用时的删除语义。

## 发现

- `KnowledgeEvalCase.expected_document_id` 的真实 PostgreSQL 外键为默认 `NO ACTION`。
- 旧删除链直接执行 `db.delete(document) + commit()`；被评测用例引用时会泄漏底层 `IntegrityError`，可能表现为 HTTP 500。
- `CASCADE` 会静默删除用户评测资产；直接 `SET NULL` 在当前无 source snapshot 的模型下可能让用例失去全部 ground truth。

## 修复

- 增加 `KnowledgeDocumentConflictError` 领域异常。
- Service 删除前查询 `expected_document_id` 引用并给出明确提示。
- 保留数据库 `NO ACTION` 作为并发竞态下的最终防线；捕获 `IntegrityError` 后 rollback 并翻译成领域冲突。
- Route 将该冲突映射为 `409 Conflict`。
- 新增故障测试，断言冲突发生后 Document 和 EvalCase 均保留。

## 后续

允许删除无评测引用的文档后，数据库 chunks 与 FAISS/BM25 文件仍缺少统一发布协议。该问题将纳入 index generation / active pointer 设计，避免在 delete 方法里选择另一种跨资源半状态。

## Index Generation 设计结论

- 仅给文件增加 generation 目录不够，DB chunks 和查询条件也必须携带同一 generation。
- 第一版采用全量 Chunk 快照，新增 `KnowledgeBase.active_index_generation`、`KnowledgeChunk.index_generation` 和 Generation 状态记录。
- 文件使用 `<knowledge_base>/generations/<generation>/`；active pointer 是唯一读版本权威。
- 发布采用 Compare-And-Swap：只有 active pointer 仍等于构建基线时才允许激活，避免并发构建互相覆盖。
- 删除文档时，候选 generation 文件先构建；active pointer 切换与 Document DELETE 放在同一数据库事务，任一失败共同回滚。
- 现有数据先回填为 `legacy` 并继续读取旧文件路径，避免迁移时要求数据库与文件同时搬迁。
- 实现拆为 legacy 兼容读取、新建/重索引发布器、删除与清理三个可验证阶段。

## Legacy 兼容读取已落地

- 新增 `KnowledgeBase.active_index_generation` 和 `KnowledgeChunk.index_generation`，默认/历史数据均为 `legacy`。
- 新增 Generation 状态记录模型和 `(knowledge_base_id, index_generation, vector_id)` 唯一约束。
- Store 同时支持 legacy 旧路径和 `generations/<id>/` 新路径。
- RetrievalPipeline 把 active generation 同时传给 FAISS/BM25 和 DB Chunk 查询，避免跨代映射。
- 新增混入 future-generation 同 vector ID 的隔离测试，确认 legacy 查询不会泄漏 future Chunk。
- 真实 PostgreSQL 已回填 1 个 legacy KB、376 个 legacy chunks，并创建唯一索引。
