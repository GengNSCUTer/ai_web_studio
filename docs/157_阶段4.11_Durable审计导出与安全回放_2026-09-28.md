# 阶段 4.11：Durable 审计导出与安全回放

## 目标

4.9、4.10 已经解决 Worker 可观察性、任务管理和 Planner 的受控后台建议。本阶段把一次 Durable Run 变成可以安全检查、解释和恢复的执行记录：记录当时使用的工具/Skill 身份，发现版本漂移时停止回放，并允许用户下载不含敏感正文的 JSONL 审计文件。

## 4.9/4.10 的最终边界

- 4.9 的外部邮件/短信告警、自动扩容和集中式 supervisor 属于部署运维，不是本地工作台核心链路；当前保留持久化心跳、Lease/Fencing、Metrics 告警和独立 Worker 脚本。
- 4.10 不让模型字段直接把普通 Chat 切到后台。Planner 只能输出建议，Chat 仍先同步执行；用户确认后才创建只读 Durable Run。这是权限和用户预期边界，不是漏实现。

## 执行快照与漂移检查

`backend/app/services/tools/schemas.py` 新增 `tool_execution_snapshot()`。它从工具 provider、category、adapter 类型、来源类型、风险/只读属性、输入输出 schema、质量合同和 evidence projection 生成稳定 SHA-256 指纹；持久化的摘要不含固定参数、认证信息和完整 adapter 配置。

`DurableToolRunService.enqueue()` 将每个 Tool key 的摘要写入 `AgentRun.planner_state_json`。Worker 真正领取 Step 和用户显式 replay 前，都会重新加载当前 `ToolCatalog` 并比较指纹；同时重新解析当前 Skill，比较版本和 manifest digest。工具风险升级、只读属性改变、schema/质量合同变化、Skill 被停用或审核版本变化都会失败关闭。旧 Run 没有快照时保留已有低风险/allowlist 检查，并在审计中标记 `legacy_snapshot=true`，不会伪装成完整快照。

## JSONL 审计

`backend/app/services/durable_audit_service.py` 生成稳定的逐行 JSON 对象，覆盖：

- `run.summary`：Run 状态、当前步骤、预算、终态和是否为旧快照；
- `run.execution_snapshot`：Skill 版本/digest、工具 provider/category/risk/read-only/fingerprint；
- `step.summary`：工具、依赖、状态、尝试次数、参数哈希、Lease 版本、错误码和错误哈希；
- `checkpoint.summary`：状态版本、观察类型和剩余预算计数；
- `artifact.summary`：产物 ID、内容哈希、字符数和 prompt 状态；
- `outbox.summary`：投递状态、尝试次数、Lease 版本和错误码。

不会导出 `arguments_json`、`content_json`、完整 Artifact preview、Provider 原始响应、URL 查询参数或凭据。接口为当前用户作用域：

`GET /api/agent-runtime/tool-runs/{run_id}/audit.jsonl`

任务页的“导出审计 JSONL”按钮使用同一接口下载；失败重放仍需任务页二次确认，并重新经过快照、Skill、风险和只读检查。

## 修改文件

- `backend/app/services/tools/schemas.py`：工具执行摘要和稳定指纹。
- `backend/app/services/durable_tool_runtime.py`：入队保存快照、Worker/replay 漂移检查。
- `backend/app/services/durable_audit_service.py`：脱敏 JSONL 审计事件生成。
- `backend/app/api/routes/agent_runtime.py`：用户作用域审计下载 API。
- `frontend/src/components/task-dashboard.tsx`：任务详情审计下载入口。
- `backend/tests/test_durable_tool_runtime.py`：快照、漂移拒绝、审计脱敏和用户隔离回归。
- `scripts/stage49_worker_browser_smoke.py`：真实 Worker、原会话、任务页和 JSONL 下载烟测。
