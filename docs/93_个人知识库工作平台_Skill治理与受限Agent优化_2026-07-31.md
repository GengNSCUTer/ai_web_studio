# 个人知识库工作平台：Skill 治理与受限 Agent 优化

更新时间：2026-07-31

## 1. 产品定位与明确非目标

项目定位收口为“个人本地知识库工作平台”：帮助用户整理自己的文档，进行知识检索、研究、审阅和可追溯的低风险辅助操作。产品不追求成为 Codex 式编程代理，也不追求通用 RPA 或无边界自动化平台。

当前明确不纳入 Tool Catalog 的能力包括支付、邮件发送、外部发布、任意外部 HTTP 写接口、Bash、Shell、SQL、删除文件和任意本机文件写入。文件修改仍必须经过 `PatchDraft -> Diff -> 用户确认 -> one-time continuation -> FileRevision CAS`，避免 Skill 或模型静默改变用户材料。

## 2. ReAct 参考与本项目边界

参考的 ReAct 文档把 Agent Loop 描述为 `Think -> Act -> Observe`，并强调模型主动结束、迭代上限、用户取消、异常状态检测、事件流和显式状态机。这些原则适用于本项目，但文档中的代码编辑、Bash 和最多 50 步循环不适合个人知识库工作台。

同步 Chat 保持固定五轮：

```text
LLM Planner -> 代码执行 Tool -> observations -> 可选第二次 Planner -> 最终回答
```

第二轮仍请求继续时记录 `max_rounds_reached`，不暗中进入第三轮。需要更长时间的任务，只有低风险、只读、允许恢复的 Skill 才能显式进入 Durable Tool Run。Durable Run 使用 AgentRun/Step、Outbox、Lease/Fencing、Checkpoint、有限重试、DLQ、受控重放和对账；它不是同步 Chat 的无限循环替代品。

## 3. Skill 治理

Skill 当前采用项目内置、审核后的声明式 Manifest。Skill 只能编排已有 Tool，不能携带 Python、Shell、任意 URL、凭据或新权限。运行时每次重新校验安装、启用、项目/工作区、必需 Tool、凭据和安全审核状态，并由 allowlist 同时约束 Candidate Selector、LLM Planner、fallback 和 Executor。

Skill 安装记录锁定 `manifest_version + manifest_digest`，`SkillInstallationRevision` 保存审核后的 canonical JSON 快照。升级和回滚都是显式接口；缺少 digest 的历史安装 fail-closed。当前 `repository_attestation` 只是仓库内审核/完整性标记，不是第三方 detached cryptographic signature，因此不能宣传成已具备第三方插件市场的签名验证能力。

系统推荐 Skill 只能提供建议：

```text
系统基于语义与规则推荐 -> 用户确认选择 -> 后端再次校验 -> 执行
```

推荐不会安装、启用或扩大权限。第三方市场需要可信发布者公钥、detached signature、隔离拉取、兼容性验证、安全审核、升级/回滚和审计后再考虑。

## 4. Gold Set 与可观测质量

新增 Skill/Tool Gold Set 和离线评估接口，目标指标为 Skill 推荐 Recall@3、Tool Recall、Planner 的 Skill 选择正确率、参数正确率、任务成功率和可选 p50 延迟。评估器只评分提交的 Plan/Trace，不自动调用付费 Provider，也不会把“没有真实运行”的样本计为成功。后续需要建立固定 Case、人工 relevant Tool/Skill 标注和可复现 Eval Run，才能得到可用于决策的在线基线。

Trace 记录候选列表、Planner 计划、Schema/安全校验、实际 Tool 结果、最终回答、轮数和终止原因；运行指标按 Skill、Tool、状态和最近窗口聚合。这样可以区分“正确 Skill 没有召回”“Planner 选错”“参数错误”“工具失败”和“模型没有利用证据”。

## 5. 上下文治理

Prompt 模板升级为 `context_prompt_v4_layer_budgeted`。系统 Prompt、当前用户问题和稳定历史前缀保持独立；证据按 `conversation_summary`、`long_term_memory`、`attachment_context`、`external_context`、`knowledge_context` 分层。超预算时先整体丢弃低优先级层，再压缩仅剩的证据层，再裁剪旧对话，最后才将当前问题作为兜底截断对象。

动态证据仍放在当前轮尾部，稳定前缀保留给 vLLM/OpenAI-compatible 的缓存观察和复用潜力；当前没有接入 OpenAI 或 Anthropic 云端 Prompt Cache，不能作此类宣传。诊断信息包含 dropped/truncated layers 和 retained tokens，便于评估“检索到了但没有注入”与“注入了但被模型忽略”的差异。

## 6. 验证与下一步

本轮后端 `compileall` 和单元测试通过，完整回归为 279 tests，3 项因环境条件跳过；前端 ESLint 和 production build 通过，`git diff --check` 通过。已有真实 Skill E2E 脚本不携带凭据，验证了浏览器显式选择 Skill、受限 Planner、Tavily Tool、最终回答、落库和 Trace 的完整链路。

下一步按优先级推进：先做可复现的在线 Planner Eval Run；再改善长期记忆候选的置信度、语义去重、用户审核和撤销；随后完善 RAG 的召回、重排和上下文利用评估。只有真实需求和供应链基础成熟后，才评估第三方 Skill 市场。JSONL 可作为审计/回放导出格式，但在线业务主存储继续使用 PostgreSQL，不为形式而迁移。
