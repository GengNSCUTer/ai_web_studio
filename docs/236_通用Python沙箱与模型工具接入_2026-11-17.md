# 通用Python沙箱与模型工具接入

2026-11-17。在235的Bubblewrap底座上增加通用Python执行，不再要求为CSV统计、反馈汇总等业务分别注册脚本。当前是离线、单进程、标准库执行，不是Shell或完整Codex执行环境。

## 用户能做什么

- 插件中心增加“通用Python沙箱”：可提交不同Python代码，选择资料副本，查看代码后批准执行，查看stdout和Markdown/JSON/CSV/TXT产物，保存为新的工作区草稿并下载。
- 问答台启用工具后，模型可调用`sandbox.python.execute`准备代码。这里只创建待审批任务，Trace提供“查看代码并批准沙箱任务”链接，模型不能替用户确认。
- 批准后独立Sandbox Worker执行；用户随后可以让模型用`sandbox.jobs.get`读取真实结果并回答。**目前不自动续接原Chat图**，这是“审批后执行、随后查询”，不是原父任务挂起/唤醒全部实现。
- 原有资料清单入口继续工作。通用代码不依赖安装“知识整理”插件，也不把内置执行器伪装成第三方插件；任务以`builtin.python`标识内置来源，不创建虚假的PluginRelease。

当前Chat请求仍用`web_search_enabled`开启工具编排；这不等于允许网络，用户原任务“不联网”仍由动作检查拦截网络工具。新增计算工具走本地Adapter，不经过远端外发规则；原任务未包含计算/脚本意图时不能被证据静默诱导执行。

## 代码怎么实现

`Chat Planner → sandbox.python.execute → Executor校验 → SandboxService.preview_code → 用户批准 → SandboxJob queued → Worker授权复核 → Bubblewrap → 结果检查 → SandboxJob succeeded → sandbox.jobs.get → 模型回答`

| 文件 | 职责 |
| --- | --- |
| `backend/app/tool_manifests/default_tools.json`、`services/tools/selector.py` | 两个通用工具的Schema和候选召回，不注册具体统计业务 |
| `services/tools/executor.py`、`providers/sandbox_python.py` | 代码请求只创建awaiting_approval，结果查询限制当前用户和项目；校验异常回滚短事务 |
| `services/sandbox_service.py`、`schemas/plugins.py`、`api/routes/plugins.py` | 新增Python预览接口，固定本次代码/输入副本；确认接口只接Job ID和approved，不接替换代码；取消沿用现有执行版本 |
| `backend/scripts/run_sandbox_worker.py` | 领取/写回时复查项目权限、类型、取消、owner/version/expiry；取消查询限频为每250ms最多一次 |
| `backend/scripts/prepare_sandbox_python.py`、`sandbox/python_runtime.py` | 从可信已安装解释器单独复制Python3.12、标准库和必需动态库；不复制site-packages、业务环境或配置 |
| `sandbox/bwrap_runner.py`、`sandbox/code_entry.py` | 只读挂载独立运行时和授权输入；代码在seccomp加载后编译执行，print与emit_artifact结果有界回传，再由宿主检查 |
| `frontend/src/components/plugin-center.tsx`、`app/plugins/page.tsx`、`tool-trace-panel.tsx` | 代码编辑/授权预览/结果、从Chat链接打开指定Job；页面通过鉴权接口读Job，不信任URL自带权限 |

新接口：`POST /api/plugins/sandbox/python/preview`，接收`project_id/code/file_ids`，不允许额外的宿主路径、Shell、挂载、域名或资源参数。沿用`POST /api/plugins/sandbox/{id}/confirm`、取消/查询和产物保存接口。无数据库结构迁移。

## 实际边界

- 本机准备的独立运行时为Python3.12.13，标准库和必需动态库来自可信已安装环境的独立复制。代码里不能访问源conda环境，沙箱也不挂载它；系统3.8仍仅用于旧审核脚本。
- 单进程、禁止fork/exec/socket，256MiB地址空间，45秒墙钟/CPU累计。无可写目录，文件处理用授权副本；尚未支持可写临时空间及二进制文件产物。
- 代码最多64KiB，输入最多12份/8MiB；stdout+stderr累计1MiB，print捕获最多65536字符，emit_artifact文本合计512KiB/16份。操作系统输出上限仍是最终边界，帮助函数不是安全隔离措施。
- 即使`full_workspace`，本版代码执行也逐次批准。项目改为read_only后，确认、领取或写回会拒绝；审批前未启动用户代码。模型不能提交confirm工具。
- 标准输出只能是数据，不能声明权限或正式写入成功。通用结果查询仅`succeeded`通过结果质量检查；排队/失败/取消不当作完成数据解锁依赖。
- 不支持Shell、子进程、动态依赖、网络、任意路径写入和自动修改正式文件。原Diff/Approval/FileRevision CAS不改；不声称已实现计划中所有任务恢复/产物存储桥接。
- 同账号进程、共享内核，依旧不宣传为面向公网攻击者任意代码的强隔离。旧Docker检查保留，通用入口只接受实际具备Python能力的Bubblewrap Worker，没有宿主执行兜底。

## 验证

96项定向测试通过，包含通用程序、资料副本、授权、动作意图、候选、原审核脚本与隔离边界。六类不同代码共用同一执行器；实际拒绝网络、fork/exec、写文件、读取宿主资料、内存超量、输出洪泛及错误语法。旧Bubblewrap用例继续验证超时/取消和进程回收。

前端lint/build及12项Node测试通过。真实浏览器先验证旧审核脚本，再提交两段不同代码（均值统计、反馈计数），批准后由Worker执行成功，产物保存下载检查继续通过；移动端无溢出、页面错误0。

在线模型链路验证：首次因测试请求没有启用工具编排，模型只输出代码，不能算调用成功；修正请求后，模型真实创建待批准任务，浏览器打开代码并批准，Worker得到均值4，第二轮真实调用`sandbox.jobs.get`并生成最终答案。没有把工具开关当成联网授权，没有更改Provider或启动Ollama。测试临时项目/任务/会话及插件安装状态按原脚本清理恢复。

开发期间全量后端1459项通过，耗时727.409秒；最后语法检查归属、异常回滚和取消查询限频等细节由96项定向测试再验证。最终CI以当次实际结果为准。记录见`backend/evals/results/generic-python-sandbox-20261117.json`，不把上述专项数字等同线上通用成功率。原200条Agent任务未重测，不改旧成绩。

## 部署

```bash
# 从服务器已信任的Python3.12准备独立运行时，目标不能已存在。
PYTHONPATH=backend backend/.venv/bin/python -m scripts.prepare_sandbox_python \
  --python /path/to/trusted/python3.12 --target .runtime/sandbox/python
# 默认读取上述目录，或由部署人员设置AIWS_SANDBOX_PYTHON_ROOT。
bash deploy/run_services.sh ctl restart backend sandbox-worker chat-worker frontend
```

运行时不入Git，缺少时通用能力明确不可用，旧审核脚本可继续服务。准备脚本不安装依赖或更改源环境。后续可写临时文件、统一Artifact及父图自动恢复仍按[通用沙箱架构](../plan/architecture-sandbox-runtime-1.md)分阶段实施。
