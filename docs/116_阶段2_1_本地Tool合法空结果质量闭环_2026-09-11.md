# 阶段 2.1：本地 Tool 合法空结果质量闭环

日期：2026-09-11
范围：`ResultQualityContract` 的第一小步；只覆盖可控的本地只读 Tool，不改变同步 Chat 的五轮上限，不增加 Tool 或权限。

## 1. 要解决的问题

此前质量门把 `sources=[]` 统一判为 `invalid`。这对 Provider 损坏、字段缺失和远端 MCP 空响应是正确的失败关闭策略，但对以下业务场景不准确：

- 当前项目没有可供 Agent 访问的文件；
- 当前项目没有匹配搜索词的文件；
- 指定文件存在但没有可读取的解析文本；
- 当前项目没有可读取的 Durable Agent Artifact。

这些场景的业务结论是“查询已完成，结果为空”，不是“工具调用失败”。若直接把它们标为失败，最终模型无法可靠说明“未找到”；若仅用 `allow_empty=true` 放宽，又会使 Provider 无故返回空数组被误判为成功。

## 2. 实现合同

`ToolCallResult` 增加受限的 `result_semantics`：

| 语义 | 当前含义 | 当前写入方 |
| --- | --- | --- |
| `evidence` | 普通可引用证据；无 source 默认无效 | Executor 默认值 |
| `empty_answer` | “没有命中/没有数据”本身是业务答案 | 仅 `workspace_file`、`agent_artifact` 本地 Provider 经 Executor 白名单确认 |
| `approval_draft` | 为后续审批提案预留，不代表副作用已完成 | 本阶段未开放给普通 Provider |

空结果通过质量门必须同时满足：

1. 本地可信 Adapter 的 metadata 显式声明 `result_semantics=empty_answer`；
2. 对应 manifest 显式声明 `quality_contract.allow_empty=true`；
3. Executor 根据 Adapter 类型白名单确认语义，而不是相信 Tool 文本、MCP metadata 或模型输出。

未知语义、远端 MCP 自称 `empty_answer`、或普通 `evidence` 的空 source 列表，均保持 `invalid`。这不是新的 `valid_empty` 质量状态，质量维度仍是 `valid / uncertain / invalid`。

## 3. 当前覆盖范围

本阶段只为四个低风险只读 Tool 补齐合同：

| Tool | 正常空结果的固定、安全说明 |
| --- | --- |
| `agent.artifacts.list` | 当前项目没有可读取的历史 Agent 产物 |
| `workspace.files.list` | 当前项目没有可供 Agent 访问的文件 |
| `workspace.files.search` | 当前项目中未找到与本次查询匹配的文件 |
| `workspace.files.read` | 目标文件存在，但没有可读取的解析文本 |

这些说明由本地代码固定生成，不回显本机路径、其他项目、其他用户数据或原始搜索词。它们会作为一个安全 Source 进入最终上下文，因而模型能如实回答“未找到”；内部只保留空集合或调用中已知的文件 ID 等最小 canonical 字段，不能伪造出不存在的文件 ID、坐标或其它结构化参数。

`agent.artifacts.read`、`workspace.files.propose_edit`、`workspace.files.apply_edit` 暂不在本小步放宽：空 Artifact 内容更可能是存储损坏；编辑预览和真实写入还需要分别设计 `approval_draft`、Revision CAS 与审批完成语义。

## 4. 审计与恢复

Executor Trace 的 `tool_result_quality`、`tool_call_end` 均记录最终受信任的结果语义。Durable Worker 写入 Artifact 时额外保存：

- `quality_status` 与受限 `quality_reasons`；
- `quality_metadata`；
- `result_semantics`。

因此恢复、对账和后续 `agent.artifacts.read` 能区分“合法无结果”与“Provider 未返回可用数据”，而不会只看到一个模糊的成功记录。

## 5. 验证

- 质量函数：普通空 evidence 即使合同带 `allow_empty=true` 也判为 `invalid`；可信 `empty_answer` 仅在合同允许时通过；未知语义失败关闭；
- Executor：远端 `mcp_http` 伪造 `empty_answer` 不被信任，本地 Adapter 才可获得合法空结果；
- Provider：workspace list/search/read、Artifact list 的安全空结果不泄露 storage key、跨项目或跨用户数据；
- Workflow：合法空结果可以作为“查询成功”进入最终答复，但缺少 `metadata.raw` 时不能给下游绑定产生虚构参数；
- Durable Worker：持久化 Artifact 保留质量状态与结果语义。
