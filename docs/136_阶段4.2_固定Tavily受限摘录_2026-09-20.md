# 阶段 4.2：固定 Tavily 受限摘录

更新时间：2026-09-20  
状态：已完成阶段 4.2；阶段 4 整体未完成。

## 为什么需要这一小步

阶段 4.1 默认不向下一轮 Planner 回灌外部自由文本，这是安全的默认值。但多步研究有一个实际问题：如果 Planner 只知道“第一轮搜索成功”，却完全不知道搜索证据中的事实，它难以决定是否需要补充检索。

阶段 4.2 不重新开放任意网页正文，而是为一个固定、项目内已审核的 Tool 提供极短摘录。

## 摘录资格

只有以下三项同时满足时，才会生成摘录：

```text
provider     = tavily
source_type  = web_search
tool_key     = web.tavily.search
```

它只能读取该 Tool 已规范化的 canonical `metadata.raw.content`。动态 MCP、工作区文件和其它 Provider 即使声明相同 `source_type` 或伪造 tool key，也不会获得摘录资格。

## 预算与安全收口

- 每次最多投影前两条搜索来源；
- 每条摘录先压缩为单行，最多 240 字符；
- 摘录保存在独立 `excerpt` 字段，附带 `excerpt_status`；
- 标题、URL、`display_text` 和其它 raw metadata 始终不进入 Planner；
- 命中疑似系统提示覆盖、调用 Tool、导出数据或泄露密钥等控制信号时，摘录状态为 `suppressed_suspicious_content`，内容不回灌。

这不是“关键词过滤后文本就安全”的结论。保守抑制只是一层附加措施；候选范围、权限、审批、预算、Schema、SSRF 和实际执行仍由代码侧安全边界复验。

## 代码与测试

- `backend/app/services/tools/observation_projection.py`：摘录资格、长度预算、抑制状态和投影。
- `backend/app/services/tools/planner.py`：明确 `excerpt` 只是受限不可信研究资料。
- `backend/tests/test_tool_router.py`：覆盖正常固定 Tavily 摘录、恶意内容抑制、动态 MCP 拒绝以及两轮 Planner 收到摘录而非原文。

固定两轮测试链路：

```text
第一轮 Tavily canonical content
  ↓
PlannerObservationProjection
  ↓
第二轮 Planner：excerpt=available
  ↓
原始标题 / display_text / URL 不可见
```

## 同轮补充：异常日志不记录 Provider 原文

阶段回归中发现，知识库检索或评测吞掉 Provider 异常后，若仍用
`logger.exception` 输出完整 traceback，异常字符串中的 URL 查询参数可能进入
服务端日志。该路径并不影响用户接口返回，却会扩大运维日志中的秘密暴露面。

现已将这两条已捕获、可继续降级的异常路径改为只记录稳定 `error_code`、资源 ID 和
异常类型；不再记录异常正文或 traceback。`test_knowledge_service.py` 同时断言模拟的
Provider 地址和敏感查询参数不会进入日志。这个修复不尝试抑制未捕获的进程级崩溃日志，
后者应在统一日志过滤层单独治理。

## 未扩展的范围

本阶段没有为工作区文件或动态 MCP 开放摘录。前者需要绑定项目 ACL、文件 revision 和用户意图；后者需要绑定审核合同、canonical Mapper/Profile、Server 版本摘要和漂移失效机制。它们应在后续小步中分别设计和验证。
