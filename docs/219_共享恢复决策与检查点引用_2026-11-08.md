阶段二基于阶段一`a5461a1`继续。阶段一Actions42491805462已成功；不是重构两套Worker，而是把同一类恢复判断收敛到`ToolInvocationRuntime`。

## 实际行为

| 情况 | 共同规则 |
| --- | --- |
| 结果已提交且当前仍有权限 | 核对用户/Run/Step、工具版本、文件/产物范围和内容哈希后复用；不加尝试 |
| Step写明已提交但产物丢失 | 阻断并提示对账，不能假装没执行过再重发 |
| 已请求、没结果、低风险只读 | 原预算/次数内允许重试 |
| 已请求、没结果、含副作用 | 停止自动重放，原审批/CAS不变 |
| 次数耗尽且没结果 | Chat阻断；固定后台任务进入原DLQ逻辑 |
| 当前权限或版本已变 | 不复用旧证据、不执行旧计划 |

`ToolInvocationRuntime.reconcile`给出决策，各协调器仍持有自身当前租约和业务锁。`durable_graph.py`删除了直接见Artifact就复用的捷径，先走`_build_call`及当前授权。`ToolExecutor`改为只依赖共用`current_invocation_runtime`，不再导入Chat专用协调器。Document恢复已提交阶段也核对产物内容且不额外增加一次尝试。

## 检查点怎样变小

新增`chat_tool_snapshot.py`：保存前匹配当前Run已提交工具Artifact中的结构化结果/正文，将相同内容改为`artifact_id + 内部路径 + 内容摘要`引用。预算、规划位置、反馈和无法重构的内容保留，原生图State仍只有安全计数/节点。

读取时先检查引用所属用户、Run、Step、类型、当前Step关联与Artifact内容哈希，再展开成原业务对象。外部JSON里的`$artifact_ref`仍是普通数据，不会触发恢复读取。缺产物、串Run、篡改、过量展开会拒绝。旧无引用快照继续可读，不改已执行任务的版本含义；重新保存自然迁入新格式。恢复检查点及展开内容仍限制4MiB，单工具结果仍保留2MiB限制。

此处内容摘要用于验证“同一持久化产物有没有被改”和内部引用是否仍指向原内容，复用原Artifact的content_hash，不新增数据库表、冻结文件或独立哈希门禁。

## 敏感输入边界

审计脱敏和执行输入不同。Chat保留参数被脱敏时拒绝恢复执行的规则；Durable创建前拒绝需要脱敏的业务参数，避免其input_json/Step里保存明文秘密。工具认证继续由用户范围的CredentialResolver重新读取，不把API Key放进调用计划。这不是新增加密输入仓，也不宣称已支持任意敏感参数自动恢复。
