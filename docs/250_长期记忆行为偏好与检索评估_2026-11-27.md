# 长期记忆行为偏好与检索评估

2026-11-27

## 生效规则

普通 Chat 根据本轮原始问题检查中英文回答偏好。识别到编写、修改代码或给出代码示例的请求时，也检查详细中文代码注释偏好。查询范围为当前用户和当前项目下已启用、有效且来源可用的记忆。当前明确要求优先于项目偏好，项目偏好优先于个人偏好。关闭长期记忆、单轮选择「仅用本轮问题回答」或明确要求本轮不用记忆时跳过注入。

`MemoryRetrievalService` 将匹配到的偏好转换为限定句式。行为层最多两条，和事实层共用三个名额及调用方明确的字符预算。标题、行和分隔符一同计入。先预留一条能放入预算的相关事实，再填充偏好和剩余候选。最终 Prompt 治理按完整行裁剪，记忆层需要缩减时先缩减行为层，再缩减事实层。模型收到前复核候选的版本、来源、作用域和生效状态，实际注入条数来自治理后保留的文本。

## Embedding 切换和补建

设置保存继续清理旧签名。在线召回、冲突分析和索引 Worker 写回向量时使用相同的配置行锁，并在持锁期间核对配置签名和记忆版本。模型请求在事务外执行。索引 Worker 还核对领取时的租约。已部署实例的只读核查扫描了 1 条有搜索向量的记忆，发现 0 条旧签名记录。本次无需数据库迁移。

```bash
PYTHONPATH=backend backend/.venv/bin/python backend/scripts/repair_memory_index_signatures.py
# 有旧签名残留时，把派生搜索向量放回索引补建队列
PYTHONPATH=backend backend/.venv/bin/python backend/scripts/repair_memory_index_signatures.py --apply
```

## 排序对照

[用例](../backend/evals/memory_retrieval_cases.tsv)包含 32 组事实、128 个问题。64 个留出问题与开发集使用不同的事实。候选策略在开发集选门槛和权重，以留出集的 Precision@3、Recall@3、误注入率决定是否生效。三项须同时达到现有策略水平。误注入率指至少注入了一条无关记忆的请求占比。评测使用配置的真实 Embedding API 和合成记忆，用精确相似度评估排序。

| 模型 | 策略 | 语义门槛 | Precision@3 | Recall@3 | 误注入率 |
| --- | --- | ---: | ---: | ---: | ---: |
| BAAI/bge-m3 | 现有 RRF | 0.55 | 73.96% | 91.67% | 32.81% |
| BAAI/bge-m3 | 加权或混合 | 0.60 | 75.26% | 81.25% | 17.19% |
| BAAI/bge-large-zh-v1.5 | 现有 RRF | 0.55 | 65.63% | 62.50% | 9.38% |
| BAAI/bge-large-zh-v1.5 | 加权或混合 | 0.50 | 67.71% | 77.08% | 25.00% |

两组候选未通过留出评测，线上继续使用 0.55 和 RRF。见[评测脚本](../scripts/evaluate_memory_retrieval.py)和[原始指标](../backend/evals/results/memory-retrieval-20261127.json)。

## Redis 观测

每个 ChatRun 记录选择缓存是否命中、是否因容量清空、PostgreSQL 复核耗时、Embedding 请求数和耗时。汇总按新请求、重新生成等 ChatRun 类型拆分，报告不输出问题、记忆正文或用户标识。先收集 14 天且至少 500 次可缓存读取，再根据命中率、清空频率和命中实际节省的成本评估淘汰策略与 Query Embedding 缓存。现行 8 个查询容量和 TTL 继续生效。

```bash
PYTHONPATH=backend backend/.venv/bin/python backend/scripts/report_memory_cache.py --days 14
```

## 验证

Playwright 通过现有 Chat 页面提交三类请求，确认 Provider 实际收到的 Prompt 分别包含两条偏好、一条语言偏好、服从本轮显式要求。ChatRun 诊断与最终 Prompt 一致，浏览器控制台和页面错误均为 0。隔离 PostgreSQL 测试验证冲突分析的迟到向量被拒绝，旧签名向量重新进入补建队列，Worker 在无需 Chat 触发的情况下完成索引。
