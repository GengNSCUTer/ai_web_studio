# 阶段 4.4：受限摘录可用性与跨语言安全回归

更新时间：2026-09-20  
状态：已完成代码实现、离线回归和真实在线 Chat 验证。

## 本步目标

阶段 4.3B 已经把动态 MCP 的 `bounded_excerpt` 接入合同和 fixture，但受限摘录仍偏保守：默认只保留较短文本，且截断可能落在半句话上；注入回归也主要覆盖中文和英文。阶段 4.4 只处理“信息可读性 + 固定跨语言回归”，不扩大新 Tool 的默认正文权限，也不把模型判断当成安全边界。

## 实现内容

- `PlannerObservationProjection` 的 Tavily Profile 将单条摘录上限调整为 720 字符，总预算调整为 2,400 字符，最多允许 4 条来源；每次调用仍严格共享 Profile 总预算，不会因为来源增多而无限扩大 Prompt。
- 摘录额度来自 Tool 的声明式 Evidence Projection Profile，而不是写死在 Provider 分支中。未来新 Tool 仍需声明 canonical content path、来源类型和预算，并通过 onboarding/fixture/人工审核；未声明的 Tool 默认不投影正文。
- 新增句子边界截断：在不超过 Profile 字符预算的前提下，若句末标点位于预算后 30% 区域内，优先保留完整句子；找不到合适边界时仍严格使用硬上限。
- 扩展日语、韩语、西班牙语、葡萄牙语常见“忽略之前指令 / 调用工具 / 系统提示”变体的保守抑制回归。
- 继续区分 `evidence_role=reference_evidence` 与 `instruction_authority=none`：相关事实可以作为参考，资料中的指令没有执行权限。结构化事实投影不因摘录抑制而丢失。

## 代码位置

- `backend/app/services/tools/observation_projection.py`：跨语言抑制模式与句子边界截断。
- `backend/app/tool_manifests/default_tools.json`：Tavily 受限摘录 Profile 预算。
- `backend/tests/test_tool_router.py`：跨语言注入、句子边界和真实投影行为回归。

## 边界

这不是通用 Prompt Injection 检测器，也不是把文本关键词过滤后就视为可信。摘录资格仍由代码侧 Profile、Mapper、质量合同、Tool 身份、ACL、审批和预算共同决定；新 Tool 未声明并通过审核的 Profile 时仍默认 `none`。下一步如果继续阶段 4，应优先做跨来源去重、来源新鲜度/版本绑定和可观测的 evidence 预算诊断，而不是继续无限增加关键词。
