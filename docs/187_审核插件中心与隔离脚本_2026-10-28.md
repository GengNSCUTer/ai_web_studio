# 第三步：审核插件中心与隔离 Python 脚本

本轮把已有 Tool、Skill、文件审批和文档交付组织成四个能力包。插件中心已真实部署并完成浏览器验收；沙箱控制面、独立 Worker、容器运行器和出口代理已实现，但当前机器不满足运行前提，尚未通过真实容器执行验收，不能称为沙箱已上线。

## 用户现在可以做什么

打开前端 `/plugins`，或从设置中心的“工具与集成”进入审核插件中心。首批四包为知识整理、来源研究简报、文档审阅与受控修改、Markdown/Word 交付；每包显示 Skill、实际 Tool、来源、版本、权限、示例和产物类型。

安装预检不安装、不启用能力。确认安装后保存审核版本及所依赖 Skill 的版本记录；再次开启指定项目后，用户还要回问答台显式选择 Skill。文件改写仍走既有 Diff/Approval/FileRevision CAS。插件安装不会自动批准文件修改、联网或任意脚本。

升级和回滚会清除该包的项目启用状态，需重新检查并授权。重复安装同一审核内容保持幂等，不重新停用项目。卸载后，即使历史 Skill 安装记录仍存在，也不能绕过所属插件停用状态执行；共享 Skill 仅在另一个已启用包仍授权时可用。历史直接安装的 Skill 不被本轮强制迁移。

外部 Skill/MCP/脚本只能提交 HTTPS 来源登记，状态为 `pending_review`；服务不自动请求来源，不接受客户端传 `approved`，不提供公共开发者发布。当前审核和发布仍由维护者修改仓库、审查代码和测试完成，仓库审核记录不冒充第三方密码学签名。

## 脚本链路

项目已启用知识整理 → 勾选文件 → 预览审核脚本、文件副本、域名、依赖与资源限额 → 用户确认 → 独立 Worker 执行 → 产物隔离检查 → 任务产物入库 → 用户再次选择保存为工作区新草稿。

首个审核脚本 `document_inventory` 根据授权文档正文副本生成 JSON/Markdown 清单。默认不联网、不安装依赖；可选择审核的 `tabulate==0.9.0` 生成表格。依赖先在无资料容器中解析完整版本和 wheel 摘要，回到 `awaiting_dependency_approval`，用户再次确认后才安装、执行。只允许官方 PyPI 二进制 wheel；Git/任意 URL、源码构建、系统包和运行中自行安装均不支持。安装失败不放宽限制。

Web 只写授权计划，不导入 Docker 执行器。独立 Worker 才接触自己的 Rootless socket，必须不同非 root UID、socket 独占、Rootless+seccomp+cgroup v2、CPU/内存/pids 限额和固定镜像 digest。任务容器无凭据、无 Docker socket、无宿主目录挂载；只读根目录，授权副本只读，临时输出写限额 tmpfs。每个任务销毁容器和网络。

默认容器网络关闭。需联网时仅接内部网络，通过独立 HTTPS CONNECT 代理出站；仅完整授权域名和 443，禁止任务外部 DNS。每个连接检查所有解析地址并固定连接 IP，阻止内网、本机、保留地址和宿主接口地址；跨域重定向需新的授权域名。安装阶段的包源域名与任务阶段的域名分开，资料不进入安装容器。部署在 NAT 后还需配置宿主公网映射拒绝表。

产物只接受有限数量和大小的文本，拒绝 tar 越界、链接、设备文件、嵌套路径和可执行内容。产物保存不覆盖原文件；只读工作区不能创建草稿。任务超时、OOM、输出超量、依赖/联网失败均终止；Worker 写回核对租约 owner/version/expiry，并重新检查插件授权。Worker 失联的过期任务标记 failed，不自动无条件重放。

## 当前真实阻塞

本机 `rootlesskit --net=slirp4netns --disable-host-loopback /bin/true` 返回缺少 `newuidmap`。尚无独立 Worker 系统账号和 Rootless socket；当前账号也不能访问 `/var/run/docker.sock`。以当前 Web UID 启动 Worker 会被独立身份检查拒绝。前端明确显示无可用沙箱 Worker，禁用执行按钮；直接请求确认接口仍被拒绝，任务保持待确认。

按用户要求再次尝试真实部署：补充确认 `newgidmap` 同样缺失，`sudo -n -l` 要求密码，独立账号 `aiws-sandbox` 不存在；宿主是 cgroup v1/v2 混合挂载，v2 的 `cgroup.controllers` 为空，CPU/内存/pids 仍由 v1 控制。不能将混合挂载中的空 v2 目录误报为可用资源隔离。当前缺的是宿主管理前提，未修改系统启动配置或共享 Docker。管理员需提供 uidmap、独立账号和可用 v2 控制器，或者提供满足条件的独立测试机，之后才能继续真实容器验收；完整检查表见 `deploy/SANDBOX.md`。

因此当前没有启动沙箱 Worker，也没有在宿主直接运行审核脚本。真正补齐隔离环境后，必须再测试容器执行、依赖安装、直连/内网阻断、资源耗尽、Worker 崩溃和产物导入。当前命令/策略单测和代理的本地套接字测试不能替代这些测试。容器也不被宣传为可安全运行任意恶意代码的完整保证。
