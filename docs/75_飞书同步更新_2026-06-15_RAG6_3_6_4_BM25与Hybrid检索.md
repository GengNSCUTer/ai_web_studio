# 飞书同步更新：RAG-6.3 / RAG-6.4 BM25 与 Hybrid Search

时间：2026-06-15

本轮完成 RAG-6.3 / RAG-6.4 第一版，知识库检索从单一路向量召回扩展为可配置的三种模式：`vector`、`lexical`、`hybrid`。

## 已完成

- 后端 `KnowledgeRetrievalPipeline` 新增 BM25 关键词召回。
- 后端新增 Hybrid Search：
  - FAISS 向量召回。
  - BM25 关键词召回。
  - RRF 排名融合。
  - optional rerank 最终精排。
- 检索结果 metadata 保留可解释字段：
  - `vector_rank`
  - `lexical_rank`
  - `vector_score`
  - `lexical_score`
  - `rrf_score`
  - `pre_rerank_score`
- 修正 Rerank 后分数语义，不再把 Hybrid/RRF 分数误写成 `vector_score`。
- 后端知识库更新接口支持修改 `retrieval_mode`。
- 前端新建知识库默认使用 `hybrid`。
- 前端新建知识库弹窗可选择：
  - 混合检索（向量 + BM25 + RRF）。
  - 向量检索。
  - 关键词检索（BM25）。
- 前端知识库详情页可直接切换已有知识库的检索模式。
- 检索测试结果展示 BM25 / RRF / Rerank 分数，便于观察召回来源。
- `AGENTS.md` 已补充 Playwright 测试要求：涉及前端页面、关键交互或全链路功能时必须做浏览器冒烟测试。

## 技术取舍

本轮没有引入 Elasticsearch / OpenSearch。

原因：

- 当前阶段更需要先打通检索策略和观测闭环。
- 独立全文检索服务会增加部署和索引一致性成本。
- 个人知识库第一版可以先用 query-time BM25 验证效果。

当前实现保留了替换空间：后续可以把 lexical retriever 底层从内存 BM25 替换为 PostgreSQL full-text、SQLite FTS、Elasticsearch 或 OpenSearch，而不改变上层 `KnowledgeRetrievalPipeline` 调用方式。

## 当前边界

- BM25 当前是查询时内存计算，不是持久化倒排索引。
- Hybrid 当前是单知识库内部 RRF；多知识库之间仍按最终分数合并。
- 尚未实现 Parent-Child / Recursive Retrieval。
- 尚未实现 Contextual Retrieval。
- 尚未实现 query rewrite、多查询扩展和自动评测集生成。

## 下一步

建议进入 `RAG-6.5 Parent-Child / Recursive Retrieval`。

原因：

- BM25 和 Hybrid 解决的是“更稳地召回候选”。
- Parent-Child 解决的是“召回片段过短、回答上下文不完整”。
- 这一步对 PDF / 论文 / 长文档知识库的回答质量提升会更直接。
