# 阶段收尾：五轮受限 Agent、评测与记忆治理

更新时间：2026-07-31

## 1. 同步 Agent 上限

同步 Chat 的 Tool Workflow 已统一为最多五轮 `plan -> execute -> observe`。这是硬上限，不是开放式 ReAct：每一轮仍受单份 ToolPlan 调用数量、Schema、凭据、工作区、Skill allowlist、风险策略、取消与 Provider 超时约束。第五轮还要求继续时记录 `max_rounds_reached`，明确停止并提示用户把低风险只读长任务显式提交到 Durable Tool Run；更早阶段的低轮次限制仅作为历史背景，不代表当前行为。

## 2. 可复现评测闭环

RAG 已有 Eval Set、人工 Chunk/Document Ground Truth、Hit@K、MRR、Context Precision/Recall、检索配置快照、降级标记和延迟记录。本轮增加 Skill/Tool Gold Set 的批量评分入口：只对真实捕获的 Planner Plan 与 execution status 聚合 Skill Recall@3、Tool Recall、Planner 选择正确率、参数正确率、任务成功率与 p50 延迟；评测器不自动发起付费模型调用，也不会把 `not_run` 样本当作成功。

当前可以准确表达为“具备可复现的检索评测与 Tool/Skill Gold Set 评分基础”。尚未执行足够规模、固定 Provider 的线上基准前，不能将评测接口写成某个模型或方案已经提升了多少准确率。

## 3. 自动候选长期记忆

新用户默认开启“自动候选”，每四个用户回合由持久化 Extraction Job 提取一次；它通过幂等键、Lease、有限重试运行，模型只输出候选。候选默认 `pending + is_enabled=false`，不会进入 Prompt。用户需要显式 approve，才会成为 active memory。

候选进入审核前执行以下治理：凭据/直接个人标识检测、短期时效表达检测、长期指令强制复核、低置信度强制复核、内容哈希去重，以及 SequenceMatcher 加中英文词项包含度的改述去重。项目型记忆继承来源会话的 project scope，不能跨项目泄漏。当前去重是可解释的词项近似，不宣称已实现跨模型向量语义去重。

## 4. 产品收口

这一阶段之后，平台优先完善个人知识工作的可信闭环：资料可追溯、检索可评测、记忆可审核、工具可控、长任务可恢复。支付、邮件、外部发布、任意 HTTP 写操作、Bash/Shell、SQL、删除文件和任意本机文件写入继续不在产品范围内。后续不以增加泛化 Tool 数量为目标；只有能加强个人资料研究、整理、审阅、溯源或低风险执行的能力才进入路线图。
