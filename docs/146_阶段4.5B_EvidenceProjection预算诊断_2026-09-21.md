# 阶段 4.5B：Evidence Projection 预算诊断（2026-09-21）

## 目标

阶段 4.5A 已经解决重复来源反复占预算的问题，但此前只能从最终的 `excerpt_status` 逐条判断某个来源为什么没有进入 Planner。4.5B 将这些结果汇总为结构化诊断，让开发和面试复盘可以区分：来源数量超过上限、总字符预算耗尽、单条内容过长、缺少 canonical 内容，还是命中了可疑内容抑制。

## 代码链路

```text
ExternalContextService
  -> PlannerObservationProjection.project_sources_with_diagnostics
  -> 单轮 observations + projection report
  -> 多轮 aggregate_diagnostics
  -> ExternalContextResult.diagnostics.external_evidence_projection
```

主要文件：

- `backend/app/services/tools/observation_projection.py`
  - 保留旧 `project_sources()` 兼容调用；
  - 新增 `project_sources_with_diagnostics()`，在生成 observation 的同时累计状态和预算；
  - 新增 `aggregate_diagnostics()` 汇总多轮数据；
  - 诊断不保存正文，只保存计数、预算和受控状态枚举。
- `backend/app/services/external_context_service.py`
  - 在每轮受限重规划中收集投影报告；
  - 在 `ExternalContextResult.diagnostics.external_evidence_projection` 返回 `rounds` 和 `totals`。
- `backend/tests/test_tool_router.py`
  - 验证多来源 Profile 预算；
  - 验证 `source_limit_reached`、`suppressed_suspicious_content` 统计；
  - 验证诊断字符串不包含来源正文。

## 诊断字段

每轮包含：

- `input_sources`、`projected_sources`；
- `global_source_limit`、`sources_dropped_by_global_limit`；
- `status_counts`；
- `profiles`：每个受控 Tool key 的 `mode`、`allowed_sources`、`allowed_chars`、`max_chars_per_source`、`observed_sources`、`included_sources`、`included_chars` 和状态计数。

整个 Chat 请求额外提供：

- `rounds`；
- 所有轮次的来源、状态和 Profile 数值汇总；
- 每轮报告仍保留，方便定位具体哪一轮发生预算收口。

## 安全与泛化边界

诊断中不保存 excerpt、标题、URL、canonical 正文、请求参数或 Provider 原始 JSON。新 Tool 只要经既有 Mapper 输出统一 `ExternalSource`，就会自动复用这套统计，不需要在诊断器中增加 Provider 分支；但未审核 Profile 不会因此获得正文投影权限。

本步只解释投影结果，不把关键词计数当成 Prompt Injection 的安全边界，也不把 URL 当成来源版本证明。来源新鲜度、工作区文件 revision 和 ACL 绑定留到阶段 4.5C。
