# 2026-06-11 RAG-5 卡住问题根因修正说明

第 64 号同步中已记录知识库问答卡住的修复，但后续进一步确认了更准确的直接根因。

## 直接根因

RAG-5 第一版把 `knowledge_base_name` 等上下文诊断字段放入 `x-context-stats` 响应头。

当知识库名称包含中文时，Starlette 构造 HTTP header 会按 `latin-1` 编码，中文无法编码，后端抛出：

```text
UnicodeEncodeError: 'latin-1' codec can't encode characters
```

因此 StreamingResponse 构造失败，前端请求停在首 token 前，表现为“模型正在思考，请稍候...”，但实际不是模型真正一直在思考。

## 已修复

- `x-context-stats` 改为 ASCII-safe 的 `json64:` base64 JSON 格式。
- 前端 `parseContextStatsHeader()` 优先解析 `json64:`，并保留旧 `a=b;c=d` 格式兼容。
- 新增单测确认中文 stats header 可以安全编码为 `latin-1`。
- 知识库检索超时保护仍保留：
  - `KNOWLEDGE_MODEL_REQUEST_TIMEOUT_SECONDS=60`
  - `KNOWLEDGE_CONTEXT_TIMEOUT_SECONDS=25`
  - 慢检索会降级为上下文 notice，不再拖住聊天。
