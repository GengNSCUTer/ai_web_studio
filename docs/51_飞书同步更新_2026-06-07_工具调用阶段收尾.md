## 已完成能力

### 1. 流式链路稳定性

- `/api/chat`、`/api/chat/regenerate`、`/api/chat/edit-last-user` 三个前端代理 route 已统一走共享流式代理函数。
- 代理 route 只转发轻量 header，并对 `x-context-details` 做长度保护。
- 后端对 context stats、notices、details header 做大小限制，降低复杂工具调用后的 header overflow 风险。
- 后端模型异常时发送 `model_error` NDJSON 事件。
- 前端区分用户主动停止、模型错误、流式中断、工具错误。

### 2. Planner 主路径优化

- LLM planner 继续作为主路径。
- deterministic planner 只作为缺少 runtime、LLM 超时、LLM 输出不可解析等场景的兜底。
- Planner prompt 增强复杂问题多工具拆分要求。
- Planner 支持并强调 `depends_on / can_parallel`。
- 新增复杂 query 测试，覆盖路线、天气、地点搜索、网页搜索的组合规划。

### 3. MCP 工具目录增强

- MCP Server 添加入口改为弹窗式表单。
- MCP tools 支持查看原始 input schema。
- MCP tools 支持编辑描述覆盖和工具分类。
- MCP tools 支持单工具测试入口，用户可输入 JSON arguments 调用 MCP `tools/call`。
- MCP tools 启用/禁用在卡片中清晰展示。

### 4. 工具结果引用增强

- 工具执行器会给来源结果补充 `call_id / tool_key / tool_display_name / source_index`。
- 来源卡片支持展开查看原始结果。
- 来源卡片可以跳转到对应 Tool Trace 调用记录。
- Tool Trace 调用完成/失败事件可以跳转到对应来源卡片。

## 阶段性结论

工具调用阶段可以阶段性收尾。当前项目已经具备：

- 用户级工具凭据
- MCP Server 注册
- MCP tools/list 同步
- MCP tool 启用/禁用
- LLM planner 主路径
- DAG/并行工具执行
- 有限 replan
- Tool Trace
- 工具来源引用

后续主线建议切换到知识库 / RAG：

- 工作区文件库入库
- 文档解析和索引任务
- 向量检索 / 关键词检索 / 混合检索
- 检索引用定位和文档预览
- RAG 召回结果进入现有上下文治理预算
