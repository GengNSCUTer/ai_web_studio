# 编辑提案：发现、规划、Diff与完成判断修复

2026-11-04。承接[预算实验200](200_同步Tool预算真实实验_2026-11-04.md)。本轮处理编辑提案链路，不增加轮数、调用数、并发或时间上限，也不开放新的本机写入能力。

## 1. 这次修复什么

用户要求“读取一份文件，提出标题或保留周期修改预览”。真正成功应是：找到目标文件、读取原文、用原文和当前版本生成服务端验证的Diff、回答展示该Diff；文件保持原样。安全上没有写错文件，并不等于已经完成这个业务目标。

```text
用户明确要求修改预览
  → 当前权限/Skill范围内选择定位、读取、只读预览工具
  → Planner定位文件并read
  → 下一轮看到有限的原始正文、真实file_id与revision_id
  → Planner生成逐字old_string/new_string，调用propose_edit
  → Provider重新检查用户/项目、版本和唯一替换
  → read/preview同目标同版本，才满足预览完成条件
  → 最终模型展示真实Diff，明确尚未写入
```

`propose_edit`只是临时Diff，不创建持久化PatchDraft、审批或写入任务。用户另行要求实际修改时，才走原有`apply_edit`提案/审批/Revision CAS流程。只读预览仍保持Workflow的`waiting_approval`，不会因此解锁依赖“已经写入”的DAG节点；这和“生成预览”目标已经完成不矛盾。

## 2. 定位到的根因与实际修改

| 环节 | 发现的问题 | 修复位置和行为 |
|---|---|---|
| 工具发现 | “标题改为”未被编辑意图规则覆盖，预览可能不进候选；只读预览与实际写入没有在意图层分清 | `file_edit_intent.py`统一预览/编辑识别；`selector.py`给已审核只读approval_draft候选加权，预览请求排除非只读工具，仍受启用和Skill allowlist限制 |
| 读取反馈 | read仅投影file_id、版本、行号，Planner看不到被读取的原文 | `providers/workspace_files.py`返回实际读取行的脱敏canonical正文，不带展示行号；默认manifest为该工具声明bounded_excerpt，单来源1600、最多4来源/共6400字符 |
| 字面准确性 | 通用投影会压平换行，参数校验会strip字符串，原文缩进及换行被改变 | Profile支持审核后的`preserve_whitespace`；预览/写入旧文、新文字段以`x-preserve-whitespace`保留原文，仍校验类型和长度；文件ID等普通字符串继续规范化 |
| 规划格式 | 模型将上轮read的ID放进本轮depends_on，或把result_bindings写成object | `planner.py`明确跨轮直接用已读ID/版本和excerpt；只有本轮待执行节点才写DAG边，给出预览计划示例；无效计划保留脱敏校验原因，不放宽解析器 |
| 查找文件 | 模型传file_name:null，被通用字符串校验转成"None"；中文需求拼英文项目代号产生词法未命中 | `validation.py`省略未提供的可选字符串null；预览规划提示只用短原文关键词，空结果后list定位真实ID，不重复同一空结果搜索 |
| 兜底 | 编辑规划失效后走普通网页搜索兜底，既无助于本地编辑，还外发本不需要搜索的项目问句 | 明确文件预览仅有限延续只读定位/读取，无法构造安全后续时返回未完成，不退到网页搜索，不猜替换文本 |
| 完成判定 | 有一次read就被认为证据充分，没有要求Diff，最终模型可能自行写一个草稿 | `edit_preview_completion.py`要求真实read和preview、同file_id和revision；显式多个文件要求逐一覆盖。`external_context_service.py`追加缺口并在原预算内续轮；最终`evidence_sufficiency.py`区分有效Diff和不足，普通文字不是工具证据 |

原文中的指令仍不是授权：沿用完整canonical文本可疑指令检查、摘录抑制、字符/来源上限、Executor ACL/风险/Schema及版本检查。仅对当前已审核文件读取工具开放受限正文；新工具不自动获得该权限。未命中、可疑、超预算等状态不会因为保留空白就变成可用正文。

范围仍有限：预览意图识别覆盖常见中英文明确请求，不等同于任意语言意图理解；多目标完成检查支持显式文件名与同目标版本匹配，不是通用语义任务评审。最终模型仍可能违背提示，代码的证据充分性不是对自然语言所有断言的语义证明；本轮不增加线上语义Judge。

## 3. 真实复测与中间失败

原35秒和50秒各6条编辑实验均没有有效Diff，这个历史结论保留。不是靠换题、扩大预算或把文字草稿当工具成功。

修复过程保留两个中间文件：

- `tool_budget_experiment_20261104_edit_fixed_r1.json`：仅修正文可见性和初步完成要求时，模型仍把上轮read写为本轮依赖，六条未完成；据此修正规划说明并关闭网页兜底。
- `tool_budget_experiment_20261104_edit_fixed_r2.json`：四个标题请求已实际生成预览，线上`evidence_sufficiency_status=sufficient`、ToolCall为waiting_approval；旧评分器只收success来源，误记为部分完成。另两次定位请求确有null过滤/混合词法问题。该文件保留原分数，不把它当最终完成率；不会根据已清理后缺失的来源补造“原始证据”。

评测脚本已更正：只对`workspace.files.propose_edit`接受waiting_approval，并且必须同时存在`workspace_file_edit_preview`来源、`raw.applied=false`和目标替换文本；写入审批卡片、模型文本、单纯read都不算。单调用状态指标仍如实保留waiting_approval，不把它冒充实际写入success。

最终对原三个任务各重复两次，生产参数仍是4轮/6调用/35秒/并发1；结果见`tool_budget_experiment_20261104_edit_fixed_final.json`。浏览器独立走真实UI→Next代理→FastAPI→在线模型/工具→最终回答→数据库→刷新，报告`edit_preview_browser_20261104.json`，截图`/tmp/aiws-edit-preview-browser.png`。任务只创建临时项目及脱敏文件，不修改账号或旧项目。
