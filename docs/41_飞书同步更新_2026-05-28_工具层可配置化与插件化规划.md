# 2026-05-28 工具层可配置化与插件化规划

本次更新只做架构和需求文档梳理，不做代码实现。

## 背景

当前项目已经实现：

- 联网搜索按钮。
- Tavily Search。
- 高德天气。
- 高德地图基础 API。
- 深度思考。
- 来源折叠展示。
- Markdown、代码块和数学公式渲染。

但工具层仍然偏 MVP：

- 工具逻辑集中在 `ExternalContextService`。
- 工具调用过程不可视化。
- 工具调用 Trace 没有独立持久化。
- Tavily / 高德 API Key 写在后端 `.env`。
- 工具列表固定在代码中。

## 调研结论

参考 Dify、Coze、Ragent 和主流 Agent 平台后，建议不要直接堆叠工具，也不要马上复制完整插件市场。

更适合当前项目的路线是：

```text
内置工具注册表
-> 工具调用过程可视化
-> Tool Trace 持久化
-> 用户级/工作区级工具凭证
-> 工具启用/禁用
-> 自定义 HTTP 工具
-> MCP Client
-> 插件市场
```

## 六项规划

### 1. 工具调用过程可视化

新增流式事件：

```json
{"type":"tool_plan","plan":{...}}
{"type":"tool_call_start","call_id":"...","tool_key":"..."}
{"type":"tool_call_end","call_id":"...","elapsed_ms":320}
{"type":"tool_call_error","call_id":"...","error":"timeout"}
```

前端用类似 `思考过程` 的折叠面板展示工具过程。

### 2. 工具层拆分

把当前 `ExternalContextService` 拆成：

- `ToolRegistry`
- `ToolCredentialResolver`
- `ToolRouter`
- `ToolExecutor`
- `ExternalSourceFormatter`
- `ExternalContextAssembler`
- `ToolTraceRepository`

聊天主流程继续只依赖统一 facade。

### 3. Tool Trace 持久化

新增：

- `tool_route_runs`
- `tool_call_runs`

用于保存工具计划、工具调用、耗时、失败原因、fallback 和来源。

### 4. 来源卡片增强

新增专用卡片：

- 网页来源卡片。
- 天气来源卡片。
- 地图 POI 卡片。
- 路线规划卡片。
- 知识库引用卡片。

### 5. 工具可配置性

前端新增独立设置页，把 `工具与集成`、`工具凭证` 从聊天弹窗中拆出来。

凭证优先级：

```text
工作区级工具配置
-> 用户级工具配置
-> 后端 .env fallback
-> 未配置则禁用工具
```

API Key 不能明文回显，后端日志和 Tool Trace 不能记录完整凭证。

### 6. 工具导入与选择

近期不做完整插件市场。先做：

- 内置工具目录。
- 用户启用/禁用工具。
- 本地 manifest。
- 自定义 HTTP 工具。
- MCP Client。

完整插件市场等安全、权限、版本和沙箱机制成熟后再考虑。
