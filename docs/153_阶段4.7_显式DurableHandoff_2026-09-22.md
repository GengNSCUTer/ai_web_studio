# 阶段 4.7：显式 Durable Handoff

## 本阶段目标

把适合长时间执行的低风险只读任务，从同步 Chat 交接到已经存在的 Durable Agent Runtime，同时保留清晰的用户确认边界。

本阶段不是把普通 Chat 自动改成后台任务，也不是扩大 Tool 权限。普通 Chat 仍按当前运行模式同步执行；只有用户明确确认后，才创建可恢复的 `AgentRun`。

## 交接流程

```text
同步 Chat / 用户选择低风险只读 Skill
        |
        v
POST /api/agent-runtime/tool-handoffs/preview
        |
        | 代码检查用户/项目/会话范围、Skill durable_eligible、Tool low-risk + read-only
        | 返回短时签名 handoff token；不创建数据库 Run、Step 或 Outbox
        v
用户查看任务范围并确认
        |
        v
POST /api/agent-runtime/tool-handoffs/confirm
        |
        | 令牌验签、过期检查、用户范围检查
        | 只能使用令牌冻结的 calls，不能在确认请求中替换调用计划
        v
DurableToolRunService.enqueue()
        |
        v
AgentRun + AgentStep + AgentOutboxEvent + AgentCheckpoint
        |
        v
已有 Durable Worker：Lease / Heartbeat / Fencing / Retry / DLQ / Artifact
```

## 代码职责

- `backend/app/services/durable_handoff_service.py`
  - 负责短时预览令牌、签名、过期和作用域验证。
  - 预览只展示 Tool 名称、步骤 ID 和依赖关系，不返回原始 Provider 内容或凭据。
  - 确认时不接受新的 `calls`，把令牌中的冻结请求交给现有 Durable Runtime。
- `backend/app/api/routes/agent_runtime.py`
  - 新增 `/tool-handoffs/preview` 和 `/tool-handoffs/confirm`。
- `backend/app/schemas/agent_runtime.py`
  - 定义 handoff 请求、预览摘要和确认请求。
- `backend/app/services/durable_tool_runtime.py`
  - 本阶段不替换现有状态机；继续负责完整 Tool Schema、依赖 DAG、Skill allowlist、幂等、Outbox、Checkpoint、Lease 和 Worker 状态收口。
- `backend/tests/test_durable_handoff_service.py`
  - 覆盖预览不落库、确认幂等、高风险/非 Durable Skill 拒绝、篡改令牌和过期令牌拒绝。

## 安全边界

1. 预览不是执行授权。没有确认，不会产生可领取的 Outbox Event。
2. 确认接口不允许客户端重新提交工具列表，防止“预览低风险、确认换成高风险工具”。
3. 预览阶段只做早期可见性检查；确认阶段仍由 `DurableToolRunService.enqueue()` 重新执行完整 Schema、依赖、权限和幂等检查。
4. 当前只接受低风险只读 Tool；文件写入、删除、Shell、SQL、支付、邮件、外部发布和任意 HTTP 写接口不在 Durable handoff 范围内。
5. 相同 handoff token 的重复确认使用稳定幂等键，返回同一个 Run，不重复创建 Step/Outbox。

## 前端闭环

`frontend/src/components/tool-trace-panel.tsx` 已把 handoff 接入 Chat 的工具追踪面板：

1. 当前 assistant 消息存在受控 `tool_plan` 时，用户可点击“转为可恢复任务”。
2. 前端提交当前项目、会话、assistant message 和冻结的只读 Tool calls，展示后端返回的步骤摘要；完整参数不会作为确认表单重新编辑。
3. 用户点击“确认并后台执行”后只提交短时 handoff token，不能替换 Tool calls。
4. 返回 `AgentRun` 后，面板可手动刷新并展示 Run 状态、步骤状态、错误和 Durable Artifact 摘要。

`chat-message-list.tsx` 和 `chat-thread.tsx` 负责把项目、会话、当前 Skill 范围传给追踪面板；`lib/types.ts` 保留依赖和 Result Binding 字段，便于后续由 Planner 生成受控计划。

## 验证结果

- Durable handoff 服务定向测试：4 项通过，覆盖预览不落库、确认幂等、风险/Skill 拒绝、令牌篡改和过期。
- 后端全量测试：478 项通过，包含 PostgreSQL/pgvector 条件集成测试。
- `compileall`、`git diff --check`：通过。
- 前端 ESLint：通过。
- 前端 `npm run build`：通过。
- 真实在线模型浏览器 smoke：通过。临时工作区中由 LLM Planner 规划 `workspace.files.search/read`，工具执行成功，最终回答持久化为 `done`，文件正文未被修改，浏览器无 console/page error；夹具已清理。
- 真实 Durable Worker smoke：通过。preview -> confirm 后，独立 Worker 执行 `workspace.files.list`，Run 收口为 `succeeded`，Step 为 `succeeded` 并写入 1 个 Artifact；期间修复了 `autoflush=False` 下 Run 终态查询读取旧 Step 状态的问题。

前端 handoff 按钮、预览和确认代码已通过 lint/build；真实浏览器 Chat 主链能够完成 Planner、只读 Tool 和最终回答。由于在线模型返回 Tool Trace 的时序可能变化，本轮没有把“按钮一定出现”作为后端功能的通过条件；preview/confirm 已通过真实 HTTP 调用和 Worker 执行验证。

## 阶段边界

4.7 收尾后，普通同步 Chat 仍保持有界执行，不会因为达到轮次或工具上限而静默转后台。Durable handoff 目前只接受低风险、只读、已审核且 `durable_eligible` 的 Skill/Tool；文件写入仍必须走 Diff、用户确认和 Revision CAS，不与只读 handoff 混用。Worker 通过 `backend/scripts/run_agent_tool_worker.sh` 独立运行，控制面不会假装 Worker 已被永久部署。

后续若继续产品化，优先补 Planner 生成受控 handoff 计划、Worker 结果回绑会话、受控 replay/告警和部署运维；这些不属于本次 4.7 收尾的必要条件。
