# 统一执行内核最终验收与成本对照

本轮四阶段接在Chat独立任务和工具持久化之后，覆盖2026-11-08至11-09。目标是合并重复的执行规则，不再次更换架构。阶段一至三分别见[218](218_统一工具执行内核_问题核对与阶段计划_2026-11-08.md)、[219](219_共享恢复决策与检查点引用_2026-11-08.md)、[220](220_统一产物存储与历史成果复用_2026-11-08.md)；本篇记录最后的真实业务、故障与成本验收。历史失败报告保留，不追溯改分；学习仍停在Day28补强，不修改简历。

## 最终实现怎样串起来

Chat Worker负责动态Plan→Execute→Observe，Durable Worker负责用户确认后的固定计划，文档业务图继续组织取证→草稿→导出→可选审批保存。两类Worker没有合并，也没有为每个工具额外排队。

各协调器先在短事务中核对自己的父租约、版本、generation、用户/项目与当前权限，再调用`ToolInvocationRuntime`判断：已有正式结果则复核后复用；未提交的低风险只读调用可在原预算内重试；不明副作用、结果缺失、权限变化或尝试耗尽则阻断。它统一身份、尝试、结果质量与产物创建，但不独自commit、不代替Executor，也不决定所有业务状态。

实际请求仍经`ToolExecutor`校验Schema、动作意图、权限、凭据、安全和预算。返回后，协调器在锁内重新检查执行权，将Step与Artifact一起提交。恢复以业务Step/Artifact为准，原生LangGraph位置不能证明外部调用成功。

`AgentArtifactStore`是Chat、Durable、Document全部生产产物的构造入口。Chat内部恢复数据不进入历史业务列表；文档草稿、导出和只读工具结果可按当前用户/项目发现，重新核对来源、版本、撤销和时效。Checkpoint尽量引用已有Artifact，保留预算、规划位置和不可重建的派生状态，旧格式仍可读。

## 故障实验

脚本`tool_runtime_reliability_e2e.py`创建独立PostgreSQL库，运行正式工具图与真实工作区文件适配器，Planner固定以排除模型随机性；子进程实际`os._exit`，父进程等待真实45秒租约。不是修改数据库时间模拟到期，也没有终止其他项目服务。

| 场景 | 文件工具实际执行次数 | 业务SQL条数 | 已存结果复用 | 接管后至证据就绪 |
| --- | ---: | ---: | ---: | ---: |
| 正常串行两工具 | 2 | 144 | 0 | 不适用 |
| 正常并发两工具 | 2 | 144 | 0 | 不适用 |
| A调用前退出 | 2 | 223 | 0 | 460.0 ms |
| A返回、结果未提交时退出 | 3 | 227 | 0 | 546.9 ms |
| A结果提交后退出 | 2 | 223 | 1/1 | 413.5 ms |
| 两结果提交、业务检查点前退出 | 2 | 238 | 2/2 | 384.3 ms |
| 不明写入副作用 | 0次真实写工具 | 82 | 不适用 | 41.5 ms后阻断 |

7个场景均达到各自预期；4/4只读故障任务恢复完成，3/3已提交产物被复用。不明写入场景用隔离表模拟外部副作用已发生而回执丢失，并未执行未审批的文件修改；原call_id和换call_id均不能重放，模拟副作用数始终1、重复数0。这不等于支持所有外部写工具exactly-once。

只读“返回后、提交前”的窗口实际多读一次，这是至少一次的成本，不能宣传无重复调用。故障至恢复证据完成约42.25—42.94秒，主要在等原租约；384—547 ms只是获得新执行权后的处理时间。故障相比正常增加79—94条业务SQL。完整原始值见`backend/evals/results/tool-runtime-reliability-20261108-r1.json`及同名Markdown。

## 最终审阅修复

补测发现：文档草稿/导出隐式依赖同Run的取证产物，却只校验其内容与原资料，漏掉取证产物自身被撤销、过期、归档或步骤失败。原回归先复现失败，再让隐式上游通过同一`reusable`规则递归检查；共享深度/总量限制避免循环。撤销现在能传播到旧草稿/导出的历史发现。普通下载及正式审批边界未改变。

主要文件：`tool_invocation_runtime.py`管调用规则，`chat_tool_snapshot.py`管引用型检查点，`agent_artifact_store.py`管产物/上游资格，`tools/providers/agent_artifacts.py`管发现读取，`artifact_semantic_ranker.py`管默认关闭的在线语义精排；Chat/Durable/Document各自保留业务锁、图和提交。

验收脚本新增正常/故障成本报告；`document_task_real_acceptance.py`增加可持久化结果文件及失败类型，不记录凭据。最终1314项后端含真实PG/Redis全部通过、0跳过（236.857秒），相关45项另行通过但不与全量相加；前端lint/build、5项Node事件/认证测试、compileall与diff检查通过。Node提示现有package模块类型未声明，不影响通过，本轮未为消除提示改构建语义。Web/Chat/Durable/Frontend已使用单套Supervisor重启，临时基线checkout在实验后删除；没有启动Ollama。

## 边界

恢复不是半截Token续接；最终回答最多重新生成一次，消耗可能增加。没有新增外部幂等写或对账处理器，不明副作用继续阻断。历史成果发现最多扫描60条、在线精排最多24条且须原任务明确同意，默认本地匹配；不等于全量历史ANN搜索。时效控制不删除用户报告。沙箱真实容器仍未验收，不开放宿主Shell、SQL、任意路径写入或其他高风险能力。未进行新的200任务或百题RAG全量评分，不用本轮小样本替换历史报告。
