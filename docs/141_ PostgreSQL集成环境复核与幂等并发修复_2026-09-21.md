## 3. 发现并修复的问题

并发 Durable Run 使用相同幂等键时，PostgreSQL 唯一索引会正确阻止重复 Run。但唯一键冲突可能在 SQLAlchemy `flush()` 阶段发生，旧代码只在 `commit()` 阶段捕获 `IntegrityError`，因此会把本可安全收口为“返回已有 Run”的请求暴露成异常。

修复文件：

```text
backend/app/services/durable_tool_runtime.py
```

现在 `enqueue()` 在 `flush()` 和 `commit()` 两个阶段都执行相同的幂等收口：

1. 回滚当前失败事务；
2. 按用户作用域内的幂等键读取已有 `AgentRun`；
3. 比对请求哈希；
4. 哈希一致则返回已有 Run；
5. 哈希不一致则返回幂等冲突；
6. 找不到已有记录时才继续抛出未知数据库错误。

这使得“数据库唯一约束 + 应用请求哈希”共同保证并发幂等。
