# 2026-05-19 深度思考与联网搜索规划同步

本次更新围绕 AI Web Studio 还缺少的两个 ChatGPT / 豆包 / DeepSeek 类网页端能力展开：

- 深度思考按钮
- 联网搜索按钮

本次只做调研、方案设计和文档更新，未进入代码开发。

## 1. 深度思考结论

深度思考不能简单做成前端按钮后拼 Prompt。它需要 provider capability、provider-specific 参数、流式协议、reasoning 展示和持久化一起设计。

调研结论：

- Ollama 官方 API 支持 `think` 参数，支持 thinking 的模型可返回 `message.thinking`。
- SiliconFlow / Qwen 这类 OpenAI-compatible provider 常通过 `enable_thinking` 和 `thinking_budget` 控制推理模式。
- OpenAI reasoning、Gemini Thinking、Claude Extended Thinking 都有各自协议，通常不承诺返回完整原始思维链，更常见的是 reasoning summary 或 thinking block。
- 因此前端文案应区分“思考过程”和“思考摘要”，不能承诺所有模型都能显示完整思考链。

建议第一版：

- 输入区新增 `深度思考` toggle。
- 默认关闭。
- 后端根据 provider profile 决定是否发送 `think` / `enable_thinking` / 其他字段。
- 流式协议升级为 NDJSON 或 SSE，区分 `reasoning_delta` 和 `answer_delta`。
- 前端用折叠面板展示 reasoning。
- 后端保存 thinking 是否启用、是否可见、耗时和内容/摘要。

## 2. 联网搜索结论

联网搜索有两条路线：

- Provider 原生搜索工具，例如 OpenAI Responses API Web Search Tool。
- 应用层外部搜索 API，例如 Tavily / Brave / Bing / SerpAPI，然后把搜索结果注入 Prompt。

结合 AI Web Studio 当前“本地优先、多 provider 兼容”的定位，第一版建议使用应用层搜索：

- 后端调用 Tavily。
- 搜索结果清洗成统一结构。
- 作为 `web_search_results` 上下文层注入模型。
- Ollama 和 OpenAI-compatible provider 都可复用。
- 回答中用 `[1] [2]` 引用来源。
- 前端展示来源卡片。

建议第一版：

- 输入区新增 `联网搜索` toggle。
- 单轮生效，默认关闭。
- 第一次开启提示隐私边界。
- 设置页支持 Tavily API key、搜索深度、top_k、失败回退策略。
- 后端新增 `WebSearchService`、`TavilySearchProvider`、搜索 run/result 持久化。
- 上下文诊断展示搜索结果数量、token 占用、裁剪原因。

## 4. 推荐下一步

下一轮如果开始开发，建议先做：

```text
P2.5-1 深度思考按钮 MVP
```

原因：

- 当前代码里 Ollama 和 OpenAI-compatible 已经明确关闭 thinking，改造入口非常清晰。
- 深度思考改造能倒逼流式协议升级，为后续联网搜索状态、工具调用、Trace 展示打基础。
- 相比联网搜索，它暂时不需要引入第三方 API key 和搜索结果数据表，风险更低。

完成后再做：

```text
P2.5-2 联网搜索按钮 MVP
```

再继续：

