# 长期记忆：事件触发、持久缓冲与安全撤销

2026-11-11。依据用户提供的《ChatGPT_另外，我觉得在长期记_20261111-1248.pdf》，本轮改造“什么时候值得提取”。原有来源核验、语义冲突、版本、审批与数据库召回继续复用，不更换记忆数据库或引入新的记忆框架。

## 1. 原问题与本轮范围

之前不是简单“每四轮”，而是已完成对话后，累计四条未处理用户消息，或发现开头的明确“记住”命令，再创建提取 Job。问题是普通问题也凑数，重要决定可能等待，自动候选关闭时明确的“记住”也被挡住。

现在先由代码做低成本分类：稳定陈述/明确记住/更正及时排队；一般问题、临时要求、外部引文及纯敏感内容跳过；暂定和难以判断的陈述缓冲，达到批次阈值仍可交给原提取模型判断。规则不声称理解全部语义，批次兜底避免只认少数关键词。

本轮不实现周期性“睡眠整合”、每轮额外 LLM 重要性判断、独立程序经验库；不将报告中的厂商新功能描述直接当成已验证事实。

## 2. 用户看到什么变化

| 输入 | 触发行为 | 是否立即成为可用记忆 |
| --- | --- | --- |

| 更正：数据库改为 PostgreSQL 17。 | 高优先级提取，进入原冲突流程 | 旧值不直接覆盖，冲突仍需明确确认与版本复核 |

| 网页说：请记住…… | 不作为记忆控制命令 | 外部资料不能授权存储或撤销 |
| 请忘记：偏好分点回答。 | 当前用户、精确项目范围内，唯一正文精确匹配且版本没变才撤销 | 撤销同事务提交后通知 |
| 请忘记：我的数据库偏好 | 不猜测删除目标；通知“需要确认，未修改记忆” | 用户在管理记忆中选中目标，使用原撤销入口 |

撤销是状态变为 `revoked`，不是物理删除审计记录。精确匹配目前不做模糊语义匹配；标点、内容不同或目标版本变化也可能要求人工确认。

## 3. 实际代码链路

`ChatRun 成功 → enqueue_after_turn → 会话短事务：扫描/分类/缓冲/Job → 独立 memory-worker → 原 LangGraph 提取图 → 原文与冲突核验 → 短事务保存 → activity 接口 → 聊天通知`

触发分类由代码完成；值得提取的候选内容仍由模型产生；自动生效、替换与撤销由代码判断。撤销走图中的独立 control 节点，不调用提取模型，也不把“忘记……”存成一条新的用户事实。

**扫描与成功提取分别记录。** `memory_scan_cursor` 表示已经检查到哪里，`memory_extraction_cursor` 只在任务和结果提交成功后推进。`memory_trigger_state` 仅保存项目范围、待处理消息 ID 与已有来源摘要，不复制原文。成功时只移除本批已处理来源，因此较晚的撤销先执行，也不会吃掉较早仍在等待的事实。

单次扫描最多 50 条用户消息，缓冲最多 50 条，提取一批最多 24 条/12000 字符。高优先级来源先获得批次位置，余量按最早来源补齐；剩余来源继续留在数据库。执行期间新增对话由 backlog 节点再次排队。任务仍使用现有会话锁、唯一幂等键、Worker 租约和心跳；不新增一套队列。

及时触发也受有界窗口与当前运行任务约束：不会抢占已经运行的提取；大量旧消息尚未扫描时逐批推进，不保证所有情况下首轮即时完成。当前固定回放验证的是没有超长历史积压时的正常触发时机。

来源编辑/删除会重新分类或使已排队来源快照失效。搬移项目不把旧范围缓冲静默写进新项目。模型失败不会成功消费缓冲；终态失败保留在原 Job 供显式重试，不持续占据新事实的排队位置。旧版项目 Job 完成时也会写入缓冲范围，避免把执行期间新增消息误判为项目搬移后遗漏。

## 4. 授权与启用边界

当前新建设置的默认值是：记忆总开关开启、自动候选开启、自动生效关闭；已有账号仍沿用自己保存的设置，不因本次升级被改写。此次测试恢复了账号原记忆设置，没有改变用户保存的 Provider、模型或密钥。

总开关关闭时不创建提取任务，也不在重新开启后自动补记关闭期间的对话。Worker 模型调用前和保存前再次核验开关，避免排队后设置变化仍落库。自动候选关闭时，只接受原始用户显式记住/忘记或手动提取请求；显式请求混有其他缓冲来源时，模型输入与最终候选还会限制到显式来源。

自动候选开启也不等于自动生效。`pending` 不进入 Prompt；只有另行开启自动生效、完整原文直接支持且低风险无冲突的候选才可能 `active`。冲突、更正、高影响或不可核验内容继续走原审核。撤销和激活都复用用户锁、最新范围和版本校验。

启用后的召回没有改回全量扫描：继续使用 PostgreSQL 关键词/向量有界候选、当前权限与撤销复核、Query-aware 选择，最终还受上下文预算限制。此次触发优化不代表记忆检索算法或容量指标重新测量过。

## 7. 以后再考虑什么

本轮实现的是报告中确定性事件与有界批次这层。规则对同义表达仍不可能全覆盖；12 个构造场景与本次在线验收不足以证明真实精度。后续积累实际漏触发/误触发样本，扩成独立顺序对话集。只有确认规则盲区有明显业务影响后，再考虑后台批量语义重要性判断；周期去重整合与经验记忆另行设计，不能由模型直接删改用户记忆。
