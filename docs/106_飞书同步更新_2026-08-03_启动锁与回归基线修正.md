# 2026-08-03 启动 schema lock 与回归基线修正

在代码审查收尾后又补了一项可靠性优化：PostgreSQL 多实例启动时，所有进程先通过独立连接获取同一个 advisory lock，再执行 schema 检查和运行时 DDL，避免并发启动基于同一份旧 metadata 重复 `ALTER TABLE`。异常路径也会释放该锁；SQLite 和其它开发后端保持 no-op。

新增 2 项启动锁行为测试后，后端完整回归基线为 `333 tests`，结果 `OK (skipped=3)`。3 项跳过均为未设置 `TEST_POSTGRES_URL` 的 PostgreSQL/pgvector 集成测试；`compileall`、默认 Tool manifest JSON 校验和 `git diff --check` 通过。

剩余边界：这仍不是完整版本化 migration；正式生产部署仍建议迁移到 Alembic，并保留真实 PostgreSQL 多进程集成测试。
