# Chat 工具图原生结构化状态

上次改造已去掉独立的 Planner 快照，但 LangGraph 状态仍把计划、预算和证据序列化成一个 `tool_state` 字符串。一个字段变化就要整块写入，检查点也无法直接显示变化来自哪类状态。

现在 `sync_tool_graph.py` 通过 `StateGraph` 声明 `checkpoint_policy`、`budget_state`、`plan_state`、`progress_state` 和 `evidence_state`，每个节点只返回有变化的通道，由已有 PostgreSQL Saver 持久化。`chat_tool_snapshot.py` 仍对白名单类型进行编解码、脱敏和限制大小；大段证据优先引用已提交的 Artifact。`chat_tool_runtime.py` 在接管时校验租约、原始用户请求、工具和文件版本，再按原预算与节点位置恢复。`SyncToolRun` 仍是单次 Worker 执行期间供 Planner、Workflow 和 Executor 使用的内存对象，没有独立的持久化副本，也不作为跨进程恢复依据。

升级不用新增数据库表或批量重写历史记录。未完成的旧任务仍能读取同一图线程里的 `tool_state`，下一个成功保存的节点写入结构化字段并清空当前状态中的旧字段；已经结束的旧任务仍可读取证据。新格式缺字段时拒绝恢复，不拿旧字符串回退执行。旧版本 Worker 不能读取新格式，部署时应避免混用。Durable 工具、文件审批和最终模型回答的恢复语义不变。

验证使用隔离 PostgreSQL、独立子进程退出、固定 Planner 和真实文件工具，覆盖旧/新格式的计划落库后接管、已提交结果复用、失效租约拒绝和产物篡改拒绝。未重跑在线模型或浏览器。
