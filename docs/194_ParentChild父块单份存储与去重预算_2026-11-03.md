# Parent-Child父块单份存储、去重与预算修复

2026-11-03。确认原实现存在三个问题：`split_parent_child()`把完整parent_content放到每个Child metadata；KnowledgeContextService按Child取前max_context_chunks并展开，同Parent无去重；大父文占满预算可挤掉后续证据。答案评测组装也有同类重复。

## 修复链路

索引仍以Child检索与Embedding，不改变其正文、ID、向量或排名。同用户/知识库/文档/generation内，父文只由首Child保存一次，其余Child以parent_chunk_index引用该锚点。查询在最终检索/重排后批量读取同作用域锚点，恢复运行时父文，不依赖可能已更新的解析文件。复用Chunk表，没有另建父块表；不是所有Child的metadata都不含父文，而是每Parent只存一份。

上下文先按用户/库/文档/generation/Parent归并，再限制注入块数；保留排名最高Child为代表，matched_child_ids记录全部命中Child以供溯源。原始候选和Child级检索评分不合并改写。没有可用父文时回退Child，不把未知父块合并。

父块展开时按剩余证据数分配字符空间，过长则围绕最佳命中Child取窗，不只截父文开头。单库与跨库合并都控制预算；来源显示正文与RAG层实际注入相符，parent_content/context_content不重复塞进来源和日志metadata。之后Chat全局Token预算仍可能继续裁剪，此处selected不等于最终模型一定读取。

答案评测证据复用父块去重与命中区域预算。matched_child_ids只是溯源，不证明全部兄弟Child全文已注入，不据此虚增Gold召回/引用正确率。普通非Parent模式不采用父块平均分配。Embedding、BM25、RRF和Rerank逻辑未改；本次未重跑固定百题或修改历史报告，不宣称原指标提高。

## 旧数据与边界

旧重复parent_content仍能读取，并即时应用注入去重/预算。新索引和重建自动单份保存，不需要结构迁移。提供`backend/scripts/compact_parent_metadata.py --user-email <账号>`默认预览，显式`--apply`才修改旧metadata；单事务锁定指定用户块，按版本分组，父文冲突的组跳过。Child/Embedding/Generation不变，重复执行无变化。大量旧块整理时仍需评估事务时长，不能把一次性脚本说成在线无成本迁移。

本轮只读检查固定账号，parent_groups=0，无旧Parent-Child块需要压缩，未重建或改写论文库/中文库。脚本用合成旧数据验证了预览、压缩、幂等、冲突跳过。其他用户如有旧块须按明确账号处理，不能宣称全库历史磁盘数据均已整理。
