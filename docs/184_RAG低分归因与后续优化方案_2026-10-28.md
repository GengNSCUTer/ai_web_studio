# RAG 低分归因与后续优化方案

日期：2026-10-28

## 已完成的分阶段诊断

新增只读诊断脚本 `backend/scripts/diagnose_rag_stages.py`，依次记录 Vector、BM25、RRF 融合、Rerank 返回和最终阈值过滤结果，不修改知识库或评测标签。

### 论文库

论文库 90 题、200 个目标 Chunk，使用现有 Hybrid + Rerank 配置追踪到：

| 阶段 | 找到的目标 Chunk |
|---|---:|
| Vector | 154/200 |
| BM25 | 53/200 |
| Vector/BM25 并集 | 157/200 |
| Rerank 返回前 | 121/200 |
| 最终返回 | 120/200 |

因此有 43 个目标块没有进入初始并集，属于召回问题；36 个已经进入融合池的目标块没有进入最终精排前六，属于候选排序和最终数量限制共同造成的损失；只有 1 个目标块是阈值过滤造成的。后者不是 ANN 或数据库速度问题。

论文集中的 10 道最终未命中题，既包含初始召回失败，也包含精排没有保留目标块的情况。部分题把“同一主题的相关块”全部标成必需证据，可能高估了目标数量；例如 Adaptive-RAG 的分类器问题同时绑定了训练/推理块和评测指标块，后者不一定是回答所必需的证据。

### 中文后端资料库

中文库的 14 道可回答题中，Vector/BM25 融合已经覆盖 15/16 个目标块；在精排阶段下降到 12/16，最终为 11/16。最明显的异常是 Python 教程主题题：目标块已经在融合池，但 Rerank 分数约为 0.064、0.049、0.041，而知识库的 `score_threshold=0.15` 直接把它们全部过滤掉。

这说明当前把向量/融合分数阈值直接复用于 Rerank 分数是不安全的。不同模型的分数没有同一标定范围；Rerank 应优先按 `top_n` 返回，或使用单独经过校准的 Rerank 阈值。

## 评测集问题

### 中文题集

- 两道无答案题仍然绑定了目标 Chunk，导致 Hit、Recall 和引用指标被污染。无答案题应当没有 Ground-Truth Chunk，并单独统计拒答准确率、误检率和证据不足识别率。
- “序列数据结构在哪里学习”绑定的是目录 Chunk，真正支持答案的是正文第 2.4 节 Chunk。答案正确但被当前 Gold Set 判为未命中。
- Redisson 题绑定的两个早期入门块不足以覆盖可重入、重试、WatchDog 和主从一致性，真正相关内容在后续块中。它需要重新标注为充分证据，而不是继续扩大目标数量。
- 目前多证据题数量和报告曾经不一致，必须从 JSON 自动计算，不能手填。

### 论文题集

90 题是模型辅助起草、独立模型复核的固定集合，不等同于人工穷尽标注。每题只标了 2—3 个目标块，但一篇论文可能存在多个同样可接受的证据段，因此 Context Precision 会被压低，不能直接解释为“其余返回块都无用”。后续需要把证据分为“回答必需”“可接受补充”“无关”三档，并保存支持范围或句子级证据。

历史指标不删除，也不回写成优化后的新分数；应创建 v2 Gold Set，在新题集上单独报告。

## 解析和索引问题

1. PPTX 初次转 Markdown 时按文件名字符串排序，顺序变成 `1、10、100、11…`，破坏了幻灯片上下文。这是导入流程错误，Redis 文档应按数字页码重新提取和重建索引。
2. PDF 文本中存在 `Re mote Di ctionary S erver` 等 OCR/字体空格，影响 BM25 和关键词命中。显示正文和检索文本应分开：保留原文用于引用，同时生成经过安全空格归一化的检索字段。
3. 当前中文库使用通用 900 字符切块，目录、章节说明、代码和正文边界没有完全保留。应在切块时保存标题路径、页码/幻灯片号和章节范围，并评估 Parent-Child 或结构化切块。

## 后续实施顺序

### 1. 先修评测和 Rerank 收口

- Gold Set v2 支持 `answerable=false` 且没有目标 Chunk；检索指标只在可回答题上计算，另报负例误检率。
- 重新人工复核中文题和论文低分题，补充可接受证据和必需证据，不根据当前命中结果临时改标签。
- 分离向量阈值与 Rerank 阈值；默认 Rerank 只按 `top_n` 返回，空结果只在 Provider 没有返回候选时发生。
- 增加测试：目标在融合池但精排分数低、无答案题、精排失败、阈值过滤和重复引用。

### 2. 修复资料解析和结构化切块

- 数字顺序提取 PPTX 幻灯片并重建中文 Redis 文档。
- 对 OCR 空格做可逆、仅作用于检索字段的归一化，不修改证据原文。
- 给 Chunk 保存章节路径、页码/幻灯片号和父块关系；比较通用切块与 Parent-Child。

### 3. 提升初始召回

- 在固定开发集上比较原 Query、已有指代改写、中文术语扩展和中英文术语扩展；扩展失败时回退原 Query。
- 对论文库重点增加论文名、章节名、方法名和缩写的 metadata/标题检索。
- 在有稳定收益后，再考虑 Contextual Retrieval：为每个 Chunk 生成简短的文档/章节上下文，同时用于 Embedding 和 BM25。Anthropic 的官方报告将这种做法称为 Contextual Embeddings 与 Contextual BM25，并报告在其数据上降低失败检索，但该收益不能直接套用到本项目。
- Hybrid 权重和 RRF 参数只用开发集选择，留出题不参与调参。

### 4. 改进最终答案和指标

- 证据展示保留完整支持段落，引用使用句子级来源绑定；避免模型引用相邻但不支持结论的块。
- 分开报告可回答题和无答案题：Faithfulness、Relevancy、Citation Correctness、Citation Validity，以及 Abstention Precision/Recall。
- 同时保留检索层指标和答案层指标；不能用高 Faithfulness 掩盖召回遗漏，也不能用低 Exact-Chunk Precision 直接断言上下文无用。

## 业界可借鉴的方法

- Microsoft 的 RAG 检索指导把 Query Translation 分为扩展、分解、重写和 HyDE，并建议使用重排处理初始召回无法判断的相关性；本项目已有上下文指代改写，下一步应补受控术语扩展，而不是重复做一套重写。
- Anthropic 的 Contextual Retrieval 是在 Chunk 前增加文档相关上下文，同时建立 Contextual Embedding 和 BM25 索引；其官方结果显示结合重排能进一步减少失败检索，但需要额外离线模型成本。
- BGE 官方文档说明 `bge-reranker-v2-m3` 是跨语言 Cross-Encoder，精度高于单纯向量相似度但推理成本更高；因此候选池和 Rerank 分数阈值要分开治理。
- Microsoft Foundry 的评测建议把 Document Retrieval、Groundedness、Relevance 和 Response Completeness 分开，正好对应本项目需要区分的检索、答案忠实度、回答相关性和答案覆盖度。
