# 会话消息序号与数据库连接预算

2026-11-26 核对常驻库时，迁移版本为 `20261118_01`，消息有 366 条，其中 318 条序号为空，非空序号没有重复。配置的 `max_connections` 为 100，读取 `pg_stat_activity` 当时有 16 个客户端连接。这些是现场快照，无法代表历史峰值。

## 并发写入和旧消息

正常 Chat、Durable 和文档落库通过 `MessageRepository` 分配序号。原先已经在同一事务内锁住会话行，再取该会话最大序号。现在分配值还高于当前记忆扫描和提取游标，避免删除会话尾部后，新消息复用一个已经处理过的序号。

`20261126_01` 在 PostgreSQL 加入 `UNIQUE(conversation_id, sequence)`。历史空值允许保留。跨会话可以使用同一个序号。升级发现重复的非空序号会失败并回滚，保留原记录，便于核对摘要边界和记忆游标。首次为历史空序号补号时，已推进游标的会话只补空值。无游标且需要重新排号的会话，在同一事务中先释放需要移动的序号，再逐条写入正确位置。

## 连接池

`database_pool.py` 统一解析角色默认值和环境覆盖，`supervisord.conf` 为 API 和 Worker 指定角色。同步 SQLAlchemy、诊断用 AsyncSession、LangGraph 检查点及审批池分别配置。单进程每角色的常规业务池默认上限合计 42，启用沙箱后为 44。限额表、调参优先级及活动连接查询见[部署说明](../deploy/README.md#数据库连接预算)。

启用配额的订阅和上传路径会先结束鉴权查询的只读事务，再申请业务额度。调整池容量后，同一请求即使在只有一个连接的池中也能走通认证、任务读取、事件回放和额度归还。
