# 上线准备第二批：资源保护、迁移、备份与自动回归

更新于 2026-10-17。实施入口：[三批计划](../plan/infrastructure-production-readiness-v1.md)。本批完成 TASK-007 至 TASK-010；Durable 入口产品化和真实用户容量证据仍属于第三批。

## 这批解决什么问题

第一批解决“服务能否干净安装、依赖是否可发现、上传解析是否拖住事件循环”。第二批解决四个上线前必须回答的问题：一个用户同时发起很多 Chat、上传和知识库任务时是否有边界；数据库结构如何升级；PostgreSQL、上传文件和本地 BM25/索引文件能否成套恢复；回归测试是否可以在没有收费 API 的 CI 中重复执行。

## 资源保护

`backend/app/services/resource_quota_service.py` 使用 PostgreSQL 用户级短租约。Chat 路由在创建用户/assistant 占位消息之前申请 `chat` 名额，流式响应结束、失败或客户端取消时释放；租约有心跳和过期时间，进程崩溃后不会永久占用。上传在异步读取完整批次后按实际字节数预留容量，已有文件和其他有效租约都会计入；解析或写入失败时沿用原有整批清理。

知识库 Job 在同一个数据库事务中先取得用户 advisory lock、检查 `pending/running` 数量，再写 `KnowledgeDocument + KnowledgeJob + OutboxEvent`。超限直接返回 429，事务回滚，不能只留下文档、只留下 Job 或只留下待投递事件。默认限制为 Chat 2、上传 2、待处理知识库 Job 20、用户上传存储 1GiB，可由环境变量调整。

## 版本化迁移

`backend/app/core/startup.py` 已从“启动时补表/补列”改为只读版本检查。`backend/migrations/versions/20261017_01_接管现有数据库结构.py` 冻结当前 39 张业务表作为首版基线，`20261017_02_规范约束与用户容量租约.py` 只新增资源租约表。`backend/app/core/migrations.py` 负责锁、版本检查和历史库收编；`backend/scripts/migrate_database.py` 是部署前唯一升级入口。

现有非空数据库升级必须先提供同库备份，再显式使用 `--adopt-legacy` 收编；如果表、列、索引或约束与首版基线不符，命令拒绝写入版本号。升级和 `alembic_version` 在同一 PostgreSQL 事务中处理，目标表冲突测试证明失败会回滚版本和本次 DDL。

## 成套备份与恢复

`deploy/data_backup.py` 会短暂停止本项目正在运行的 API、知识库、记忆和 Durable Worker，导出 PostgreSQL custom dump，并分别归档 `UPLOAD_DIR` 与 `KNOWLEDGE_INDEX_DIR`；不读取或打包 `.env`，备份目录权限为 700、文件为 600。恢复要求目标数据库和两个目标目录都是独立、未存在的路径，检查归档越界路径和符号链接后再恢复，禁止覆盖线上库。

真实备份目录为 `/disk2/gengnan/aiws-backups/20261017-batch2-current`。在隔离数据库恢复后执行迁移并验证：用户 13、知识库 Chunk 1,739、上传文件 521、BM25/索引文件 3，`alembic_version=20261017_02`，数据库查询可用。备份包含业务个人数据和加密凭据，恢复机器必须使用原 `SECRET_ENCRYPTION_KEY`；密钥本身不在备份中。

## 自动化回归

`.github/workflows/ci.yml` 将后端测试放在 PostgreSQL/pgvector 与 Redis 服务容器中，执行全量 unittest、编译检查和迁移检查；前端执行 `npm ci`、lint、build 和 Node 行为测试。Tavily、高德、在线模型等收费或不稳定 API 不自动进入 CI，继续用本地真实 smoke 脚本手动验证。

本机最终验证：后端 `707 tests OK`（包含真实 PostgreSQL/pgvector 集成），前端 lint/build 和 Node 测试通过，迁移 `check`、compileall、Shell 语法、`git diff --check`、`/health/ready` 和 `deploy/check_services.py` 均通过。

## 当前边界

本批没有把用户级限额当作压测容量数字，也没有实现高可用、WAL/PITR、跨主机对象存储或第三批 Durable 产品入口。后续若进入第三批，再补真实业务任务、受控容量探测和用户试用证据。
