## 当前流程

用户原问题＋已审核Skill完成条件 → TaskSpec → 原Planner/Executor/Workflow → 工具证据预算裁剪 → CompletionVerifier → Trace/诊断/最终回答约束。

TaskSpec只复用现有文件读取、Diff预览、修改审批、Skill required_tools声明；不调用额外模型，不接受外部正文生成要求，不增加权限。未知任务返回not_assessed；不因为HTTP成功就判为任务完成。

| 判定 | 本轮含义 |
| --- | --- |
| complete | 声明的工具证据齐全；不表示最终答案、报告章节或语义全部正确 |
| partial | 有证据，但缺必要工具证据，或预算/其他执行分支未完成 |
| clarify | 等待审批、澄清或依赖确认，不表示已经修改文件 |
| blocked | 无必要可用证据，或原任务动作/外发边界拒绝 |
| not_assessed | 受审核规则没有覆盖该自由任务，未验证完成程度 |

检查依据是实际保留的来源、empty_reason、质量状态、tool_key、文件/版本与真实审批记录，不读取资料中的“任务已完成”声明。只读Diff可以完成预览要求，不要求批准正式写入；正式修改的待审批记录仍为clarify。

结果明确标注assessment_scope=declared_tool_evidence、assessment_stage=after_tool_budget_before_final_prompt、answer_semantics_verified=false。本次检查发生在工具预算之后、最终多层Prompt治理之前，不等于最终注入清单或生成后引用核验；下一步需在最终来源清单上补做全局判定。

未满足时ToolRouteRun以既有partial状态保存；不改Message成功/失败语义、不新增数据库状态。最终回答增加“只答已核实部分、说明缺口”的约束。原重规划、DAG、审批、租约与权限检查保持。本轮不自动构造参数、重试或放行依赖。
