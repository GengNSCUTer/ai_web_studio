# 阶段 4.3A：通用 Evidence Projection Profile

更新时间：2026-09-20  
状态：已完成阶段 4.3A；阶段 4 整体未完成。

## 本步解决的问题

阶段 4.2 已经验证了“只把极短的 Tavily canonical content 给下一轮 Planner”这条安全链路，但资格判断直接绑定 provider、source type 和 tool key，且结构化 facts 仍由代码中的固定字段集合决定。这样的实现适合安全样板，不适合作为后续 Tool/Skill/MCP 的通用扩展接口。

阶段 4.3A 把可见性改成 Tool Definition 上的声明式 `evidence_projection` Profile。Profile 只决定已经通过 Adapter、Mapper 和质量门的 evidence 如何投影给下一轮 Planner，不授予执行权限，也不替代 Candidate Selector、Schema、ACL、Approval 或 Executor。

## Profile 模式

```text
none             默认关闭；只保留平台身份字段 call_id/tool_key
facts_only       只按白名单 JSON Pointer 暴露结构化标量 facts
bounded_excerpt  按 canonical content 路径暴露有界不可信摘录
review_required  只允许进入用户审阅路径，不作为下一轮 Planner 的普通资料
```

新 Tool 未声明 Profile 时自动归一化为 `none`。Profile 不能读取 `display_text`、标题、URL 或任意嵌套对象；`fact_paths` 和 `content_paths` 只能指向经过 Mapper 产生的 `/metadata/...` 标量字段，其中正文摘录目前进一步限定为 `/metadata/raw/...`。

`bounded_excerpt` 的预算仍由 Profile 声明，包括允许的 source type、最大来源数、单条字符数和本轮总字符数。Tavily 当前保持原有保守配置：`web` 类型、最多 2 条、每条 240 字符、总计 480 字符。扩大正文信息量留到后续预算治理小步，不在本阶段顺手放宽。

## 适配新 Tool 的方式

固定 Tavily 现在只是一个 manifest Profile，不再在投影器里写 Tavily 特判。天气、地理编码、路线、距离、POI、工作区搜索和文件读取已经使用 `facts_only` Profile 声明各自的 canonical 字段路径；没有 Profile 的 Artifact 和其它 Tool 默认保持关闭。

动态 MCP 的接入合同也可以记录 Profile，并将 Profile 纳入合同 digest。为了避免本阶段扩大远程正文权限，4.3A 对动态 MCP 只允许 `none/facts_only/review_required`，明确拒绝 `bounded_excerpt`；动态 MCP 的正文摘录需要等 4.3B 把 fixture、Mapper 输出和投影结果一起验证后再开放。

## 关键安全收口

Tool Executor 现在会权威覆盖 source metadata 中的 `call_id`、`tool_key`、`tool_display_name` 和 `source_index`。Adapter 或远程 MCP 不能通过返回同名字段伪装成另一个已经获得正文投影权限的 Tool。

投影器在运行时还会重新确认：source 的 `tool_key` 能在当前 Catalog 找到、Provider 与 Definition 一致、source type 在 Profile 白名单中、Profile 本身仍可校验。任一条件失败，投影关闭或返回受限状态，不回退到自由文本。

## 实现文件与测试

- `backend/app/services/tools/evidence_projection_profile.py`：Profile 版本、模式、JSON Pointer 和预算校验；未知字段、越界预算和非 canonical 路径失败关闭。
- `backend/app/services/tools/observation_projection.py`：根据 Catalog Definition 投影受限 facts/excerpt，并复核 Tool 身份和 Profile。
- `backend/app/services/tools/catalog.py`、`schemas.py`：加载和保存 Tool Definition 的 Profile。
- `backend/app/services/tools/onboarding.py`：动态 MCP 合同记录 Profile，旧合同摘要保持兼容，4.3A 禁止动态 MCP 正文摘录。
- `backend/app/services/tools/executor.py`：覆盖 Adapter 提供的身份 metadata，防止结果伪装。
- `backend/app/tool_manifests/default_tools.json`：Tavily、地图、天气和工作区只读 Tool 的 Profile 声明。

新增和更新回归覆盖：默认关闭、新 Profile 规范化、非法字段/路径/预算、动态 MCP digest 绑定、动态 MCP 正文摘录拒绝、Tavily 通过 Profile 投影、地图/文件 facts 投影，以及 Adapter 伪造 Tool 身份被执行器覆盖。

本阶段不声称已经解决“长摘录如何动态分配 Token”。当前目标只是把资格和适配层从 Provider 特判抽象出来，并保证新 Tool 默认不会静默扩大 Planner 可见内容。
