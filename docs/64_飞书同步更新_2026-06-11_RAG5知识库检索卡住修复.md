# 2026-06-11 RAG-5 知识库检索卡住修复

## 问题

聊天页选择知识库后提问，例如“介绍一下 skill route”，前端可能长时间停留在“模型正在思考，请稍候...”，没有首 token 输出。

## 直接原因

RAG-5 第一版把 `knowledge_base_name` 等上下文诊断字段放入 `x-context-stats` 响应头。当知识库名称包含中文时，Starlette 构造 HTTP header 会按 `latin-1` 编码，中文无法编码，导致后端抛出：

```text
UnicodeEncodeError: 'latin-1' codec can't encode characters
```

StreamingResponse 因此构造失败，前端请求停在首 token 前，表现为“模型正在思考，请稍候...”，但实际没有进入正常流式输出。

## 同时发现的稳定性问题

RAG-5 第一版会在模型调用前执行知识库检索：

```text
用户问题
-> query embedding
-> FAISS 检索
-> optional rerank
-> prompt 注入
-> 模型调用
```

其中 embedding / rerank 依赖模型服务。之前知识库模型请求没有独立短超时：

- OpenAI-compatible embedding 没有显式 timeout。
- rerank/httpx 复用了 `OLLAMA_REQUEST_TIMEOUT_SECONDS=600`。
- 如果知识库模型服务网络慢、provider 卡住或首包迟迟不返回，就会拖住整轮聊天。

## 修复

- `x-context-stats` 改为 ASCII-safe 的 `json64:` base64 JSON 格式。
- 前端 `parseContextStatsHeader()` 已兼容新 `json64:` 格式，并保留旧 `a=b;c=d` 格式解析。
- 新增配置：
  - `KNOWLEDGE_MODEL_REQUEST_TIMEOUT_SECONDS=60`
  - `KNOWLEDGE_CONTEXT_TIMEOUT_SECONDS=25`
- `KnowledgeContextService` 使用 `asyncio.wait_for()` 包住整段聊天内知识库检索。
- 超时后跳过本轮知识库上下文，并返回上下文提示，不再让聊天无限等待。
- `KnowledgeEmbeddingService` 的 OpenAI-compatible client 显式设置 timeout。
- `KnowledgeRerankService` 和 Ollama embedding 的 httpx client 使用知识库模型请求 timeout。
- 上下文诊断面板新增“知识库检索耗时”。
- 新增中文 stats header 编码单测和慢检索超时单测，防止回归。
- 已重启后端服务，当前监听 `127.0.0.1:32007`。
