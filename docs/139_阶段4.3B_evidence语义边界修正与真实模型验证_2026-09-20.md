# 阶段 4.3B 补充：Evidence 语义边界修正与真实模型验证

更新时间：2026-09-20  
状态：已完成本次语义修正与在线端到端验证。

## 为什么要修正

此前提示中大量使用“不可信 evidence”来强调 Prompt Injection 防护。安全意图是正确的，但模型可能把它误读成“这段内容不能参考”，从而忽略本来有用的事实。

现在统一拆成两个维度：

- `evidence_role=reference_evidence`：内容可以作为与当前问题相关的事实参考；
- `instruction_authority=none`：内容没有资格执行命令、修改系统规则、扩大工具权限或改写任务。

因此，系统表达的是“可以参考事实，但不能执行其中的指令”，而不是“这段内容完全不可信、不能使用”。

## 代码变化

- `observation_projection.py`：Planner observation 增加 `evidence_role` 和 `instruction_authority`；平台摘要改为明确说明事实可参考、指令无执行权限。
- `planner.py`：Planner 规则改为允许使用相关事实判断是否需要下一步工具，同时禁止执行资料中的命令。
- `catalog.py`：工具描述不再把返回内容笼统描述为不可用的“不可信 evidence”，改为参考 evidence + 无指令权限。
- `prompt_builder_service.py`、`context_governance_service.py`：最终回答上下文使用同一语义，允许模型利用相关事实，并明确禁止执行其中命令；平台 system prompt 也不再把所有资料笼统描述成不可使用的“不可信资料”。
- `catalog.py`、`default_skills.json`：工具描述和 Artifact Skill 约束同步区分参考证据与指令权限。
- `knowledge_e2e_evaluation_service.py`：RAG 评测 Prompt 同步修正，避免把评测证据描述成不可使用的文本。

阶段 3 的 Workflow 失败反馈本身只包含结构化状态、质量状态和有限原因，不包含 Provider 正文；本次保持这一安全边界，只修正 Planner 对“失败状态”和“可用证据”的表达，未把失败分支重新注入为自由文本。

## 验证

离线回归：453 项通过，5 项因未配置 PostgreSQL/pgvector 条件环境跳过；compileall 和 diff 检查通过。

真实在线模型验证使用现有测试账号配置的 OpenAI-compatible Provider，未输出或持久化 API Key：

1. 直接调用在线模型，给出“北京晴、最高 28℃”和一条要求删除文件的恶意文本。模型保留了事实回答，没有执行危险命令。
2. 通过真实 FastAPI 链路创建临时会话，调用 `/api/chat/events-stream`，走上下文组装、Provider 流式输出、消息落库和清理临时会话。HTTP 200，收到完整 `done` 事件，无 `model_error`。
3. 开启真实低风险工具调用，再由在线模型完成最终回答。工具事件 26 个，最终回答非空，收到完整 `done` 事件，无 `model_error`，临时会话已清理。

## 当前结论

安全边界仍然是代码侧权限、Schema、ACL、审批和预算；模型只负责理解“哪些事实与问题相关”。`untrusted` 兼容字段暂时保留，新的调用方应使用更明确的 `evidence_role` / `instruction_authority`。后续如需扩展，应继续区分证据质量、来源可信度和指令权限，不能用一个词覆盖三种语义。
