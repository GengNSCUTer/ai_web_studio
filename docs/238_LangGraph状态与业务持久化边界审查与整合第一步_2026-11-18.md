# LangGraph 状态与业务持久化：Chat 工具图收敛

2026-11-18。项目依赖锁定 LangGraph 1.2.20 与 PostgreSQL Checkpointer 3.2.0。本次将普通 Chat 工具循环的恢复收敛到原生检查点，退役旧表及旧图版本，不改前端协议、工具权限或模型配置。

## Chat 工具图：从两份记录到一个恢复来源

原来图检查点只记少量节点状态，真正的计划、观察和预算由 `ChatToolPersistence.save()` 另写 `AgentCheckpoint`，接管时先读业务快照再把节点塞回图。现在新运行不再新增这份业务快照，也不做双写版本对齐：原生 PostgreSQL Checkpointer 是图执行状态唯一来源，包含预算、计划、观察和工具产物引用。下一节点由框架决定；未完成的运行传入 `None` 续跑，完成的运行只复核并重新组装回答证据。

`chat_run_service.py` 仍以短事务创建和领取 ChatRun。`chat_run_worker.py` 将租约和运行范围交给 `sync_tool_graph.py`。图先用 `reserve` 保存本轮预算与绝对截止时间，再调用 Planner；工具调用将执行身份、真实尝试和正式结果写到业务表，原生图随后推进。`chat_tool_runtime.py` 只做有界编码、产物引用的还原、权限/版本复核，以及业务步骤和终态的事务提交；`chat_tool_checkpoint.py` 继续在写入原生 Checkpoint/Pending Writes 的同一事务内检查父租约和 generation。

`ChatToolSnapshotCodec` 不再写另一套检查点，它现在是图状态的业务编解码：复用已有脱敏、大小限制和同用户、同 Run、已提交产物引用校验。已提交工具结果不放进另一个可供下载的框架缓存；业务产物仍以原 `Artifact` 为准。保存图状态前的 Planner 请求如果尚未写下结果，接管可能重发该轮模型请求，仍使用原截止时间。最终答案不续接半截 token，继续使用 ChatRun 原有的有限重生成、SSE 和正文归档。

迁移 `20261118_01` 要求先停新请求并排空 Chat，有排队、运行或正在取消的任务时直接拒绝。迁移删除 Chat 旧快照和 v1 图线程；v2 图状态、已完成回答、实际工具步骤和产物均保留。旧表中其他任务的业务事件迁至 `agent_run_audit_events`，只保留事件详情和序号，不再存恢复用的计划和预算。新代码没有 v1 回退路径；退役数据无法从新表还原，回退须使用升级前完整备份。

## 其余链路的源码边界

| 链路 | 框架负责 | 业务事实及未迁移项 |
| --- | --- | --- |
| ChatRun | 工具循环节点、状态、Pending Writes 恢复 | 用户/消息、SSE、任务配额、取消、租约、已提交调用结果和审批；不持久化最终生成的模型流 |
| Durable Tool | 每个固定步骤的预检、执行/提交、核对和原生检查点 | `AgentOutboxEvent` 领取、Step 尝试、幂等、DLQ 与 Artifact；详情 API 返回 `latest_audit_event`，JSONL 使用 `run.transition`，不从检查点读取模型输入或工具正文 |
| Document | 同一 PG Saver 和逐 Step 图，按取证、草稿、导出、交付推进 | 用户可下载产物、可选审批保存及版本核对；阶段业务事件仍可审计。草稿生成未提交产物前崩溃，不保证不重新请求模型 |
| Approval | `interrupt` 与 `Command(resume=...)` | 已认证用户决定、一次性审批、FileRevision CAS 和已生效变更；审计状态不等于图控制状态 |

工具业务记录与图状态并非互相覆盖：进程在结果提交后、图节点完成前退出时，LangGraph 会重进该节点，Executor 根据正式 Step/Artifact 复核后复用结果。把外部写包装成 Task 不能解决远端提交与本地记录之间的空窗，也不开放新的自动写入或工具权限。

业务 Step、Artifact 和审计记录分别为调用身份与尝试次数、权限受控的正式产物、产品可见的状态变更而保留。`AgentRun.planner_state_json` 在非 Chat 链路仍保存冻结的执行策略和工具版本等业务事实，不作为原生图的替代恢复来源。不为每个框架内部节点强制新增业务 Step。
