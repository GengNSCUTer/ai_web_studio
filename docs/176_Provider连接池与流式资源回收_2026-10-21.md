# Provider 连接池与流式资源回收

2026-10-21。解决的问题是：此前每次 Chat、Planner 或摘要调用都创建并关闭客户端，客户端内部虽然支持 HTTP 连接池，但难以跨请求复用。本次让 Web 服务在同一事件循环内保留有限数量的客户端，不修改 Tool 权限、模型请求参数或业务状态机。

## 调用链与实现文件

`FastAPI lifespan 注册池 → ChatProviderService 按配置借客户端 → SDK/HTTPX 发请求 → 返回流式事件 → 关闭本次响应并归还借用 → 后续请求复用 → lifespan 退出统一关闭`。

| 文件 | 具体职责 |
| --- | --- |
| `backend/app/services/provider_client_pool.py` | 按协议、Provider、Base URL、API Key 指纹分组；借用计数、空闲淘汰、有界等待与关闭 |
| `backend/app/services/chat_provider_service.py` | OpenAI-compatible/vLLM 与 Anthropic 调用适配；流提前结束时关闭响应，保持共享客户端可用 |
| `backend/app/services/ollama_service.py` | 复用同一池接口，保留原请求超时；本次没有启动本地模型 |
| `backend/app/main.py` | lifespan 注册当前循环的池；退出时关闭 Provider 池及 Chat 数据库池 |
| `backend/app/core/config.py`、`backend/.env.example` | 非敏感容量与超时默认值；实际 `.env` 未修改 |
| `backend/tests/test_provider_client_pool.py` | 16 项资源隔离与真实本地 TCP 测试 |
| `backend/tests/test_chat_provider_service.py` | 原有流式事件、缓存、客户端回收回归，模拟流支持 SDK 的 close 方法 |
| `scripts/provider_pool_real_smoke.py` | 浏览器连续两轮真实在线 Chat，校验最终回答和 PostgreSQL done 状态，清理自建临时会话/项目 |

## 复用与隔离规则

相同协议、Provider、地址和凭据可以共享客户端；不同 API Key、地址或协议不能共享。模型名、温度、消息等仍逐请求传入，不写入共享客户端。密钥仅以指纹参与内部查找，不记录日志或导出；路径保留大小写，不能把 `/API` 和 `/api` 错认为同一地址。

池属于单个 Web 进程的事件循环，没有跨进程、跨循环复用。没有注册 Web lifespan 的独立 Worker/脚本仍逐请求创建关闭客户端，避免已有 `asyncio.run` 生命周期不兼容。Web 内部通过本适配器发出的 Planner、摘要等请求同样受益；Embedding/Rerank、Tool 专用 HTTP 客户端不在此次改造范围内。

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `PROVIDER_CLIENT_POOL_MAX_SIZE` | 32 | 每个事件循环最多保留的客户端配置数 |
| `PROVIDER_CLIENT_POOL_WAIT_SECONDS` | 10 秒 | 配置池满且全部忙碌时的最长等待 |
| `PROVIDER_CLIENT_IDLE_SECONDS` | 300 秒 | 闲置配置在下次借用时清理，不是定时扫描 |
| `PROVIDER_HTTP_MAX_CONNECTIONS` | 20 | 每个客户端的 HTTP 连接上限 |
| `PROVIDER_HTTP_MAX_KEEPALIVE_CONNECTIONS` | 10 | 每个客户端的空闲保活连接上限 |

HTTP 空闲连接保活默认 30 秒。配置改变后按新键借用，旧配置只在空闲时淘汰，不中断在途请求；满池优先淘汰空闲 LRU。池容量不等于每秒请求速率，也不等于全站 Chat 并发限额；多进程会有多个池。

## 流式取消和重试

流结束或取消时关闭当前 SDK 响应流，归还客户端借用；不能关闭共享客户端，否则同配置其他对话也会断开。委托的异步生成器使用 `aclosing`，取消作用域中对资源归还做清理保护。应用退出在请求排空后关闭池；池关闭也会唤醒等待者并拒绝新借用。

没有新增 Provider 重试循环。安装的 `openai==2.11.0` 默认最多额外重试两次，一次 SDK 调用最多三次 HTTP 尝试；已有客户端 timeout 和 Chat 首包/空闲/总时长限制保留。测试核实 429/503 可按 SDK 重试，400/401/403 不盲目重试。

“12 次”仅是两层重试相乘的假设：应用总尝试 4 次 × SDK 每次 3 次。原题若应用总尝试 3 次，应是 9 次，之前反馈改动了题目前提，已修正。当前主 Chat 没有这个外层循环；Durable 任务重试也不能直接当作主 Chat 外层重试。

流中途断开后，不悄悄重发整个问题并把新答案接在旧前缀后面。当前 Chat 保存已生成内容，异常标记 failed，取消标记 cancelled；显式重新生成建立新 generation。这里没有实现 token 断点续传。
