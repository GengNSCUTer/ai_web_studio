# 长期记忆触发：观测、标注、评测与低频语义复核

2026-11-11。在 [222 事件触发与持久缓冲](222_长期记忆事件触发与持久缓冲_2026-11-11.md)上完成五项改进；跨会话周期整合和程序经验库不属于本轮。

2026-11-12后续修复见[225](225_记忆混合输入与关闭边界修复_2026-11-12.md)：关闭总开关不再读取正文做触发分类或新增观测；旧memory_disabled观测仅为历史实现，不再新建。rules-v3识别问题之前的独立稳定陈述；原48例另存新报告Recall90%、保留两条漏例，下文85%和三条漏例保留为rules-v2当时结果，不覆盖旧报告或自然标注。

## 1. 用户看到的变化

普通问答照常回答，不为每轮增加一次价值判断。明确稳定陈述、记住、更正和忘记仍走原路径；规则难以确定的陈述保留在缓冲区。

设置中心 → 长期记忆新增 **低频语义复核缓冲信息**，默认关闭，不改变已有账号设置。开启记忆和自动候选，积累至少四条 buffer 来源后，才有机会交给当前模型复核；每用户 60 秒至多预留一次请求，每 Job 至多一次。超时 15 秒，输出最多 240 Token。没有独立模型配置，使用用户当前 Provider/模型；当前在线验收为 DeepSeek 官方 `deepseek-flash`，不加载 Ollama。

模型只能建议“值得提取、继续缓冲、跳过”。**值得提取不等于已记住**：仍须原提取器生成候选，核验原文、敏感信息、范围、重复、冲突和启用权限。这个开关没有开启自动生效。

## 2. 完整实现链路

`ChatRun 成功 → enqueue_after_turn → 规则分类并记录 → 有界缓冲 / 优先 Job → 独立记忆 Worker → buffer 可选语义复核 → 原提取/原文/冲突链 → 短事务提交 → activity 通知`

明确记住、更正、撤销不经过语义复核。只有 buffer 且满足开关、批次和频率条件的任务能调用它；后台执行不占用 Chat 浏览器连接。

| 语义结果/情况 | 实际处理 |
| --- | --- |
| `extract_now` | 继续原候选提取，不直接保存或启用事实 |
| 高置信度 `skip` | 复用原锁内来源/范围/开关/租约校验，以零候选收口并消费来源 |
| 高置信度 `buffer` | 本次 Job 结束，但保留来源和提取游标；同批次不忙循环，新输入到来再判断。缓冲满50条时回原提取链释放扫描空间，避免挡住新事实 |
| 低/中置信度、非法 JSON、超时或异常 | 走原提取器保守判断，不伪装为已保存 |
| 未开启、冷却中、少于四条 buffer | 不增加语义请求，维持原批次提取 |
| 来源编辑、范围变化、关闭记忆或失租约 | 原校验阻止旧结果消费来源或保存候选 |

网络前用短事务预留用户频率和 Job 调用标记，释放事务后请求模型。预留后、结果提交前崩溃，重领不再额外请求价值判断，而回到原提取；判断已提交时，恢复只做来源收口。标记是**应用预留次数**，不是 Provider 计费次数，SDK 重试和发送前崩溃需另行观测。

## 3. 决策记录与真实标注入口

新表 `memory_trigger_decisions` 记录来源消息 ID、观测回合、原有 source_digest、策略版本、动作、原因、上下文计数/布尔值、Job 关联、是否新建 Job，以及语义动作/置信度。不复制聊天正文或模型自由文本理由；原文仍留在 Message 表。

`outcome` 区分已排队、缓冲、跳过、自动候选关闭、已有任务和等待已有任务；旧总开关关闭记录仅为历史，自2026-11-12不再新建。同一来源版本/策略/观测回合不重复写；后续回合重看缓冲会留下新的上下文观测。消息/会话/项目删除会级联清理，Job 删除只清关联。ID 仍受访问控制保护，这不是匿名化方案。

当前用户只能读取和标注自己且会话仍处原范围的观测，不能影响另一用户：

```text
GET  /api/memories/trigger-decisions?conversation_id=...&limit=50
POST /api/memories/trigger-decisions/{decision_id}/label
```

```json
{"expected_action":"extract","review_reason":"missed_trigger"}
```

标签允许 `extract/revise/revoke/buffer/skip`，`extract` 在代码中规范为 `extract_now`。理由限定 `correct/missed_trigger/false_trigger/needs_context/wrong_action`，没有自由文本笔记，避免复制敏感原文。标注不改变 Job 或记忆权限；当前有接口与导出脚本，没有标注管理页面。

真实样本须由用户回看原会话后标注，不能把规则自己的判断当标准答案。服务器管理员可以导出指定拥有者的已标注观测：

```bash
PYTHONPATH=backend backend/.venv/bin/python scripts/export_memory_trigger_reviews.py \
  --user-id <拥有者ID> --output /tmp/reviewed-memory-triggers.json
PYTHONPATH=backend backend/.venv/bin/python scripts/evaluate_memory_trigger_policy.py \
  --observations /tmp/reviewed-memory-triggers.json --output /tmp/reviewed-memory-metrics.json
```

导出不读取 Message 正文，不含凭证；同来源版本/策略跨轮重复观测保留最新标签，最多一万条。它评价冻结的历史决策；没有原文不能重放新规则。新规则回放使用另一份人工脱敏题本。

## 4. 固定题本与评测定义

`backend/evals/memory_trigger_labeled_cases.json` 有 48 条人工正反例，覆盖五类动作、中英文、问题、临时要求、引文、敏感信息、控制请求、含糊决定和事实混合问题。包含用户给出的两类示例，但不能当作 48 条自然线上日志。后续真实误触发/漏触发经标注导出，和构造集分开评估。

本轮不围绕失败样例不断增加正则。引用处理使用通用引号剔除；近期“有决定”仅作上下文特征，不直接将另一条含糊消息升级为长期事实。

```bash
PYTHONPATH=backend backend/.venv/bin/python scripts/evaluate_memory_trigger_policy.py
```

| 指标 | 定义 | 本轮规则回放 |
| --- | --- | --- |
| Trigger Precision | 应立即触发且判为立即触发 / 判为立即触发 | 17/17，100% |
| Trigger Recall | 应立即触发且判为立即触发 / 应立即触发 | 17/20，85% |
| 误触发率 | 误判立即触发 / 标准应 buffer 或 skip | 0/28，0% |
| 漏触发率 | 未立即触发 / 标准应立即触发 | 3/20，15% |
| 五类动作准确率 | 五类完全一致 / 全部样例 | 45/48，93.75% |
| 额外语义调用 | 离线规则未调用模型 | 0 |

二分类正类为 `extract_now/revise/revoke`，`buffer/skip` 是非立即触发。把应提取判成更正，对二分类是命中，对五分类是错；不能混用 TP 定义。没有有效分母输出 null。真实观测的调用标记按 Job 去重，不能按多条来源重复累计。

完整结果在 `backend/evals/results/memory-trigger-policy-review-v1.json`，保留三条错误：混合“项目事实＋索引提问”被判 skip；“数据库已经定为……”和“固定项目评审日”被分到 buffer。后两类可以等待语义复核；被 skip 的混合句不会进入该分支，需以漏触发标注推动后续修正。本轮不宣称语义复核解决全部漏触发，也不将本表视为线上准确率。

## 5. 有界上下文与访问范围

每轮只查一次最近六条用户消息和当前用户/授权范围最多一百条有效记忆的数量，并批量读观测，避免每条来源各查一次数据库。范围复用召回过滤（合法全局记忆与本项目），不计其他项目旧来源；计数到一百是截顶，非精确总数。三十条来源测试限定 SELECT 不超过十四次。

后台语义输入包含当前会话最近四条用户上下文（最多四千字符）、已过滤范围的已有记忆摘要（最多两千字符）和本批来源，沿用发送前脱敏。上下文只帮助判断长期价值，不能授权跨用户/项目保存；候选仍必须通过本批原文证据核验。
