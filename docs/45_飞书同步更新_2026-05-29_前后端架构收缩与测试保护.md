## 后端本轮调整

### 1. 先补测试保护

新增：

- `backend/tests/test_chat_execution_service.py`

当前最小集成测试覆盖：

1. `prepare_chat_execution`
   - 新会话创建
   - 用户消息 / assistant streaming 占位消息创建
   - 附件上下文注入
   - Prompt 诊断产出

2. `prepare_existing_turn_execution`
   - 已有会话上下文构建
   - 外部工具开启时的来源与工具事件生成
   - `ToolRouteRun / ToolCallRun` 持久化

测试方式：

- SQLite 内存数据库
- fake external context
- 不依赖真实 PostgreSQL、Ollama、Tavily、高德

### 2. 再拆 service 边界

原来大量执行前逻辑都堆在 `ChatExecutionService`。

本轮拆分后：

- `chat_execution_models.py`
  - 放执行链路 dataclass
- `chat_turn_bootstrapper.py`
  - 负责会话/消息启动、turn 级覆盖、附件输入校验
- `chat_context_assembly_service.py`
  - 负责长期记忆、附件上下文、外部工具上下文、摘要刷新、Prompt 构建、诊断组装
- `chat_execution_service.py`
  - 收缩为门面服务，对 route 保持原有调用接口不变

这次拆分的重点不是“拆得越碎越好”，而是先把：

- turn 启动
- 上下文组装
- HTTP route

这三层边界分清楚。

## 当前结论

这一轮前后端结构治理已经可以阶段性收尾。

不建议继续为了“更干净”而无限拆分：

- 前端下一步如果继续拆，优先拆 `MessageList / MessageItem / MessageActions`
- 后端下一步如果继续拆，应该先补更多聊天链路测试，再决定是否拆 `ChatContextAssemblyService`

当前更合理的主线，是逐步回到：

- 知识库 / RAG
- 业务功能增强
- 产品体验优化

而不是继续纯做架构拆分。
