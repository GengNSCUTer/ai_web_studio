# 文档交付第一步：草稿生成与下载

后续更新：聊天的“保存为文档”已转入 [188 可恢复文档任务](188_可恢复文档任务与整体验收_2026-10-28.md)，后台生成/导出后由用户再次批准保存。本文记录的直接草稿接口仍存在，原 UI 立即创建并下载的描述是第一步历史实现，不作为当前聊天入口。

## 已实现

新增 `POST /api/projects/{project_id}/documents/draft`，支持把聊天整理结果保存为独立的 Markdown 或 DOCX 草稿；新增 `GET /api/projects/{project_id}/files/{file_id}/download` 下载接口。聊天助手消息操作栏已接入“保存为文档”，会把当前回答和来源列表交给草稿接口并打开下载地址。

入口和职责：

- `backend/app/schemas/document_delivery.py`：草稿输入、来源列表和下载响应结构。
- `backend/app/services/document_delivery_service.py`：校验工作区权限和文件名，原子写入用户工作区，生成 Markdown/DOCX，保留来源列表，并创建 `ProjectFile` 记录。
- `backend/app/api/routes/projects.py`：提供草稿创建和下载接口，下载前再次核验用户、项目、文件归属与真实路径。
- `backend/tests/test_document_delivery.py`：验证扩展名归一化、来源保留、DOCX 可打开和路径边界。
- `frontend/src/components/chat-message-list.tsx`：提供助手消息的文档交付入口。
- `frontend/src/components/chat-thread.tsx`：调用草稿接口、传递会话和来源信息、处理下载与错误提示。

保存结果是新建独立草稿，不覆盖已有文件；已有文件修改仍然必须走 PatchDraft、Approval 和 FileRevision CAS。Markdown 会在末尾增加“来源”段落，DOCX 会追加“来源”标题和列表。首版没有把第三方 URL 当作可信下载地址，也没有允许任意本机路径。
