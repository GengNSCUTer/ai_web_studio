# 阶段 3.4：多工具组合外层端到端验证

## 验证目标

本阶段验证的是“Chat 外层门面 → Planner → ToolWorkflow → Executor/质量门 → diagnostics”的组合行为，不把单个 Tool 成功误认为完整 Agent 成功。

## 自动化组合测试

`backend/tests/test_tool_integration.py` 现覆盖以下五类外层测试：

1. 单工具本地 MCP 完整成功链路：覆盖 Chat 外层、MCP 初始化、调用、质量门和 diagnostics。
2. 独立并发全成功：天气与搜索均返回有效结果，聚合为 `succeeded`，两类 evidence 均保留，并断言执行替身实际同时运行过两项调用。
3. 独立分支部分成功：天气分支返回质量不合格，搜索分支有效；最终聚合为 `partial`，有效搜索 evidence 保留，天气 evidence 不进入上下文。
4. 严格依赖阻断：路线依赖天气；天气质量失败后，路线生成 `dependency_quality_not_usable`/阻断结果，不进入 Executor，外层动作收口为 `clarify`。
5. 全路失败与等待确认：全路失败时可以在有限预算内受控重规划，但不会产生伪造 evidence，预算耗尽后稳定停止；确认前的预览进入 `waiting_approval`，依赖下游不执行，外层动作是 `clarify`。

除本地 MCP 协议链路外，这些组合测试均使用脱敏执行替身，不访问网络，目的是稳定验证失败传播、并发和证据边界；真实 Provider 仅通过独立烟测验证，避免把网络、限流或账户状态变成日常回归的失败来源。

## 真实低风险工具烟测

使用当前环境中已配置的低风险只读凭据，直接调用默认 Catalog 中的高德天气和 Tavily 搜索：

- 两个独立工具并发成功；返回 7 条受质量门保护的来源，聚合状态 `succeeded`，下一步 `stop`。
- 高德天气使用不存在的测试城市、Tavily 搜索保持有效；聚合状态为 `partial`，仅保留 2 条去重后的搜索来源，天气结果未进入上下文。
- 天气失败、路线严格依赖天气时，实际 Executor 只执行天气，路线未发出网络请求，外层收口为 `clarify`。
- 2026-09-20 再次通过真实 Chat API 运行双工具成功烟测：LLM 实际规划 `amap.maps.weather` 与 `web.tavily.search`，两项均成功并通过质量门，聚合 `succeeded`，第一轮以 `completed/stop` 收口，流式回答正常完成。

烟测输出仅保留来源数量、类型、聚合状态、动作和事件类型，不输出 API Key、完整 URL、Provider 原始正文或请求参数。

## 代码涉及

- `backend/tests/test_tool_integration.py`：外层组合回归和本地 MCP 链路测试。
- `backend/app/services/external_context_service.py`：多轮外层收口和安全观察。
- `backend/app/services/tools/workflow.py`：并发、质量门、严格依赖阻断和聚合状态。

另外，外层请求现在按来源 URL 或受限的 provider/type/title/display_text 稳定键去重，避免质量失败触发重规划时重复 evidence 持续膨胀上下文。

## 结果与边界

阶段 3.4 的四类组合验收现已齐全：并发全成功、独立单路失败、全路失败、严格依赖阻断与等待确认均有固定自动化回归；真实烟测额外证明真实 Planner、真实只读 Tool API、质量门和流式 Chat 可以走通。真实烟测不代表第三方 API Exactly Once，也不代表已开放高风险写工具或无限长任务。
