# P0-A最终验收与200任务复测

2026-11-16。本轮收尾范围是“原任务需要的工具证据是否齐全、最终是否交给模型、声明章节及导出产物是否实际存在”。不增加执行权限，不将判定范围扩成任意任务或答案事实正确性的证明。

## 本轮补齐了什么

用户要求比较A、B两份资料时，找到文件名或者只读到A不能算完成。代码从原问题的明确文件ID、有限字面文件名提取目标，逐份检查执行器返回的真实来源。少了B就把具体缺项交给原有Planner循环，只补缺项；仍使用原轮次、调用数、时间和权限预算。完整、同范围、同内容、同版本的独立重复读取可以省去，变化或不确定时仍走原执行检查。

最后再按预算治理后的`final_source_map`检查一次。检索/工具曾返回过，但正文最终被删掉或只保留节选，不能证明全文已经核对。文档任务则核对用户填写的必需章节、授权来源清单及真实Markdown/DOCX，失败保留前序成果，显式重试，不自动改写报告。

| 文件 | 实际职责 |
| --- | --- |
| `backend/app/services/tools/task_spec.py` | 从原问题提取有限目标，逐份核对来源；不读取外部正文新增目标 |
| `backend/app/services/tools/completion_verifier.py` | 执行后和最终Prompt后检查必要证据，输出缺项及检查范围 |
| `backend/app/services/tools/loop_runtime.py` | 缺项反馈进入原循环；重复读取前复查当前范围、内容和版本 |
| `backend/app/services/tools/providers/workspace_files.py` | 标记实际读取是否为行范围/字符上限节选 |
| `backend/app/services/document_completion.py` | 核对已声明章节、来源及真实导出内容；完整调用路径见docs/230 |
| `scripts/agent_task_batch_runner.py` | 使用账号当前在线模型、遵守Chat配额、保留HTTP失败及逐题Trace |
| `backend/tests/test_file_target_completion.py` | 验证漏一份、错误来源、节选、预算删除、重复计划、权限与轮次边界 |

## 验收口径

原题本`backend/evals/agent_tasks_200_v1.json`、40条知识题既有Gold、预期事实和评分均未修改。模型为账号当前配置的在线`deepseek-flash`；未切换账号、未启动本地模型。代码固定为`2dacc36`，批测期间未重启API或Worker。前端构建检查后仅重启前端，发生在API直连的文件题阶段，审批浏览器阶段尚未开始。

第一批`p0a-business-200-20261116-r1`完整保留：43通过、156部分、1失败。原因主要是脚本并发3超过账号Chat配额2，很多请求在创建任务前被429拒绝，并未执行模型。它不能用于估计模型任务质量或成功请求延迟。脚本修复为按账号配额限制并发；仅对创建Run前的429遵守Retry-After有限等待，同一client_request_id保证幂等。已创建任务和模型输出不透明重试，403等不重试，服务端限额不放宽。

正式复测为独立的`p0a-business-200-20261116-r2`，不覆盖首批报告，也不拼接局部成功重测。原始2026-11-05批次为170/29/1，2026-11-06图迁移批次为176/23/1；两份历史均保留。历史模型为V3.2、运行时也不同，数值差异不能全归因于P0-A。

## 保留的边界

- `complete`只在`assessment_scope=declared_tool_evidence`范围内成立，`answer_semantics_verified=false`。证据完整不能替代引用、计算或事实正确性评分。
- 文件目标解析是有限语法，不保证理解任意省略、别名、长文档范围或所有自由任务要求。不承诺多文件原子快照。
- 缺权限不扩大权限，待审批不冒称写入；最终预算删掉正文不靠重复读取解决。
- 本批不新增线上语义Judge，不完成P0-B沙箱或P0-C独立安全对抗。真实脚本隔离仍未验收，不能降级为宿主直接执行。
- 未测的完整任务Token成本、通用依赖正确率、语义忠实度和恢复率保持未知。小样本延迟不是生产SLA。
