# 阶段 4.3B：动态 MCP 受限摘录与 Fixture 验证

更新时间：2026-09-20  
状态：已完成阶段 4.3B；阶段 4 整体未完成。

## 本步解决的问题

4.3A 已经把 evidence 可见性从 Tavily 特判抽象为 `Evidence Projection Profile`，但动态 MCP 仍不能声明 `bounded_excerpt`。本步为动态 MCP 增加一条可审核、可回归的正文摘录路径：只有低/中风险只读 Tool 通过 Mapper、质量合同和 fixture 验证，才允许在合同中声明受限摘录。

这里的 fixture 是脱敏的离线样例，不是线上远端请求。它验证的是“Provider 返回的结构能否按声明映射，以及摘录是否按安全边界投影”，不会把远端原文、URL 或响应 body 写入审核报告。

## 现在的闭环

```text
动态 MCP 合同
  → canonical Mapper（白名单 JSON Pointer）
  → quality contract（valid/invalid）
  → bounded_excerpt Profile
  → fixture expected.projection_status
  → PlannerObservationProjection
  → 只记录状态/字符数的审核报告
  → 人工审核后才可进入 Catalog
```

fixture 里的 `projection_status` 只允许以下结果：

- `available`：有 canonical 正文，且通过有界投影；
- `suppressed_suspicious_content`：正文命中保守的疑似控制信号，完全不投影；
- `missing_canonical_content` / `empty_canonical_content`：结构存在但没有可用 canonical 正文；
- `not_eligible`：没有来源、身份/Provider 不匹配或不具备投影资格。

审核报告只包含 `projection_status`、`excerpt_present`、`excerpt_chars`、`excerpt_source_count`，不包含摘录正文。Profile 仍绑定 `allowed_source_types`、最大来源数、每条字符数和总字符数；Profile、fixture bundle 和当前 MCP 配置都进入摘要绑定，任一修改都会使旧审核失效。

## 适配性与安全边界

- 新动态 MCP 不声明 Profile 时仍为 `none`，不会自动获得正文可见性。
- `bounded_excerpt` 只能读取 Mapper 生成的 `/metadata/raw/...` 标量，不能读取标题、URL、`display_text` 或任意嵌套响应。
- fixture 只验证离线样例，不代替 Executor 的权限、Schema、ACL、审批和重放保护。
- 摘录是“不可信 evidence”，即便通过投影也不能改变工具选择或获得新的权限。
- 动态 MCP 仍必须先经过人工审核；`is_enabled=true` 不能绕过合同摘要和 fixture 校验。

## 代码与测试

- `backend/app/services/tools/onboarding.py`：允许动态 MCP 声明 `bounded_excerpt`；扩展 fixture expected 合同；执行 Mapper、质量门和 Projection，并生成脱敏审核报告。
- `backend/tests/test_tool_onboarding.py`：覆盖正常摘录、缺正文、可疑内容抑制、摘要绑定和报告不泄露原文。
- `backend/app/services/tools/observation_projection.py`：复用通用 Profile 进行实际投影，不新增 Provider 特判。

本阶段没有宣称完成动态 Token 预算、跨来源去重或更强的语义 Prompt Injection 检测；这些仍属于后续 4.3C/4.4 的上下文治理工作。
