# RAG、工具质量与会话可靠性增强（2026-08-04）

本轮根据 MuseAI 面试暴露的问题，按现有代码边界完成四类增强：

## 1. RAG Gold Set 与评测矩阵

- 新增 `backend/evals/rag_gold_set.json`：固定问题、难度、标签和答案关键词，真实文档/Chunk 由人工复核后绑定。
- 新增 `import_rag_gold_set.py`：按文件名和 Chunk 文本标记解析目标；目标缺失、歧义或重复时 fail-closed。
- 新增 `run_rag_eval_matrix.py` 与 `POST .../matrix-runs`：固定运行 Vector-only、BM25-only、Hybrid、Vector+Rerank、Hybrid+Rerank。
- 每个配置保留独立 `KnowledgeEvalRun`、配置快照、Hit@K、MRR、nDCG、Context Precision/Recall、关键词覆盖、耗时、失败数和降级数。
- 评测不自动调用模型评审最终答案，也不伪造生产指标；简历数值必须来自固定 Gold Set、固定索引代次和固定 Provider 配置的一次可复现运行。

## 2. 双路检索与 Rerank 降级

- Hybrid 模式分别捕获向量侧和 BM25 侧错误；一路不可用时保留另一路结果。
- 两路都抛出异常时使用稳定的 `hybrid_both_unavailable` 错误码，让 Chat 和评测区别“服务不可用”和“没有相关命中”。
- 结果 metadata 只记录 `vector_error_code`、`lexical_error_code`、`hybrid_fallback_reason` 等安全诊断，不持久化 provider URL、响应正文或密钥片段。
- Rerank 抛错或空返回都会保留原排序并标记 `rerank_fallback`；空返回不再被误认为“成功重排”。

## 3. Tool ResultQualityContract

- 已有结构校验、`min_sources`、required/non-empty、枚举、数值范围、置信度和 freshness 规则继续作为 Executor 边界。
- 字符串化的 `[]`、`{}`、`null`、`无结果` 等语义空载荷会被识别为无效证据，避免形式合法结果解锁依赖工具。
- 路由、POI、天气等内置 MCP 工具补齐非空质量契约；质量为 `uncertain/invalid` 时下游依赖保持阻断，并写入 quality gate trace。
- Fallback 结果仍按父工具的质量契约重新检查，不能因为“非空”就满足结构化依赖。

## 4. 长期记忆与流式状态

- 长期记忆支持 `expires_at` TTL；过期时转为 `expired`、禁用且不进入 Prompt。
- 冲突候选确认必须显式指定 `supersedes_memory_id`，确认时在同一事务中关闭旧 active 版本并激活新版本。
- 新增 `POST /api/memories/{memory_id}/revoke`；撤销保留历史和来源，但永久禁止通过通用更新重新激活。
- Query-aware 召回在词法相关性之外加入有界 importance/freshness tie-breaker，profile/instruction 仍保持显式 always-on 语义。
- 流式新增首 token 前取消、provider iterator `aclose()`、进程异常遗留 stale streaming 消息的回归测试；stale 消息会改为 failed 并更换 generation_id，迟到写入被 CAS 拒绝。

## 5. 尚未声称完成的部分

- 当前 Gold Set 的真实文档标签需要结合实际知识库人工确认；在此之前不写入简历命中率。
- 记忆 Query-aware 目前是可替换的确定性第一阶段召回，不等同于已经接入独立记忆 Embedding/Rerank 模型。
- 进程被操作系统直接杀死时，最后一个尚未提交的增量仍可能丢失；已有 stale 自愈和 generation fencing 负责恢复可见状态，不能宣称逐 token durable recovery。
