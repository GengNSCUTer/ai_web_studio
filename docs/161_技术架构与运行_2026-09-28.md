# AI Web Studio：技术架构与运行

更新于 2026-10-09。本专题吸收 5 月《技术实现设计》中仍有价值的环境约束、前后端分工、数据模型、流式协议讨论和部署决策，并补齐当前 RAG、Tool、Skill 与 Durable 运行时。原设计全文仍在本地 [06 技术设计](06_技术实现设计.md)及飞书旧版中；早期只接 Ollama、尚未做 RAG/Agent 的段落不代表当前实现。

## 运行形态和职责

前端基于 Next.js/React，负责工作区、会话、知识库、设置、工具追踪和任务页的交互。FastAPI 后端负责鉴权、项目与用户隔离、业务事务、上下文组装、Provider 适配、工具规划与执行。SQLAlchemy 连接 PostgreSQL；pgvector 承担同库向量检索，BM25、RRF 与可选 Rerank 构成查询链。Redis Stream 是后台任务投递通道，不与 PostgreSQL 共享事务。

5 月设计选择用户态 PostgreSQL 而非 SQLite，是为了在无管理员权限的共享服务器上保留正式的事务和并发语义；不强制 Docker，则是当时部署约束，不是产品宣称永远不支持容器。前端与后端分离、数据库持久化、后台 Worker 独立运行，这三点仍是当前架构基础。在线 OpenAI-compatible API 与本地 Ollama/vLLM 均有 Provider 入口；实际验证可使用在线 API，而不必启动大型本地模型。

## 数据与请求链路

用户发起 Chat 时，后端先保存用户消息和 assistant 占位消息，建立附件、检索、来源和 Tool Trace 的锚点。短事务结束后再调用模型并通过 NDJSON 流式回传；生成终态按 message ID 与 generation ID 做 CAS，避免旧请求覆盖重新生成后的结果。强杀进程时未收口的 partial 内容仍可能丢失，不把流式连接本身描述成 Durable Checkpoint。当前 NDJSON 事件还包含 context_info，将诊断放入流中，避免响应头超过限制后丢失诊断入口；历史设计的 SSE 讨论不能当作当前协议。

流式终态收口已使用独立的 PostgreSQL `AsyncSession`：开始模型流前释放请求侧同步会话，完成、失败和断连取消后以短事务写回消息，并对取消时的 partial 保存设置限时保护。准备与上下文组装阶段的 Repository 仍有同步 SQL，因此当前不是全异步后端；这一变化主要减少流式收口时的事件循环阻塞和长流期间闲置事务，不能未经压测宣称单条 SQL 变快或整站吞吐提升。对应实现位于 `backend/app/services/chat_persistence_service.py` 和 `backend/app/api/routes/chat.py`。

知识库索引则由 Document/Job 与 Outbox 在数据库事务内落库，经 Redis Stream 投递给 Worker。Worker 解析、分块、Embedding、建立向量和 BM25 索引，形成 inactive generation，校验后按版本 CAS 激活。重投递由幂等状态和版本保护处理；数据库与 Redis 没有跨服务原子事务。查询时在用户和项目范围内分别检索向量与词法候选，RRF 融合、可选 Rerank，再按证据预算注入模型。

Tool 链由 Catalog、候选筛选、LLM Planner、参数/依赖验证、Executor、质量合同和证据投影组成。Planner 输出结构化 ToolPlan，不发 HTTP 请求，也不能授予权限；服务端检查 Schema、凭据、ACL、项目作用域、风险与 SSRF，处理 Tool DAG 的并发、依赖阻断、部分成功和失败收口。动态 MCP 需要来源和版本审核；Skill 只组合已有 Tool，不自动扩大权限。文件写入由独立 Diff、审批与 FileRevision CAS 控制。

## Durable 与同步的边界

2026-10-09 的 [Tool 改进第一步](168_Tool改进第一步_统一截止时间与部分结果保留_2026-10-09.md)使同步 Planner 和工具执行共用总截止时间。并发超时保留已完成且质量有效的证据，未完成调用记 timed_out，下游依赖阻断；系统未完成说明进入最终模型输入。准备阶段收到上游取消时按 generation CAS 收口为 cancelled；首次规划超时即使没有计划也有持久化错误轨迹。

[第二步](169_Tool改进第二步_文件非阻塞与搜索范围_2026-10-09.md)把文件同步查询移出事件循环：线程内独立 Session 获取快照、释放连接后匹配，再短事务按顺序锁行复核返回版本。文件名/ID 可定向查询，普通 list/search 返回扫描范围和绑定用户/项目/原条件的签名继续位置；Planner 仅收到有限事实，最终回答收到范围说明。619 项测试和真实浏览器/在线模型、独立 Worker 回写验收通过。这是线程池隔离，不称全后端原生异步数据库；查询进行中不能强杀，跨页也不冻结整库正文。

同步 Chat 有固定运行模式和总轮数、调用数、并发、时间预算。多步骤低风险只读 Tool Plan 可以由用户显式预览与确认，另建 Durable Run；Planner 的 `durable_candidate` 只是建议，普通 Chat 不会自动改为后台执行。AgentRun、AgentStep、Checkpoint、Artifact 和 Outbox 记录状态；独立 Worker 领取任务，凭 Lease、心跳与 fencing 阻止过期实例覆盖新结果。终态幂等回写原会话，任务页支持查询和需再次确认的 DLQ 重放。执行快照绑定 Tool/Skill 版本，漂移时拒绝回放；JSONL 审计只导出摘要和哈希，不导出凭据及完整 Tool 正文。

这是至少一次投递、有限重试和可恢复最终一致性，不是 Exactly Once。Durable 不承载任意写 Tool，也不允许借重放绕过审批。当前 Worker 有启动脚本和心跳指标，但没有外部告警推送、自动扩容或正式生产 supervisor。

## 运行与验证入口

2026-10-10 [Tool 第三步](170_Tool改进第三步_候选召回与前三步联合验收_2026-10-10.md)：selector 在添加前检查容量，以当前文件名/口语及有限用户追问补召回；Planner 与兜底限定候选，禁联网时不能自动走网页 fallback。在线默认 deepseek-ai/DeepSeek-V3.2，规划单次最多 25 秒且服从剩余 Tool 总预算。前端同会话刷新只同步消息，保留输入/模式/Skill，草稿首次绑定真实 ID 也保留组件身份。本地前端 BACKEND_BASE_URL 已对齐 32017；服务仍为前端 32018、后端 32017、PostgreSQL 35433。

2026-10-08 长期记忆第二步已接入独立记忆 Worker：Chat 完成后提交增量 Job，Worker 使用用户在线 Provider 提取并核对原文，候选/游标/Job 结果同事务提交。新增的自动生效开关默认关闭，不能靠模型输出扩权。当前 aiws-memory-worker Screen 使用 backend/scripts/run_memory_candidate_worker.sh；缺少该进程时任务会持久化等待，Chat 不同步等待提取。完整边界见[第二步记录](164_长期记忆第二步_增量提取与受控自动生效_2026-10-08.md)。

2026-10-09 [第三步记忆混合召回](165_长期记忆第三步_混合召回与注入诊断_2026-10-09.md)接入 Chat：短 Session 获取已过滤的记忆及配置，关闭事务后异步请求 Embedding，再以新的短 Session 校验版本/状态并写缓存、选择和渲染。网络等待期间不持有记忆数据库事务，缓存不改变事实的版本或更新时间。应用精确余弦与词法排名融合，Embedding 失败回退词法；最终治理后的记忆 ID/版本/原因同时进入诊断 UI 和持久化运行指标。向量 JSON 缓存与知识库 Chunk 分开，不是记忆 pgvector ANN。

同日新增[记忆聊天通知](166_长期记忆后台通知与全流程回顾_2026-10-09.md)：UserMemory.extraction_job_id 精确关联成功任务，MemoryActivityService 按用户/会话/项目读取当前状态。GET /api/memories/activity/{conversation_id} 是同步 def 路由，数据库操作由 FastAPI 线程池承接；前端独立 MemoryActivityPanel 短轮询，不占用 Chat 流式连接。撤销复用 forget 接口，稳定记忆 ID 防重复；不是新增消息代理或 WebSocket 服务。当前每种职责仅保留一套 Screen，前端 32018、后端 32017、PostgreSQL 35433。

本地依次启动 PostgreSQL/pgvector、Redis、FastAPI、Next.js；需要索引、记忆候选或 Durable 任务时分别启动对应 Worker。准确命令见仓库 [README](../README.md) 与 `backend/scripts/`。后端接口文档位于 `/docs`；自动测试位于 `backend/tests/`，真实 Worker/浏览器烟测位于 `scripts/`。架构口径和第二轮各项验收见[项目全景](159_项目当前全景与第二轮优化收口_2026-09-28.md)与[文档导航](README.md)。
