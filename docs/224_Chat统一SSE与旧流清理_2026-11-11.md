# Chat 统一 SSE 与旧流式路径清理

2026-11-11。按用户要求，将普通发送、重新生成、编辑重答和恢复查看统一到同一条 Run/SSE 链；后续同日再将前端从fetch手写订阅改成原生EventSource，删除旧解析与退避逻辑。本文更新当前实现，旧阶段报告中的 NDJSON 是当时的历史事实。

## 1. 唯一对外链路

`浏览器 → POST 创建 ChatRun（JSON 202）→ 独立 chat-worker 生成并持久化事件 → GET 订阅 SSE → 前端展示`

| 操作 | API | 响应 |
| --- | --- | --- |
| 新问答 | `POST /api/chat/runs` | JSON 202，包含 Run/消息 ID |
| 重新生成 | `POST /api/chat/runs/regenerate` | JSON 202，新 generation/Run |
| 编辑重答 | `POST /api/chat/runs/edit` | JSON 202，新 generation/Run |
| 订阅与续订 | `GET /api/chat/runs/{id}/events`，浏览器自动携带 `Last-Event-ID` | `text/event-stream` |
| 快照 | `GET /api/chat/runs/{id}` | JSON，已保存正文/状态 |
| 主动停止 | `POST /api/chat/runs/{id}/cancel` | JSON，取消请求或终态 |

创建、查询和取消是资源操作，保持 JSON，不包装成 SSE。事件载荷仍是 JSON，只是放在标准 SSE `data:` 字段，使用空行分帧，不再把每个网络读取块或单行视为完整事件。

```text
id: <run_id>:12
event: chat
data: {"type":"answer_delta","text":"正文","event_id":12,"run_id":"..."}

```

浏览器仅通过 Next `/api/backend/...` 通用代理；Cookie 转服务端 Bearer，保留 SSE Content-Type、禁止代理缓冲与缓存变换。生成、SSE订阅与独立取消之间的权限与职责未改变。

## 2. 删除的内容

后端删除 `api/routes/chat.py` 与 main 注册，旧 `text-stream/events-stream/regenerate-last-stream/edit-last-user-stream` POST 路径全部 404；`format=ndjson/text` 返回 422。只保留字面值 SSE，不保留自动格式降级。

前端删除 `/api/chat`、`/api/chat/regenerate`、`/api/chat/edit-last-user` 三份专用代理和 `chat-stream-proxy.ts`；`chat-thread.tsx` 删除按行 JSON 解析、旧响应头诊断解析、两份重复读流循环。发送、编辑、重生成与恢复共用一个 UI 事件处理器和 `subscribeChatRun`，此文件净减少约 377 行。

Worker 内部传递业务事件对象，不再 JSON 编码后立即解码；`chat_sse.py` 统一 HTTP 编码。测试用生成响应包装也只提供 SSE，已删除纯文本/NDJSON 开关。旧独立脚本迁移至共用 `chat_sse_client.py`，保留原业务断言；浏览器观测改为 Run 资源和 snake_case 请求字段。

会话导出 JSONL 与 Durable 脱敏审计的 `.jsonl` 下载仍保留。它们带附件下载语义，是文件格式，不是 Chat 对话流；不为统一聊天传输而破坏文件导出。

## 3. 重连与停止的准确说法

前端现在直接创建 **原生EventSource**，监听服务端命名为`chat`的事件，JSON仅作为`data`里的业务载荷解析。浏览器负责UTF-8、空行分帧、多行data、心跳和断线重连，并在同一EventSource重连时自动发送`Last-Event-ID`；已删除fetch读流、TextDecoder、分帧缓冲、after请求参数和手写指数退避。创建任务/快照/取消仍可正常使用fetch，它们不是事件订阅。

同源EventSource自动携带登录Cookie，Next通用代理转换为服务端Bearer并转发`Last-Event-ID: run_id:sequence`；不把Token放URL，不因换客户端改变认证/ACL。跨Run、负数和越界游标仍拒绝。后端`after`仅保留给显式重放的API/测试客户端，当前UI不使用。新建EventSource（例如重开页面）没有上次对象的原生游标，会从已保存事件/快照恢复；不能说浏览器永久保存游标或自动恢复Worker计算。

应用层仅保留Run/序号校验、重复事件去重、快照替换、终态关闭和AbortSignal到`source.close()`的转换。没有业务进展的连续五次原生error后关闭并提示重新打开会话；收到新业务事件清零计数。这不是五次总连接上限或手写重试，重连间隔由浏览器/服务端`retry`控制。EventSource进入CLOSED则立即失败，不额外fetch探查HTTP错误或回退另一种流。解析/回调异常显式失败，不能跳过已经推进原生游标的坏事件继续。

浏览器关闭只结束订阅，Worker 继续；主动停止使用独立 cancel 接口。恢复只读取持久化事件，不重发创建请求或额外调用模型。模型失败、取消、重启快照、引用和来源事件沿用原状态机制，不把工具分支失败混同为 Chat 全局失败。
