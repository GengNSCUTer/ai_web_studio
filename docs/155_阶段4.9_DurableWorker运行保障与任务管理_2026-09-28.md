# 阶段 4.9：Durable Worker 运行保障与任务管理

本阶段没有扩充 Tool Catalog，也没有把普通 Chat 自动后台化。4.7 的用户确认仍是 handoff 入口；4.8 的结果回写仍是终态出口。4.9 补的是 Worker 进程状态、任务异常发现，以及用户查看和处理任务的入口。

## 实际执行链路

Worker 以 `backend/scripts/run_agent_tool_worker.sh` 启动，先查询运行时表和数据库连接，再在 `agent_worker_heartbeats` 注册唯一实例。空队列时继续轮询并更新心跳；领取 Step 后状态变为运行中，执行过程继续沿用已有 Outbox Lease、30 秒续租、Fencing、有限重试、Checkpoint 和 DLQ。SIGTERM/SIGINT 只请求停止领取新任务，当前 Step 收口后再将 Worker 标记为停止。若进程被强杀，90 秒后心跳会被判为过期；旧 Lease 到期后，其他 Worker 才能接管，旧实例不能用旧版本覆盖新结果。

任务页 `/tasks` 调用用户作用域的 `GET /api/agent-runtime/tool-runs` 和原有 Run Snapshot、Metrics API，查看 Run、Step、错误和 Artifact 摘要；有运行中任务时每 15 秒自动刷新首屏。DLQ Step 的“受控重放”需要用户再次确认，再调用现有 replay API；只有当前用户的 dead-letter 且仍满足低风险只读约束的 Step 可以重放。重放只创建一个新的 Outbox Event，依赖失败的后续 Step 按原 DAG 重新排队。原会话结果消息先更新为“已重新排队”，Worker 收口后再在同一消息上更新新终态，不新增第二条结果消息。

健康指标目前通过 API 和任务页展示：在线/忙碌 Worker、最后心跳、待执行事件、过期租约、排队超过 10 分钟的事件、DLQ 数。它是主动查看时可见的告警，不是邮件、短信或外部监控推送。页面只显示全局 Worker 聚合数，不暴露其他用户的任务和 Worker 所在机器信息。任务列表按当前用户过滤，支持状态筛选和分页；会话跳转使用当前用户已有的会话 ID 白名单，结果消息的后台任务来源卡片可跳转对应 Run，详情 API 再次校验用户归属。

## 主要文件

- `backend/app/models/agent_runtime.py`：新增 `AgentWorkerHeartbeat` 持久化进程状态。
- `backend/app/services/durable_worker_registry.py`：启动注册、心跳、停止、过期判断和用户作用域告警聚合。
- `backend/app/services/durable_tool_runtime.py`：Worker 生命周期接入、已有 Lease 续租、重放后结果消息原地更新。
- `backend/scripts/run_agent_tool_worker.py`、`run_agent_tool_worker.sh`：SIGTERM/SIGINT 优雅停机和模块启动入口。
- `backend/app/api/routes/agent_runtime.py`：新增分页、用户作用域的 Durable Run 列表。
- `frontend/src/app/tasks/page.tsx`、`frontend/src/components/task-dashboard.tsx`：任务页、状态和受控重放。
- `frontend/src/app/chat/page.tsx`、`frontend/src/components/chat-app.tsx`：从任务页返回原会话时按归属合法的 conversation ID 加载消息。
- `scripts/stage49_worker_browser_smoke.py`：真实数据库、独立 Worker 和浏览器烟测，退出时清理临时记录。

## 验证与边界

单测覆盖在线重名拒绝、心跳过期接管和旧实例 Fencing、空队列继续运行、优雅停机、用户范围隔离、DLQ 重放幂等以及会话结果原地更新。PostgreSQL 条件集成在内的后端全量回归 485 项通过，前端 lint/build 通过。真实烟测使用固定测试用户创建临时只读任务，独立 Worker 完成 `workspace.files.list`，浏览器看到了 Step/Artifact 并回到原会话，SIGTERM 后状态为 `stopped`，测试数据已清理。这个测试不调用本地 Ollama，也不修改现有知识库。

真实流程发现并修复两个脚本级问题：Python 3.10 下 `asyncio.wait_for()` 的超时必须捕获 `asyncio.TimeoutError`，否则空队列 Worker 会退出；Worker shell 入口必须用模块启动，否则找不到 `app` 包。

本阶段仍不包含外部推送告警、自动扩容、任意 Tool 写入或完全自动重放。外部推送和集中式进程托管属于部署层，当前个人本地工作台只提供可查询健康指标和独立 Worker 脚本，不继续扩大本阶段范围。4.10 已完成 Planner 的受控后台候选建议；4.11 继续补充 JSONL 审计和失败 Step 的安全回放。
