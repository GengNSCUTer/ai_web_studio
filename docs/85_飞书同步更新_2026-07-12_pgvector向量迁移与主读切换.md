## pgvector 向量迁移与生产主读切换

### 数据模型

`KnowledgeChunk` 已增加 nullable `vector` Embedding 及 provider/model/dimensions/version 签名。库内向量统一使用 `l2-normalized-v1` 表示协议。

### 全库重复 Embedding 优化

重索引现在复用签名匹配的持久化向量；目标文档重切后的 Chunk 也可在 `content_hash` 相同时复用旧向量。只有真正新增、改变或模型签名失效的 Chunk 会请求 Embedding API。

### Legacy FAISS 向量迁移

默认 provider backfill 因当前 API key 无效返回 401，数据库没有留下部分回填。随后从正在服务的 legacy FAISS 按 vector_id 迁移，校验维度、ID 集合、数量和有限值后一次提交：

```text
KnowledgeChunk = 376
pgvector embedding = 376
dimensions = 1024
embedding_version = l2-normalized-v1
```

### FAISS / pgvector 对照

真实 top-20 对照的 ID 集合和顺序完全相同，最大分数误差约 `7.55e-08`。

### 正式切换

- screen `aiws-backend` 已切换到 PostgreSQL 18 / 35433。
- `/health` 返回 HTTP 200。
- PostgreSQL 生产检索路径已直接使用 pgvector cosine query。
- PostgreSQL 12 / 35432 和原数据仍保留为显式回滚点。
