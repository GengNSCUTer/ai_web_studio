# 阶段 4.6A：Chat 到工作区文件审批端到端验证

## 本阶段完成

阶段 4.6A 把已有工作区文件工具接入 Chat/API/前端审批业务链路：用户提出明确文件修改需求后，系统在当前项目范围内定位、读取文件并生成持久化 Diff；默认 `ask` 模式只返回 `confirmation_required`，不会直接写文件。用户在前端确认后，后端按 `challenge -> apply` 顺序校验一次性凭据、参数哈希、用户/项目 ACL、基础 FileRevision 和 CAS，成功后写入新 Revision，并可重新读取核验。

主要实现文件：

- `backend/app/services/tools/providers/workspace_files.py`：工作区文件 list/search/read/propose_edit。
- `backend/app/services/tools/executor.py`：统一 schema、权限和审批边界。
- `backend/app/services/agent_runtime_service.py`：AgentRun/Step、PatchDraft、Approval、FileRevision、一次性 challenge 和 CAS 写入。
- `backend/app/api/routes/agent_runtime.py`：审批 challenge/apply/reject API。
- `frontend/src/components/chat-thread.tsx`：流式工具事件和历史刷新后的状态保留。
- `frontend/src/components/tool-trace-panel.tsx`：Diff 展示、用户确认和 CAS 成功状态。
- `scripts/stage46a_playwright.py`：浏览器审批交互与 console error 冒烟。

- 后端/API 定向测试：63 项通过。
- PostgreSQL 全量后端回归：466 项通过，无跳过。
- Python `compileall`：通过。
- 前端 ESLint 与 `npm run build`：通过。
- Playwright：登录、Chat 发送、工具事件刷新保留、Diff 展开、challenge/apply 确认、CAS 成功提示和浏览器错误检查均通过。

## 边界

本阶段不新增 Tool、不开放任意本机文件写入，也不宣称真实 LLM 已经稳定自动规划文件编辑。默认 Chat 不会静默修改文件；文件操作仍受当前用户、当前项目、ACL、审批和 Revision/CAS 约束。后续如需继续，应在固定低风险工作区用例上补充真实在线模型 Planner 到文件提案的验证，再评估 Durable handoff。
