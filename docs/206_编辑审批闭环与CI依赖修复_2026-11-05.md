# 编辑审批闭环与 CI 依赖修复

日期：2026-11-05。承接 [205 首轮 200 题](205_Agent工具路由修复与200题业务回归_2026-11-05.md)，只修编辑与 CI，不扩大权限、轮数、时间预算或 Provider 配置。

## 1. 问题与修复

首轮审批题只有 9/20：多次请求模型定位、读取和规划导致 35 秒内没有审批，最后回答却可能说“已创建”。另外，GitHub Actions `41999073648` 的后端失败链为：

```text
test_agent_200_tasks → agent_task_approval_runner → playwright.sync_api
ModuleNotFoundError: No module named 'playwright'
```

后端 CI 不安装浏览器包。现仅在真实浏览器分支加载 Playwright，纯分析/单测可独立导入；没有跳过本次导入失败的测试或添加生产浏览器依赖。

明确单文件、带引号的逐字替换：用户原问题 → 代码识别目标和 old/new → 当前候选过滤 → search → 读取实际 file_id、原文、revision_id → propose_edit 或 apply_edit → 原 Executor/审批服务。缺失、可疑、重复原文或不完整搜索都停止，不猜文件 ID、不执行宿主路径写入。

复杂改写：目标明确且只有一份文件时，代码先 search/read；实际可用原文到齐后仍由在线 LLM Planner 生成编辑参数。多文件、假设性问题或无法明确识别的请求保留通用规划，不宣称任意自然语言编辑都能确定性完成。

`edit_proposal` 的状态由本轮实际 Workspace 规范来源生成：有真实 Diff 才展示，有 approval_id/run_id 才说等待审批，有 applied 和新 revision_id 才说已应用。缺结果说未完成，不让最终模型代替审批系统报告。Diff 使用预算后来源映射及真实引用，保持 NDJSON、generation CAS、持久化、取消和引用审计。记录 `answer_origin=verified_file_edit_status`；普通 Chat、文件事实和研究回答仍由模型完成。

额外修复：`apply_edit` 直接进入审批服务，之前遗漏标准调用开始事件，导致 ToolCallRun 的参数为空；现记录实际尝试的脱敏参数。全局 full_workspace 下，当前用户明确“等我确认、未确认前不写”时，Executor 只把本次调用收紧为 ask，不改项目设置；只读、原任务、权限和版本 CAS 检查保留。
