# 长期记忆语义冲突与人工确认

2026-11-03。本轮解决“同一事实换了标题就漏掉冲突”和“相同标题的补充被当成冲突”。没有让模型直接覆盖记忆；模型只判断关系，最终激活仍由代码和用户确认控制。

## 一、整体流程

```text
新候选
  → 当前用户 + 精确项目/全局范围 + 有效active记忆
  → 事实键匹配；难匹配的再用Embedding与词法找相似记忆
  → 规则确定简单值，模型结构化判断疑似关系
  → 重复 / 矛盾 / 补充 / 不同条件 / 不确定
  → 低置信、高影响、矛盾或覆盖不足留pending
  → 用户核对并选择是否替换、替换谁
  → 短事务重读候选/旧记忆版本，成功才激活与替换
```

物理项目范围先由代码隔离：项目A记忆不会作为项目B的冲突对象或发给判断模型。模型的different_scope主要区分同一项目内部的对象、环境、条件和时间，例如测试环境SQLite与生产环境PostgreSQL；不是允许模型改变项目权限。

## 二、五步怎样落实

1. **事实键找候选。** 沿用memory_identity及现有语言偏好归一化，不将普通标题当作可靠语义标识。已能确定的单值重复/变化由代码判断；不能被模型一句“可并存”撤销结构化单值约束。
2. **相似记忆补召回。** 对难匹配候选使用当前账号在线Embedding，复用记忆专用向量/版本/模型签名。只读同范围有效记忆，不混用知识库Chunk，也不加载Ollama。向量相近仅表示需要比较，不表示已经冲突。
3. **结构化语义判断。** 服务端分配pair_id并绑定旧记忆ID/版本，模型只能返回关系、数值置信度、影响、双方逐字引文及短理由。校验ID集合、字段/枚举/数值和引文归属；布尔置信度、伪造ID、错引文和非法JSON按不可用处理。标题/正文是数据，不执行其中指令。
4. **保守人工确认。** 关系为矛盾、低于0.85、长期指令/敏感/重要记忆、生产/权限等高影响规则命中或模型建议高影响时，不自动生效。原文证据、用户自动开关、临时语句和撤销历史规则继续生效。0.85是模型自评分门槛，不是校准概率或真实准确率。
5. **代码最终变更。** 分析保存候选正文/范围、active版本清单和逐对结论；激活时用户锁内重读，范围或版本变化要求重新分析。新分析的替换必须在请求中明确supersedes_memory_id及expected_target_version，同时检查expected_version。旧版superseded、新版active在同事务提交，重复确认不重复替换；确认选择保存在human_resolution。

例子：

| 旧记忆 / 新记忆 | 处理 |
| --- | --- |
| “默认保存7天” / “保留期限30天”，标题不同 | 语义召回后判矛盾，旧版保留，用户确认后明确替换。 |
| 标题都叫“技术栈”，内容为FastAPI与Redis | 判补充可并存，不因标题相同强制覆盖。 |
| 测试SQLite / 生产PostgreSQL | 不同条件可并存；生产项仍按高影响要求确认。 |
| “保存30天” / “保留期限30天” | 判重复，保留已有active，候选可拒绝，不自动销毁历史。 |
| 模型低置信补充 | 待审，用户核实后可以确认并存；不能把低置信当自动放行。 |

## 三、用户如何操作

后台提取产生pending后进入设置中心“长期记忆”。卡片显示对应旧记忆、旧版本、关系、模型自评分或规则判定，以及影响与理由。需人工确认时勾选核对；矛盾项选择具体替换目标，再点击“确认替换并启用”。补充项可以选择新增，不替换旧记忆。重复项引导使用已有记忆。

候选内容或相关记忆变化后，先点“重新检查冲突”，新分析更新候选版本，旧页面的确认会被拒绝。历史无分析的候选通过API启用前会补分析并要求再次确认。直接编辑active记忆涉及需审关系时返回409，引导先创建待审候选；不能通过编辑入口绕过检查。人工创建、手动建议、编辑、后台提取共用分析服务。

新增POST /api/memories/{id}/check-conflicts，输入expected_version；已有approve接口新增expected_target_version及acknowledge_conflicts。关系报告只由服务端产生，客户端不能提交一份“安全报告”绕过模型或代码校验。

## 四、并发与失败边界

- 模型/Embedding等待前关闭快照Session；现有异步创建、建议和编辑入口也释放原Session事务，不持有用户锁等待网络。
- 提取、Embedding、语义判断分别限制45/6/25秒。当前每次最多16对、每候选6对，Embedding请求最多32条；大目录未补完、长正文超过比较范围或命中对被限额时标记覆盖不足，不能声称无冲突。
- 模型正常返回低置信/uncertain与服务不可用分别记录；Embedding/JSON/引文出错不变成safe，不删除旧记忆。没有疑似关系时不额外调用判断模型。
- 记忆向量仍是既有JSON缓存和小范围精确相似度，没有新建记忆ANN；大规模记忆检索优化不在本轮。
- 激活检查同范围全部有效active版本，其他事实同时变化也可能要求重新检查。这是保守策略，代价是额外审核，不是只检查候选id。
- 同批第一条自动启用后，后续候选的版本清单失效，转pending/stale；避免不同标题的矛盾候选在同批都自动生效。
- 到期状态更新也加入同一用户锁，与激活/替换串行；向量缓存写入只按正文/版本比较，不改变事实版本。
- 敏感原文不发给Embedding或判断模型；需要保留的候选按既有敏感规则待审。高影响识别仍是有限规则加模型建议，不是覆盖所有领域的业务风险证明。
