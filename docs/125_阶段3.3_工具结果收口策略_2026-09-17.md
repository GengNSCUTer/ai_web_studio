# 阶段 3.3：工具结果收口策略（2026-09-17）

## 本阶段目标

把阶段 3.1/3.2 产生的 `ToolWorkflowAggregate` 接到同步 Chat 外层策略。一次工具计划完成后，代码侧根据聚合状态、质量反馈、Planner 是否请求续轮和剩余五轮预算，确定下一步是：

- `finalize_partial`：保留已经通过质量门的证据，忽略失败或阻断分支；
- `replan`：把脱敏的质量/失败观察交给 Planner，在剩余轮次内重新规划；
- `clarify`：等待用户确认或补充依赖信息，不继续调用工具；
- `stop`：本次同步请求终止，并记录稳定的终止原因。

## 当前实现

### 1. 代码侧策略映射

`backend/app/services/tools/workflow.py` 新增 `ToolWorkflowAction` 与 `decide_workflow_action()`：

- `waiting_approval` 优先映射为 `clarify`，即使当前已经到第五轮也不会偷偷执行；
- `partial` 在没有续轮必要时映射为 `finalize_partial`，只让已通过质量门的 sources 进入最终 Prompt；
- 质量反馈或 Planner 明确需要观察下一轮时映射为 `replan`；
- `succeeded` 正常结束为 `stop(completed)`；
- 全部失败为 `stop(all_tool_branches_failed)`，依赖阻断为 `clarify(dependency_blocked)`；
- 在第五轮仍要求续轮时强制 `stop(max_rounds_reached)`，并给出转向显式可恢复工作流的提示。

`has_sources/has_error` 仅用于兼容自定义测试 Workflow；正式 Workflow 的 sources 已经过 ResultQualityContract，失败和不合格证据不会进入最终 Prompt。

### 2. Chat 入口与可观测性

`backend/app/services/external_context_service.py` 在每轮执行后调用上述策略，并将动作与原因写入：

- `tool_agent_round_end` 事件的 `next_action`、`decision_reason`；
- `tool_agent_terminal` 事件的 `next_action` 和稳定终止原因；
- `diagnostics.external_tool_next_action`；
- `details.tool_workflow_next_action`。

用户可见的提示统一为脱敏文案：部分成功、依赖未满足、等待确认、全部失败和轮次耗尽分别说明，不拼接 Provider 原始异常、URL、参数或远端正文。

### 3. 没有改变的边界

- 同步 Chat 仍最多五轮 `plan -> execute -> observe`，每份 ToolPlan 仍最多五次调用；
- 没有新增 Tool、权限或自动 Durable handoff；
- Planner 只能提出受限计划，不能决定依赖是否可选、绕过 Approval 或提升风险级别；
- 外部 Tool 结果仍然是不可信 evidence，只有质量门允许的证据才可进入最终回答上下文。
