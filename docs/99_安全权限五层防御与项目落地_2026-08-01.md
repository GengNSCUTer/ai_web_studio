# 安全权限五层防御与 Agent 项目落地

日期：2026-08-01

## 一、参考文档的借鉴意义

参考文档的核心不是某一组 Bash 黑名单，而是纵深防御：危险能力硬拒绝、资源作用域、细粒度工具规则、整体权限模式和人在回路确认分别承担不同职责。它还指出了三类不能只靠 System Prompt 解决的威胁：间接 Prompt Injection、越权操作和数据泄露。

当前产品不是代码代理，也不开放 Bash、Shell、SQL、删除文件、任意本机写入、支付、邮件、外部发布或任意 HTTP 写入。因此项目没有照搬 `ToolName(pattern)` 的命令规则，而是将五层模型映射到已存在的知识库、MCP、Skill 和 ProjectFile 边界。

## 二、当前项目的五层权限链

**第一层：能力硬拒绝。** Planner 只能从候选 Tool Catalog 选择，Executor 遇到未知工具、未审核 MCP、非只读高风险外部能力或不在产品目标内的能力会 fail-closed。`full_workspace` 也不能授权任意 MCP 写入或外部副作用。

**第二层：资源作用域。** Workspace File Tool 只接收不透明 `ProjectFile.id`，每次查询同时绑定 `user_id + project_id`，不接受 OS 路径、storage key 或 Shell 表达式。MCP Server 现在支持 `project_id`，项目级 Server 只进入绑定项目的 Tool Catalog；用户级 Server 才能跨自己的项目复用。ProjectFile 的 `.env`、凭据、私钥等敏感文件名被 Agent Tool 硬拒绝。

MCP 的作用域字段同时覆盖了设置页创建流程和运行时 schema 升级：设置页会把当前工作区 ID 一并提交，并明确展示用户级/工作区级范围；旧 PostgreSQL 部署由启动时幂等补列和索引，避免只更新 ORM 后在升级环境中出现“列不存在”。

**第三层：细粒度工具开关。** `WorkspaceToolSetting` 仍然是项目级 allow/deny 开关。本轮开始，项目禁用的工具会在构建项目 Tool Catalog 时标记为不可默认启用，Candidate Selector 不再把它推荐给 Planner；Executor 仍会在执行前再次读取设置，防止竞态或绕过 Planner。

**第四层：权限模式。** 当前保留三个模式：`read_only` 只允许无副作用的低风险读取；`ask` 允许只读工具，文件修改进入持久化 Diff/Approval；`full_workspace` 只自动放行受 ACL、一次性 continuation 和版本 CAS 保护的 `workspace.files.apply_edit`，不等于服务器或本机完全访问，也不会自动放行外部写入。

**第五层：HITL 与持久化确认。** 文件修改先创建 PatchDraft、AgentRun、AgentStep、AgentApproval 和 FileRevision，用户确认后再通过参数哈希、文件基线和 CAS 写入。重复确认、过期确认、旧版本覆盖和不匹配参数都会拒绝。高风险外部能力当前没有安全 continuation，因此直接拒绝而不是伪造“确认后可执行”。

## 三、数据泄露与间接注入

Tool 返回和 ProjectFile 内容都按不可信 evidence 处理，不能覆盖 System Prompt 或 Skill 安全约束。Workspace File Tool 现在会隐藏 `.env`、credentials、secrets、`id_rsa`、`.pem`、`.key` 等敏感命名文件，并对常见 `API_KEY`、`password`、`token`、AWS/GitHub/OpenAI 风格凭据做输出脱敏；编辑 Diff 也会脱敏。原始文件仍由应用自己的上传/管理链路保存，不因此删除用户数据。

工具被拒绝时不会把异常原文泄露给模型或 Trace，而是产生安全的工具错误观察；同步 Chat 可以在五轮上限内调整计划，不能通过换一个名称或外部文本绕过 Executor。

## 四、MCP 与 Skill 的权限原则

MCP Server 的远程 `readOnlyHint`、Schema、description 和返回内容都只是 untrusted metadata/evidence。Schema 或 annotation 变化会使本地审核失效，工具回到高风险、禁用状态，必须重新审核。Skill 只能缩小已有 Tool allowlist，不能新增权限、安装可执行代码或覆盖项目权限模式。

## 五、验证与后续边界

本轮新增项目级 MCP 隔离、项目禁用 Tool 不进入候选目录、敏感文件隐藏、凭据脱敏测试。后端全量回归 289 项通过，3 项外部数据库条件跳过。

当前没有实现通用 Bash 规则引擎，也不应为了学习文档而引入。后续如果产品真的增加新的副作用工具，应先为该工具单独定义输入作用域、不可逆操作硬拒绝、审批 continuation、幂等键、审计字段和补偿方案，再加入 Tool Catalog；不能用 `full_workspace` 作为通用万能权限。
