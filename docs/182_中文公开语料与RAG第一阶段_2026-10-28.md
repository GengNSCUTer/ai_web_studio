# 中文公开语料与 RAG 第一阶段

## 目标

在保留英文论文库的前提下，建立一个独立的中文技术资料库，用来验证中文术语、步骤说明、无答案问题和多段证据，不把中文结果混入论文库的历史指标。

## 已实现

- `backend/scripts/import_chinese_public_corpus.py`：固定 Python 官方中文文档 URL 白名单，保存来源快照、抓取时间和 SHA-256，并通过现有 `add_document → parse_document → index_document` 链路入库。
- `backend/evals/chinese_public_rag_gold_set.json`：13 个初始问题，覆盖 asyncio、typing、logging、HTTP server、sqlite3 和 2 个无答案问题；题目使用来源文件与证据短语绑定，导入时再次验证 Chunk 唯一性。
- 重复导入按文件名、原始 SHA-256 和规范化文本 SHA-256 跳过；离线模式不会偷偷访问网络。

## 当前验证结果

脚本已通过 Python 编译检查和差异检查。服务器出网仍不可用，因此没有把官方页面抓取结果冒充成本地快照。用户提供了本地中文后端资料，已用它建立独立中文知识库并完成真实评测，详情见 `docs/183_中文后端资料库RAG真实评测_2026-10-28.md`。

```bash
PYTHONPATH=backend python backend/scripts/import_chinese_public_corpus.py \
  --user-email '<固定测试账号>' \
  --knowledge-base-id '<新建中文知识库ID>' \
  --snapshot-dir data/chinese_public_corpus
```

官方快照恢复后仍可使用下面命令导入；本地资料则使用 `import_knowledge_pdfs.py`，它现在也支持 PDF、Markdown 和 TXT。导入后使用 `import_rag_gold_set.py` 绑定题集，运行 `run_rag_eval_matrix.py` 和真实 Chat 端到端评测。当前不把论文库 90 题当作中文库结果。

## 下一步

1. 新建独立中文知识库并确认文档索引完成。
2. 先跑 Vector、BM25、Hybrid、Rerank 五组基线。
3. 只在留出题上核验查询扩展或切块调整，记录命中、召回、答案忠实度、相关性、引用正确性、延迟和成本。
4. 评测完成后再决定是否把中文查询扩展加入默认链路。
