# 2026-07-31：Skill 显式执行主链与真实端到端验证

本轮已将此前只有安装目录与启用开关的 Skill 接入真实 Chat 执行链。用户现在可以在输入区显式选择 Skill，后端会在每轮执行时重新校验安装状态、启用状态、工作区归属、必需 Tool 和凭据，再用 Skill 声明的白名单同时约束 Candidate Selector、LLM Planner 与确定性降级路径。Planner 只生成结构化 ToolPlan，真实 Tool 调用、安全校验、结果绑定、持久化和 Trace 仍由代码完成；Tool 结果作为不可信 evidence 返回最终模型，Skill output contract 作为可信 system instruction 约束最终回答。

## 已安装的四项内置 Skill

| Skill | 功能 | 边界 |
| --- | --- | --- |
| `research.web-brief` | 使用 Tavily 生成带来源的联网研究简报 | 展示证据、来源和不确定性 |
| `workspace.document-review` | 在明确工作区中检索、读取并审阅项目文档 | 只读，不包含文件写入 |
| `travel.route-planner` | 地理编码与驾车路线规划，可选补充天气、距离、步行、公交、POI 和联网搜索 | 必需 Tool 或凭据不可用时拒绝执行 |
| `agent.artifact-review` | 读取并复盘当前用户和工作区可见的 Agent 产物 | 强制 Artifact ACL |

公开候选 Skill 的来源和安装量不足以支撑服务端直接执行，因此当前采用项目内置、经过审核的声明式 Manifest。Skill 不允许携带 Python、Shell、任意 URL、凭据或新权限，只能组合已经存在并由 Executor 审核的 Tool。

## 可观测性与前端

Trace 新增 `skill_activation` 和 `skill_result`，记录 Skill 版本、允许的 Tool、Planner 结果、实际 Tool、来源数量、执行轮数与终态。运行指标可按 Skill、Run 状态和 Tool Call 状态聚合最近 500 条 ToolRouteRun。前端只展示已安装、已启用且当前工作区可执行的 Skill，并覆盖新聊天、重新生成和编辑重答；390px 移动端菜单越界问题已修复。

## 验证结果

- 后端最终全量回归共运行 272 项，结果 `OK`，其中 3 项条件跳过；`compileall` 通过。

## 当前边界与下一步

当前仍不开放 Bash、Shell、SQL、删除文件、任意本机文件写入、支付、邮件、外部发布和任意 HTTP 写接口。文件修改继续要求 Patch Draft、用户 Approval、one-time continuation 与 FileRevision CAS。

下一阶段优先建立 Skill/Tool Gold Set 与 Recall@k、Planner 正确率、参数正确率和端到端成功率基线；随后增加“系统推荐、用户确认激活”，再补签名、来源、版本锁、兼容性、升级回滚和供应链审核。达到这些条件后，才适合考虑第三方 Skill 市场。
