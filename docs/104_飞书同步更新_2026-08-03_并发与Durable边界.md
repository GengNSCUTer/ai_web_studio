# 2026-08-03 增量：Durable 参数与 DLQ 依赖重放

本次只同步相对于上一份代码审查收尾快照的增量：

- Durable enqueue 和 Worker 统一使用 `default_arguments -> model/binding arguments -> fixed_arguments` 的 effective arguments。required fixed/default 字段不再被错误判定为缺失；fixed 参数在持久化和模型 Trace 中剔除，仍由可信 Adapter 最终注入。
- DLQ replay 现在按依赖闭包恢复下游：只恢复因目标 dead-letter Step 而 `dependency_failed` 的下游，且其它依赖必须已经成功；独立失败分支不会被绕过。
- 源 Step 和可恢复下游在同一个事务中各自产生新的 replay outbox event，原事件保留审计；Run 状态和 checkpoint 一并更新。
- Durable metrics 的 Run、Step、Outbox、Artifact 统计统一限定 `runtime_kind=durable_tool_workflow`，不再混入 file-edit AgentRun。

验证：新增 6 项行为测试；后端完整回归 `331 tests`，`OK (skipped=3)`。3 项跳过均为未设置 `TEST_POSTGRES_URL` 的 PostgreSQL/pgvector 集成测试；`compileall`、默认 Tool manifest JSON 校验、`git diff --check` 均通过。

边界：这些修复仍提供至少一次投递下的可恢复状态机，不等价于跨 PostgreSQL、Redis、Provider、文件系统和第三方 API 的强事务或 Exactly Once。SQLite 测试也不能替代真实 PostgreSQL 多进程 `FOR UPDATE SKIP LOCKED` 验证。
