# 2026-08-03 代码审查收尾：Tool 持久化边界与在线 generation fencing

本轮完成了高风险后端代码审查的最后一批收口，并把保护放到了实际 mutation/runtime boundary：

- `ToolExecutor` 在凭据解析和 Adapter 网络副作用前再次执行完整 Input Schema 校验；非 object 参数 fail-closed，校验失败不会触发 Adapter。
- Adapter/MCP 返回的 `ExternalSource` 在观察、Result Binding、公开响应和 Durable Artifact 前统一做递归敏感键、凭据文本和 URL 查询值脱敏，覆盖独立 `token/key` 参数，同时避免误伤普通 `token_count` 字段。
- Durable Artifact 持久化增加 200,000 字符上限、严格 JSON 序列化和非有限数值拒绝；超限或不可序列化结果不会保存半截 JSON，而是进入明确的不可重试失败终态。
- `generation_id` 启动迁移支持缺列、nullable、无默认值和中断后的可重入恢复，按“加列 -> 回填 -> 默认 -> NOT NULL”完成约束。
- 残留 `streaming` 消息自愈时先取得消息行锁，再轮换 generation token；正常完成的消息不会被旧自愈读覆盖，迟到的旧模型流会被 `message_id + generation_id` CAS 拦截。
- 文件 revision 列表读取移除不必要的 ProjectFile 写锁，避免只读请求阻塞正常文件修改。

验证结果：后端完整回归共 325 项，`OK (skipped=3)`。3 项跳过均为未设置 `TEST_POSTGRES_URL` 的 PostgreSQL/pgvector 集成测试；`compileall`、默认 Tool manifest JSON 校验和 `git diff --check` 均通过。新增的 URL 脱敏、非有限 JSON、消息自愈边界测试已包含在回归中。

边界保持不变：这些措施不等价于跨 PostgreSQL、Redis、Provider、文件系统和第三方 API 的强事务或 Exactly Once；外部只读调用仍是至少一次语义，进程强制终止时尚未收口的同步 Chat partial content 仍可能丢失。Durable Runtime 继续只接受低风险只读 Tool，任意外部写入仍需专用审批、幂等和补偿设计。

## 后续边界修复：Executor effective arguments

复核发现 Planner 已经使用 `default_arguments -> 模型参数 -> fixed_arguments` 的 effective arguments 做校验，但 Executor 最终边界此前只校验模型参数，可能把合法的 required fixed field 误判为缺失。现已在 Executor 的凭据解析和 Adapter 副作用之前按同一合并顺序重新校验；校验后只把 default 与模型参数保留在 `call.arguments`，fixed 参数仍由 Adapter 最终覆盖，且不会进入模型可控 Trace。

新增回归覆盖 required fixed argument、default argument、严格 `additionalProperties=false` 和 fixed 参数不泄露。定向 Executor 13 项通过；后端全量回归共 325 项通过，3 项 PostgreSQL/pgvector 集成测试因未设置 `TEST_POSTGRES_URL` 跳过。
