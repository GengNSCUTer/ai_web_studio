# 阶段 3.2：独立失败与依赖阻断策略

## 1. 这一步解决什么问题

一次 Tool Workflow 可能同时执行多个工具。过去只看一个总状态，容易把“一个独立工具失败”和“整个任务都失败”混在一起，也容易让下游工具在上游没有可靠结果时继续执行。

阶段 3.2 将这两种情况明确区分：

- 独立分支失败只影响自身；其它已经成功且质量有效的结果继续保留，整体通常为 `partial`。
- 声明了 `depends_on` 的下游只有在所有上游都 `succeeded + valid` 时才能执行。上游失败、结果质量为 `invalid/uncertain`、等待确认或被阻断时，下游生成 `blocked` Outcome，不进入 Executor，也不能由 Planner 删除依赖绕过。

## 2. 代码实现

### `backend/app/services/tools/workflow.py`

这是阶段 3.2 的主要入口。`ToolWorkflowService.run()` 先按依赖关系选择 ready Step，再检查上游 `ToolStepOutcome`。只有 `unlocks_strict_dependents` 为真（执行成功且质量有效）才放行下游。

每个终态 Outcome 通过 `failure_scope` 区分：

- `independent`：无显式依赖的独立分支；
- `dependent_branch`：有依赖但已经实际执行、随后自身失败的分支；
- `dependency_blocked`：因为上游没有可靠结果而未执行的下游。

`ToolWorkflowAggregate` 同时统计独立失败、依赖分支失败和依赖阻断。成功证据仍会进入最终上下文，失败/阻断信息只以脱敏的反馈进入 Trace 和后续 Planner 观察。

### `backend/app/services/tools/external_context_service.py`

同步 Chat 复用 Workflow 的 aggregate，并将同一份安全摘要放入 `diagnostics` 和 `details`。本阶段没有把失败自动扩展成无限重规划，也没有改变同步 Chat 最多五轮的限制；外层 `finalize_partial/replan/clarify/stop` 策略属于阶段 3.3。

### 测试文件

- `backend/tests/test_tool_workflow.py`：覆盖独立部分成功、失败依赖阻断、质量无效阻断、依赖分支失败和 Planner 观察中的失败范围；同时验证下游不会进入 Executor。
- `backend/tests/test_tool_router.py`：覆盖 aggregate 向 Chat 路由层透传。

## 3. 真实 Provider 烟测

测试使用当前环境中的高德和 Tavily 凭据，但输出只保留状态和计数，不输出凭据、远端正文或完整 URL。

### 上游成功、下游真实依赖执行

高德天气（深圳）作为上游，Tavily 搜索作为依赖下游：

| 项目 | 结果 |
| --- | --- |
| 总 Step | 2 |
| 成功且质量有效 | 2 |
| 聚合状态 | `succeeded` |
| 下游是否真实发起调用 | 是 |

### 上游质量失败、下游阻断、独立分支成功

高德天气使用不存在的行政区，另设一个独立 Tavily 搜索和一个依赖高德的 Tavily 搜索：

| Step | 执行状态 | 质量状态 | 失败范围 |
| --- | --- | --- | --- |
| 高德天气 | `failed` | `invalid` | `independent` |
| 独立 Tavily | `succeeded` | `valid` | `independent` |
| 依赖 Tavily | `blocked` | `not_applicable` | `dependency_blocked` |

最终聚合为 `partial`，保留独立 Tavily 的有效结果；依赖 Tavily 没有进入 Executor，没有发起第二次网络请求。

## 4. 验证结果

- 阶段 3.2 定向测试：38 项通过。
- 后端完整回归：423 项通过，5 项因未配置 `TEST_POSTGRES_URL` 跳过。
- `compileall`：通过。
- `git diff --check`：通过。

## 5. 当前边界

本阶段只稳定“事实和状态”：哪些分支成功、哪些分支失败、哪些下游被依赖阻断。它没有开放任意 Tool，也没有把同步 Chat 改造成无限自主 Agent。下一步阶段 3.3 再决定 aggregate 到最终回答、受控重规划、用户澄清和停止的映射。
