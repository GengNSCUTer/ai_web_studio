# 第四步：可恢复文档任务与整体验收

当前可交付链路是“选资料或选择一条已完成回答 → 取证 → 在线模型生成草稿 → 导出 Markdown/Word → 用户批准 → 工作区新文件”。任务页为 `/documents`，聊天消息的“保存为文档”也转入该任务流程。后台阶段进度保存在已有 Run/Step/Artifact/Checkpoint 中；不会把普通 Chat 断线说成已经后台化，也不承诺续接模型中断的 token。

本轮完成非脚本文档链路的代码与验收。Rootless 沙箱因权限/宿主前提不足继续禁用；脚本执行、安装依赖及容器级网络/资源耗尽仍未实测，不列入本轮通过数量。可验证的授权、代理和拒绝路径已保留在第三步测试中，不用宿主执行代替容器隔离。

## 实际阶段与恢复方式

| 阶段 | 输入 / 实现 | 输出与恢复 |
| --- | --- | --- |
| 取证 | 校验用户/工作区/文件归属、敏感文件名；读取授权正文或已完成回答及原引用 | 保存来源与正文 Artifact，40,000 字符超限明确失败，不静默截断。来源回答重生成后旧任务拒绝改读新版本 |
| 草稿 | 读取已保存证据，提交短事务释放连接，再调用账号配置的模型；资料不授予工具/写入权限 | 完成后保存草稿；取消、超时或租约被接管时未完成结果不写回；此阶段崩溃则重做该次模型请求 |
| 导出 | 使用已保存草稿及来源生成 Markdown/DOCX | 把导出文件和来源绑定 Artifact；失败保留草稿，重试导出不重调模型 |
| 交付 | 复用 AgentApproval、既有 challenge/apply/reject 接口；导出完成后暂停为 waiting_approval | 等待期间无活动事件/租约，不占用 Worker。批准后重新排队；服务端复核权限，生成独立工作区文件，禁止覆盖原文件 |

沿用 Durable Worker 的数据库事件领取、租约版本、心跳及检查点；Web 不执行模型文档任务。只有当前可执行阶段有 pending 事件，未来阶段为 planned，避免对账器提前排队导出/交付。Worker 取回结果后重读并核验 owner/version/expiry，旧执行者不能在取消或被接管后写回。

文档生成等待设 90 秒总限时，按阶段记录 `document_draft_timeout` 等错误；临时故障最多两次自动尝试，4xx 中的永久错误不自动重试。耗尽进入 dead_letter，失败任务支持用户明确重试失败阶段，已完成产物不重做。取消不删除已生成证据/草稿/导出文件。已经发到外部 Provider 的请求不保证服务商立即停止计算，但服务端会取消本地等待并拒绝写入旧结果。

新文件保存使用每个 Run 固定的文件 ID 和路径；文件写出后、数据库提交前即使进程崩溃，重新执行仍使用同一位置和同一记录身份，不重复创建工作区文件。数据库结果、审批状态和任务状态由短事务提交。未承诺主机断电时文件系统和数据库能形成跨介质原子事务。

## 接口与页面

`POST /api/document-tasks` 创建任务（用户作用域幂等键）；`GET /api/document-tasks` / `/{run_id}` 查询；`POST /{run_id}/cancel` 取消；`POST /{run_id}/resume` 明确重试失败阶段；`GET /{run_id}/artifacts/{id}` 读取正文；`GET /{run_id}/artifacts/{id}/download` 下载导出文件。

保存复用 `/api/agent-runtime/approvals/{id}/challenge`、`/apply` 与 `/reject`。文档审批只批准创建新文件；原文件改写仍使用原 PatchDraft/Revision CAS，不混淆两种操作，也不因任务已导出就直接覆盖原文件。

`/documents` 可按工作区选资料、填写要求、选择 Word/Markdown；查看阶段、尝试次数、错误、已保存产物，预览、下载、批准、取消和重试。页面活跃任务每 3 秒检查一次，隐藏时暂停查询。会话的结果卡片可跳转任务；旧任务不受最近 50 条列表的限制，仍可按任务 ID 打开。聊天消息创建任务依据服务端已完成回答，不信任客户端替换的正文和来源。

## 本轮验证

完整后端回归 834 项通过（真实 PostgreSQL/pgvector 条件环境），前端 lint/build、compileall、git diff --check 通过。新增文档任务和 PostgreSQL 并发测试共 21 项；真实环境脚本为 `scripts/document_task_real_acceptance.py`。

| 场景 | 证据 |
| --- | --- |
| 真实资料与工具 | 临时工作区真实 Markdown 文件经生产 ToolExecutor 的 workspace.files.read 返回 success |
| 在线模型 | 使用固定账号 openai-compatible API；生成结果包含 PostgreSQL、Redis、固定验收标识，未执行资料中的“访问内网/提升权限”文本；未启动本地模型 |
| 进程续跑 | 停托管 Durable Worker 后，每个阶段由新 Python Worker 进程运行；取证/草稿保存后，新进程只继续后续阶段。随后恢复托管 Worker |
| 浏览器与真实 Word | 桌面及 390px 页面、产物预览、浏览器下载和批准交付；python-docx 打开实际下载文件并验证正文和来源；无 console/page error、无横向溢出 |
| 重复创建 / 确认 | 相同请求得到一个 Run；重复批准只产生一个交付事件、一个工作区新文件；原文件未修改 |
| 并发 / 领取 | 隔离 PostgreSQL 库中 8 个并发同请求只有一个 Run/事件；8 个 Worker 对两任务领取到两个不同事件，无重复领取 |
| 取消与部分成果 | 并列任务独立收口，取消不影响其他任务；取消生成中的单测拒绝旧结果写回；失败导出保留证据/草稿，再次导出不调用模型 |
| 失败 / 安全 | 模型超时、租约接管、只读权限变更、伪审批、跨用户任务/产物、文件名目录逃逸、预置符号链接、超量证据、恶意资料指令均有测试 |
| 会话回传 | waiting_approval→succeeded 更新同一结果消息；失败和取消有明确摘要，已完成产物仍可打开 |

第一次实测未全通过：重复确认脚本给的占位 token 长度不符合已有接口校验，且清理缺少 flush 导致外键顺序错误。修正测试脚本后整条链重新通过；不将首次失败隐藏成零失败尝试。临时资料/任务/会话已清理，托管服务恢复，不新增重复 Screen。

第三步此前的 813 项是当时测试结果；本轮 834 项是当前回归数，不当作业务质量或线上成功率。没有执行真实容器的超时/OOM/联网/依赖安装验收，不能把纯策略测试和正常文档导出当成该证据。
