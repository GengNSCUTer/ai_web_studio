# 文档交付完成检查与异常锁释放

2026-11-16；P0-A第三小步，接续228的工具证据检查、229的最终Prompt来源检查。本轮只处理现有文档任务，不增加工具、权限、模型复核或自动补救循环。

## 用户现在怎样使用

进入“文档任务与产物”，选择工作区和资料，填写任务要求。新增可选“必需章节”，每行一个标题，最多12项，每项80字符。没有声明章节时不强加固定模板；自由文本中的隐含要求不会被自动解析为完成条件。

后台沿用原链路：授权取证 → 在线模型生成Markdown草稿 → 草稿检查 → 导出Markdown/Word → 导出检查 → 标记生成成功、回传已绑定的原会话。用户可直接下载；保存到工作区仍是另外发起并批准的可选操作。

检查未通过时使用现有`failed`状态，返回缺项，保留此前已经成功保存的阶段产物。用户可显式重试失败阶段，已保存的取证和合格草稿不会因导出失败而重做。无原会话的文档页任务不向任意聊天插入消息。

## 检查具体做什么

| 阶段 | 确定性检查 | 不能由什么代替 |
| --- | --- | --- |
| 草稿 | 正文非空且不超限；已声明的Markdown章节存在且有正文；来源清单与已保存的授权取证清单一致 | 模型说“已完成”、目录中出现标题、代码块中的示例标题 |
| 导出 | 文件名/MIME与请求一致；实际字节非空且不超1MB；Markdown解码后与草稿及来源完全一致 | 非空Base64字段或文件扩展名 |
| Word | 限制ZIP解压规模后用DOCX解析器打开；逐段对比服务端渲染的正文和来源 | 只判断ZIP头或能打开但正文不同的Word文件 |
| 持久化 | 检查通过后，阶段Artifact、Step成功与Run转换在原业务事务提交；失败诊断写入已有Run状态 | 新建一份独立且可能漂移的任务状态 |

检查结果通过任务查询的`completion`返回，并显示在页面。它只证明已声明结构、来源清单和导出内容匹配，不证明来源在语义上支持每个结论；`answer_semantics_verified=false`。历史任务没有检查结果时不倒推成“已经验证”。

来源清单检查不是逐条事实引用支持性检查；本轮也不检查自由自然语言中的全部要求、不新增自动改写报告、不开放沙箱执行。章节目前采用明确的Markdown标题，不推断同义标题或从普通段落猜章节。

## 本轮发现并修复的真实PG异常

首次缺章集成测试暴露：提交节点已经持有Outbox事件行锁，完成检查抛错后，图运行时的独立检查点连接也要读取/锁定该事件。若等外层Worker捕获异常才回滚，就形成互等。

`document_graph.py`现在在预检、提交、可选交付节点异常退出前回滚业务Session，再把异常交回LangGraph和现有Worker失败处理。原租约、Fencing、重试和审批检查不变。真实PG新增缺章、损坏导出和审批后撤销写入权限的限时测试，检查异常收口和前序产物保留。
