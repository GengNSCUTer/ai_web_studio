# 长期记忆按需注入

Chat 在访问记忆存储前，根据开关和本轮文本判断是否读取。寒暄、致谢、空消息或明确要求本轮不用记忆时，跳过记忆 SQL、Redis 和 Embedding。含跨会话指代的短问题可以用最近一条用户消息补充检索词。附件仍按本轮问题处理。

普通问答要求每条记忆都有相关性依据，最多选 3 条。事实和项目背景走词法和向量召回，过滤泛词与弱匹配，语义阈值暂定 0.55。偏好和指令通过明确主题或词法命中入选。用户主动问系统记得哪些偏好时，只读当前范围内的偏好和长期指令，最多提供 8 条。显式语言要求以当前消息为准。两条路径都遵守范围、启用状态、有效期、敏感内容及上下文预算。后续如果想让某条规则持续适用，可设为项目指令。

`memory_injection_policy.py` 决定是否查询和词法匹配条件。`memory_retrieval_service.py` 调用已有的混合检索、使用区分新策略的 Redis 缓存字段，并在网络返回后复核版本和当前授权。`chat_context_assembly_service.py` 组装最终 Prompt，记录是否跳过、读取耗时、Embedding 调用次数、实际送入条数与估算 Token。沿用现有表和 Chat API。

## 对照验证

使用同一组 11 个构造问题、SQLite、固定 Embedding 响应，比较 `70ed782` 和本次实现。以下时延为预热后 5 轮本地召回中位数。

| 指标 | 改造前 | 改造后 |
| --- | ---: | ---: |
| 无需记忆却注入 | 6/6 | 0/6 |
| 应注入记忆命中 | 5/6 | 6/6 |
| 记忆段估算 Token 合计 | 978 | 348 |
| Embedding 调用次数 | 11 | 7 |
| 本地召回 P50 | 7.70 ms | 4.92 ms |

用例包含寒暄、主动禁用、无关问答、技术主题匹配、语言偏好、偏好回顾、短追问和不同措辞的语义召回。真实 PostgreSQL/pgvector 集成测试覆盖索引召回、缓存重验和查询期间撤销。Chat 测试直接检查预算治理后的最终 Prompt。延迟和命中数字限于本地固定样本，阈值仍需用真实查询分布评估。
