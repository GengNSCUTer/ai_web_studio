## 当前边界

- 目前只支持单知识库选择。
- 知识库来源卡片只能展示片段，还不能点击跳转到文档预览并高亮 chunk。
- 暂未持久化每次知识库检索日志。
- 检索模式仍是向量检索 + 可选 rerank，还没有 Hybrid Search / BM25 / RRF。
- 暂未支持 Parent-Child chunk、元数据过滤、检索评测集。
- 图片、表格、多模态内容已经在解析预览层改善，但知识库检索阶段仍以文本 chunk 为主。

## 下一步计划

优先做 RAG-5.5 和 RAG-5.6，让当前 RAG 能力更可解释、可调试：

1. 知识库来源点击定位：从回答来源卡片打开对应文档 Markdown 预览，并高亮命中的 chunk。
2. 知识库检索日志持久化：保存 query、知识库 ID、候选 chunk、rerank 结果、最终注入片段和引用来源。
3. 多知识库检索：支持一次问答选择多个知识库，并对跨库结果做合并排序。
4. 检索策略增强：引入 Hybrid Search、BM25、RRF、Parent-Child chunk、Metadata Filter。
5. 检索质量评估：构建小型问答评测集，观测 recall、rerank 命中、答案引用覆盖率和延迟。

阶段建议：

- 先完成来源定位和检索日志。
- 再进入 RAG-6 多知识库与检索策略增强。
- 不建议立即大改成复杂 Agentic RAG，先把基础检索链路的可观测性和可调试性补齐。
