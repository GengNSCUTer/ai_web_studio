# 2026-06-14 RAG-5.6 知识库检索日志持久化

## 本轮完成

本轮完成 `RAG-5.6`：知识库检索日志持久化。

现在用户在聊天页选择知识库并提问后，后端会在知识库检索成功时保存本轮检索快照。回答下方的知识库来源卡片仍可点击定位片段，同时来源预览弹窗会展示本轮检索日志摘要。

## 实现内容

后端新增：

- `knowledge_retrieval_logs` 表。
- `KnowledgeRetrievalLog` 模型。
- `KnowledgeRetrievalLogRepository`。
- `KnowledgeRetrievalLogResponse` schema。
- 检索日志查询接口：
  - `GET /api/knowledge/retrieval-logs/{log_id}`
  - `GET /api/knowledge-bases/{knowledge_base_id}/retrieval-logs`

每条检索日志记录：

- 用户 ID。
- 会话 ID。
- 用户消息 ID。
- 助手消息 ID。
- 知识库 ID。
- 原始 query。
- retrieval mode。
- top_k。
- rerank 是否启用。
- rerank 模型。
- 候选 chunks 快照。
- 最终注入 chunks 快照。
- 上下文诊断指标。
- 回答来源快照。
- 状态、错误信息和耗时。

聊天链路改动：

- `KnowledgeContextService` 在检索成功后创建检索日志。
- 知识库来源 metadata 写入 `retrieval_log_id`。
- `ChatContextAssemblyService` 在助手消息创建后，把日志关联到当前会话、用户消息和助手消息。

前端改动：

- 新增 `KnowledgeRetrievalLog` 类型。
- 点击知识库来源定位片段时，如果来源 metadata 有 `retrieval_log_id`，会额外拉取本轮检索日志。
- `KnowledgeSourcePreviewDialog` 展示“本轮检索日志”摘要：
  - 状态。
  - 耗时。
  - Top K。
  - query。
  - 候选数量。
  - 注入数量。
  - Rerank 状态和模型。

## 当前边界

- 当前主要记录成功检索日志。
- 知识库不存在、未索引、空 query、超时、检索异常等跳过 / 失败场景暂未落独立失败日志。
- 当前前端只展示日志摘要，没有完整候选列表、rerank 前后排序对比和日志详情页。
- 旧历史消息如果没有 `retrieval_log_id` metadata，无法回溯到新日志。
