<h1>阶段 5.1：工具运行模式与多维 Budget 基础（2026-09-19）</h1>
<p>本次针对同步 Chat 固定五轮的弱点，先完成后端预算基础设施。没有直接把五轮改成更大的常量，而是增加代码侧 ToolRunPolicy + ToolRunBudget，同时限制规划轮次、总 Tool 调用数、单计划调用数、并发数、重规划次数、工具阶段墙钟时间和 evidence 字符数。</p>
<h2>已实现</h2>
<ul>
<li><code>quick_chat</code>：默认模式，保持五轮兼容；总调用 10、每计划 3、并发 2、最多 4 次续轮、工具阶段 35 秒。</li>
<li><code>guided_research</code>：用户显式选择后才可使用的八轮有限研究模式；总调用 16、每计划 3、并发 3、最多 7 次续轮、工具阶段 75 秒。</li>
<li><code>workspace_review</code>、<code>edit_proposal</code>：面向文件审阅和编辑提案的更紧预算。</li>
<li><code>durable_task</code>：仅保留为后续显式 Durable handoff 的目标模式，不在同步 Chat 中运行。</li>
</ul>
<p>Workflow 在进入 Executor 前执行单计划调用和并发限制，超额调用生成安全 Outcome；ExternalContextService 维护请求内 Budget 账本，并在预算耗尽时只允许部分收口、澄清或停止。工具阶段使用剩余墙钟时间保护，超时记录 <code>tool_wall_clock_budget_exhausted</code>。Trace、diagnostics 和 details 只暴露无敏感预算摘要。</p>
<h2>验证与边界</h2>
<p>已验证默认 quick_chat 仍为五轮；guided_research 可运行到第八轮并以 <code>max_rounds_reached</code> 停止；单计划调用数和实际 Executor 并发数均受限；未知模式失败关闭；慢工具超过墙钟预算时安全停止。定向测试 50 项通过，后端完整回归 435 项通过，5 项 PostgreSQL/pgvector 条件测试因未设置 <code>TEST_POSTGRES_URL</code> 跳过，compileall 和 git diff --check 通过。</p>
<p>本阶段只有后端基础设施，前端暂未开放模式选择，普通 Chat 仍默认 quick_chat；不会因为 Skill 或 Planner 自动提升预算。下一步再将模式作为用户显式选择传入 Chat，并在后续单独实现用户确认后的静态低风险 Durable handoff。</p>
