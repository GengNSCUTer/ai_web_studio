# 2026-06-22 RAG-6.6：BM25 持久化倒排索引

本次完成 RAG-6.6 第一版：BM25 从 query-time 全量扫描 chunks 升级为持久化倒排索引。

## 1. 本次完成

- 新增 `KnowledgeLexicalStore`。
- 索引文件保存到 `knowledge_index_dir/{knowledge_base_id}/lexical_index.json`。
- `KnowledgeIndexService.index_document()` 在 FAISS 重建后同步重建 BM25 lexical index。
- `KnowledgeRetrievalPipeline` 的 `lexical` 和 `hybrid` 检索优先使用持久化 BM25 索引。
- 如果 BM25 索引缺失、损坏或版本不兼容，检索阶段会自动基于数据库 chunks 懒重建。
- Hybrid / RRF metadata 保留 `lexical_index=persistent`。
- 删除知识库时会同步清理该知识库索引目录，避免 FAISS / BM25 孤儿文件。
- 过滤器场景下 lexical 检索会扩大候选后再过滤，减少过滤后结果不足。

## 2. 索引结构

索引目录：

```text
knowledge_index_dir/{knowledge_base_id}/
  index.faiss
  lexical_index.json
```

`lexical_index.json` 主要字段：

- `version`
- `knowledge_base_id`
- `doc_count`
- `avgdl`
- `document_lengths`
- `document_frequency`
- `chunk_refs`
- `postings`

## 3. 检索流程

```text
query
-> tokenize query
-> load lexical_index.json
-> score query terms against postings with BM25
-> map vector_id back to KnowledgeChunk
-> apply metadata filters
-> lexical results
```

Hybrid：

```text
FAISS vector results
+ persistent BM25 lexical results
-> RRF fusion
-> optional rerank
```

## 5. 当前边界

- 第一版 BM25 索引是本地 JSON 文件，适合个人知识库和调试阶段。
- 还没有 chunk 级增量索引，文档索引时仍是全库重建。
- 删除单个文档后暂不立即重建 BM25，检索时会根据数据库 chunks 映射过滤旧 id。
- 中文分词仍是轻量单字 + bigram。

## 6. 后续建议

当前 RAG 检索栈已经具备：

- Metadata Filter。
- 多知识库检索。
- FAISS 向量召回。
- BM25 持久化倒排索引。
- Hybrid RRF。
- Rerank。
- Parent-Child 上下文扩展。
- 检索日志和评测基线。

下一步建议：

1. 先用真实 PDF / 论文 / 个人资料跑更多案例，观察检索日志和回答质量。
2. 如果继续 RAG-6，优先做 `Contextual Retrieval` 小规模实验。
3. 后续补索引生命周期一致性：文档删除后的索引重建任务、索引版本管理、增量索引。
4. 数据量明显变大后，再评估 SQLite FTS / Tantivy / Elasticsearch / OpenSearch。
