# 2026-06-09 更新：知识库模型凭据拆分与测试连接

本次继续完善知识库 / RAG 阶段的模型设置能力，重点解决知识库 Embedding、Rerank 与聊天问答模型之间的配置边界问题。

## 1. 本次完成

- 设置中心左侧页签中，聊天模型配置从“模型服务”统一改为“问答模型”，避免和“知识库模型”混淆。
- 知识库模型页签中，Embedding 与 Rerank 分别拥有自己的 API Key 配置入口。
- Embedding API Key 输入框移动到 Embedding 配置卡片内。
- Rerank API Key 输入框移动到 Rerank 配置卡片内。
- 移除原来底部共享的知识库 API Key 卡片。
- “刷新模型列表”按钮改为“测试连接”，语义更清晰。
- 手动测试连接时，后端使用严格模式校验当前 Provider、Base URL、API Key。
- 设置页自动静默刷新模型候选时，后端仍使用容错模式；远程不可用时不再注入内置候选，只返回空候选和 `remote-unavailable` 来源。

## 2. 后端变化

`user_settings` 新增两个加密字段：

- `knowledge_embedding_api_key`
- `knowledge_rerank_api_key`

字段语义：

- Embedding 和 Rerank 可以使用不同云端服务、不同账号或本地/云端混合配置。
- API Key 继续通过 `SecretService` 加密保存。
- API 响应只返回 `has_api_key` 与掩码，不回显明文。
- 历史 `knowledge_api_key` 仅保留为旧数据兼容回退，不作为新 UI 主入口。

`/api/settings/knowledge-model-options` 增加 `strict` 参数：

- `strict=true`：用于用户点击“测试连接”，连接失败直接返回错误。
- `strict=false`：用于设置页自动刷新候选，失败时回退内置模型列表。

新增 `SettingService.resolve_knowledge_model_api_key(user_id, model_kind)`：

- `model_kind=embedding` 时读取 Embedding 专用 Key。
- `model_kind=rerank` 时读取 Rerank 专用 Key。
- 如果专用 Key 为空，再回退历史共享 `knowledge_api_key`。

## 3. 前端变化

- 设置中心“知识库模型”页签内的 Embedding、Rerank 卡片分别展示凭据状态、掩码、清空选项和新 Key 输入框。
- 用户点击“测试连接”时，前端会携带当前卡片里的草稿 Key 进行测试，不需要先保存。
- 测试成功后刷新候选模型列表和来源信息。
- 主工作台旧设置弹窗中“模型服务”文案同步调整为“问答模型”。
- 首页设置卡片描述调整为“问答模型、知识库模型、API Key、MCP 工具”等，减少概念混淆。

## 6. 下一步

进入 `RAG-3：Chunk、Embedding 与 FAISS` 时，需要按本次配置边界实现：

- 索引执行读取知识库创建时保存的 Embedding/Rerank provider、model、dimensions。
- 索引执行读取用户设置中的 Embedding/Rerank Base URL 和对应 API Key。
- 不再硬编码 SiliconFlow。
- 如果使用本地 Ollama，索引前需要验证模型是否存在，并在首次 embedding 后校验实际向量维度。
- 向量维度必须进入索引 metadata；模型或维度变化时需要提示重建索引。
