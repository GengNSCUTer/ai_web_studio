# 最终来源完成判定与预算对齐

2026-11-16；P0-A第二小步。上一轮的完成检查发生在工具执行结束、上下文预算治理之前，存在“工具读到了正文，但正文后来被预算裁掉，仍显示证据完整”的窗口。本轮把最终判定移动到 `final_source_map` 生成之后。

## 当前流程

`ToolWorkflow` 先得到执行证据 → `CompletionVerifier` 保存执行阶段快照 → `ContextGovernanceService` 按最终预算保留、节选或移除证据单元 → 基于同一份 `final_source_map` 再判定 → 更新 `ToolRouteRun` 的完成事件 → 最终模型、引用审计和来源卡片共享该映射。

最终判定只接收最终实际注入 Prompt 的来源。完整正文可满足已声明工具证据；完整来源被移除时不能完成；必要来源只剩节选时判为 `partial`，但节选仍可作为实际引用来源；`quality_status=invalid`、空结果和错误反馈不计入证据。它仍不做自然语言答案事实性或语义支持性验证，`answer_semantics_verified=false`。

同一个 `assistant_message_id + generation_id` 才允许更新最终完成事件。更新前锁定当前 Message 和 ToolRouteRun，旧生成、跨用户和跨会话更新都会被拒绝；重复更新只保留一条最终事件，并把旧执行阶段事件改名为 `tool_task_completion_before_governance`，不删除原工具调用、参数、来源和步骤记录。

最终回答的约束也从最终判定生成：证据完整时说明只能依据已保留正文；证据缺失或节选时要求只回答已核实部分、明确缺口，不能把节选当全文，不能把审批当写入，不能根据文件名或搜索摘要补全内容。替换约束不新增消息、不重新调用模型、不扩大预算；如果替换文本更长，则保留原有更保守约束。

## 验证结果

确定性与上下文相关测试 **71项通过**；加入真实PG消息、恢复和CAS测试后，专项回归 **128项通过**。真实浏览器流程使用在线Planner和实际临时文件，搜索→读取→回答正常，消息为`done`、浏览器错误0；最终 `tool_task_completion.assessment_stage=after_final_prompt_governance`，证据引用来自最终来源映射，临时项目已清理。

本轮没有重跑全量后端或200题Agent业务集，也没有实现答案语义支持检查、报告章节完成检查或自动补证循环。下一步应接“报告/交付产物完成条件”，而不是继续扩大工具数量；同时保留小预算和来源竞争的回归样本。
