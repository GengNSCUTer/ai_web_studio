# Chat 存储与 SSE 通知上线

会话、消息、任务状态和可重放事件继续保存在 PostgreSQL。在线读取的主要优化点是 SSE 等待期间的空查询。2026 年 11 月 27 日部署 `20261127_02` 并启用提交后的 PostgreSQL 通知。

## 请求与恢复链路

1. [订阅路由](../backend/app/api/routes/chat_runs.py)先核验用户、会话归属和事件游标。每条 SSE 在读第一页前登记本进程唤醒信号，按序号回放已提交事件。存在积压时立即翻页，事件已裁剪时读取任务快照。
2. [数据库迁移](../backend/migrations/versions/20261127_02_Chat事件提交后通知.py)在任务事件序号变化或任务被删除时登记 `pg_notify`。PostgreSQL 提交后送出任务 ID。同一事务内保存事件、状态和序号，回滚时不送出通知。
3. [监听器](../backend/app/services/chat_event_listener.py)每个 API 进程使用一个独立的 PostgreSQL 连接。同一任务的所有本地订阅者会被唤醒并重新查库。运行中的订阅每 5 秒也会查一次库。发现监听断开后立即唤醒全部订阅并恢复 250–750 毫秒的自适应轮询。重新连接并监听成功后再查一次，补读断线期间提交的事件。
4. [应用生命周期](../backend/app/main.py)管理监听连接。代码默认关闭，当前实例已开启。需要回退时把 `backend/.env` 中的 `CHAT_SSE_NOTIFY_ENABLED` 设为 `false`，用现有 Supervisor 仅重启 `backend`。数据库迁移保留。

## 隔离压测

在同一 PostgreSQL 服务上创建独立测试库，由实际 FastAPI SSE 路由和 HTTP 客户端测量。旧版取 `70ed782` 的路由。各阶段按 35 毫秒间隔建立连接，通知与自适应轮询组各空闲采样约 12 秒。流式阶段以约 150 毫秒为间隔成批提交事件。128 连接一行最多 32 个任务同时发事件，其余连接等待。以下 SQL 次数只计 SSE 分页 SQL，连接鉴权、订阅限额、驱动探活和监听连接探活另计。投递时间从写入方提交返回到 HTTP 客户端收到事件，浏览器另做功能冒烟。配额默认允许最多 16 个 Chat 同时运行，32 个任务持续发事件属于高于默认并发的受控场景。

| SSE 连接数 | 旧版空闲 SQL/秒 | 自适应空闲 SQL/秒 | 通知空闲 SQL/秒 | 自适应投递 P95 | 通知投递 P95 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 16 | 119.18 | 21.33 | 2.67 | 260 ms | 109 ms |
| 32 | 236.75 | 41.91 | 5.33 | 281 ms | 238 ms |
| 128 | 建连出现池超时 | 165.99 | 25.58 | 407 ms | 284 ms |

32 连接时空闲 SQL 下降约 87%。持续输出期间通知版的分页 SQL 从约 223 次/秒上升到 286 次/秒，连接池取连接 P95 从约 12 毫秒上升到 133 毫秒，两组均无超时。这反映出成批提交时多个订阅同时唤醒，适用的结论是空闲查询与流式延迟下降。128 个任务同时输出的另一轮自适应压力测试 P95 约 961 毫秒，容量评估采用上表同口径比较。

另用已有游标验证 128 个连接逐步重连，每条连接补读 2 条事件，两组均返回全部 256 条且连接池无超时。该轮从各自发起订阅到收到事件的 P95 为自适应 128 毫秒、通知 79 毫秒。

合成历史每条约 1.25 KB（含响应字段）。读取 1,000 条的 API P95 约 0.8 秒，10,000 条约 7–8 秒。当前实例最长会话 38 条，因此本轮先部署 SSE 通知，历史游标分页留到长会话规模出现后单独实施。上述测试计量 SSE SQL 和 HTTP 耗时。Chat 快照更新的实际 WAL 与磁盘写入量需要独立负载测量。

## 验证与部署

203 项后端回归、`compileall` 和前端生产构建通过。真实 PostgreSQL 验证两个监听连接均能收到同一任务提交、回滚不唤醒、监听被终止后按游标补读并重新连接。Playwright 验证超限提示、刷新后恢复和后续普通消息，浏览器控制台错误数为 0。

先在隔离库恢复现有数据库的副本并演练升级，再停止前后端入口、排空 Chat、暂停负责写入的 Worker。停写期间备份 PostgreSQL、上传文件和索引。数据库由 `20261118_01` 升级到 `20261127_02`，升级前后均为 68 个会话、366 条消息和 1 条 ChatRun 记录。原 Supervisor 恢复所有角色，API 确认仅打开一个监听连接。当前实例经前端代理读历史、查终态、按 `Last-Event-ID` 读取快照及拒绝其他用户订阅均通过。
