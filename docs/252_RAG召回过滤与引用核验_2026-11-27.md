# RAG 召回过滤与引用核验

2026-11-27

## 召回、过滤与执行

Vector 和 Hybrid 的向量通道先按用户配置的原始余弦下限筛选，`score_threshold=0` 关闭用户下限。RRF 和 Reranker 的名次用于排序。BM25 提供原始分数和 IDF 加权覆盖特征，词法独立门槛以留出集结果决定是否启用。向量缺席时相应分数为 `null`，避免将 RRF 或 BM25 分数展示为余弦相似度。

文档、文件类型、页码和章节先限定 Chunk 范围，再计算各通道 TopK。SQL 和词法允许集限定同一用户、知识库和 Generation，章节匹配 `section_path`、`section_title` 和 `heading`，幻灯片号保留独立含义。PostgreSQL 检索和日志用每进程 2 个线程及短 Session，每条 SQL 的 `statement_timeout` 初始为 3 秒。Chat 的既有检索超时保持 25 秒。缓存按文件身份识别 `legacy` 原子替换及新 Generation，同文件冷读去重，解析后对象按 LRU 限制为 64 MiB、最多 8 个条目。

本机 3,190,545 字节索引的重复加载测量中，12 次应用冷缓存加载 P50/P95 为 513.3/576.1 ms，1,000 次缓存命中为 0.011/0.012 ms，估算驻留 38.2 MiB。该测试只度量索引加载，文件系统缓存仍可命中。真实 PostgreSQL 回归覆盖目标排在全库前 200 名之外、慢查询数据库侧超时、取消后继续查询。

## Chat 排序和引用正文

单库 Chat 保留扩大的精排候选，父块去重后继续用门控后的候选补齐。知识库检索测试仍返回 Child 排名。多个库按局部名次轮流提供候选，全局最多 100 个候选，统一使用用户知识库 Reranker；配置关闭、请求超时或结果无效时按局部名次交错合并。最终统一编号、裁剪和关联各库日志。

同一父块被多处命中时，长父块最多保留 3 段，使用原文偏移验证。`matched_child_ids` 表示已命中，`retained_child_ids` 和 `retained_ranges` 表示实际保留，经过最终 Prompt 裁剪后更新。可引用正文由最终来源清单提供。回答充分性和任务完成度使用同一证据质量校验，节选可支持局部结论，整项完成仍检查必要文件、工具及审批状态。

在线继续在 SSE 终态核验标签。端到端评测可用 `backend/scripts/run_rag_e2e_eval.py --verify-claims` 逐条核验证据支持性，记录结论引用覆盖率、支持率与无支持断言率。评审只接收本轮答案实际看到的引用正文。真实 Provider 的合成验收正确区分了支持、矛盾和缺少引用。
