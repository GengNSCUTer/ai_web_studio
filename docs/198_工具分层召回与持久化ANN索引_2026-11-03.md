# 工具分层召回与持久化ANN索引

2026-11-03。本轮不增加工具数量，解决工具目录扩大后进程缓存失效、全量向量遍历及全目录详细打分的问题。旧版对超过128个工具退出语义检索；现在128仅作为小目录精确检索阈值，不再禁止大目录语义召回。

## 一、先看整体变化

```text
当前用户/项目目录 + Skill范围 + 用户禁止项 + 工具/凭据开关与只读策略
  → 硬过滤得到当前允许集合
  → PostgreSQL关键词/类别召回最多30 + 向量召回最多30
  → RRF融合成最多30个粗候选
  → 只对粗候选做详细规则与语义排名融合
  → 默认6个完整工具Schema交给LLM Planner
  → Executor按原有流程重新检查参数、权限、凭据、风险和审批
```

工具索引是派生搜索数据，不是权限名单，也不存可执行计划。索引结果必须同时满足当前用户、Embedding配置和当前允许工具集合，并与本轮工具说明一致；Selector再与允许集合求交。用户关闭联网、Skill不允许、项目禁用或只读模式不允许的工具不能被语义检索复活。Catalog另外提前排除用户明确禁用的Provider凭据以及只读项目内的写入/高风险工具；Executor原最终检查保留。

## 二、粗召回如何实现

新增tool_search_entries，保存用户、既有Embedding配置scope、tool_key、类别、脱敏说明、关键词索引和向量。沿用旧scope隔离账号、Provider、模型、维度、API地址与凭据轮换；scope是既有不可逆摘要，不存明文Key或API地址。工具索引独立于RAG的knowledge_chunks，不改变知识库的精确/近似检索口径。

关键词侧使用PostgreSQL tsvector/GIN：英文按词，中文取双字片段；匹配词及类别进入粗候选，按ts_rank_cd/类别加分排序。这不是BM25，也不是完整中文分词器。向量侧用当前账号已配置的在线Embedding；默认BAAI/bge-m3，1024维。每路最多30个，RRF合并再取30，详细_score_tool不再对正常语义路径的全目录运行。小目录可能不足30，不填充到固定数量。保留原已授权Tavily候选兜底，它也计入30个容量；Planner可以选择不调用。

超过128个允许工具、且维度在256/384/512/768/1024/1536/2048/3072时，走HNSW表达式索引。超过2000维的上述索引使用halfvec，低维使用vector；其他维度明确走数据库精确Top-K，而不是强行混用向量。小目录仍走数据库精确检索。HNSW设置ef_search=100、strict_order迭代扫描，保留权限和说明过滤；不足目标数量时走精确补齐并记录exact_topup。近似检索不保证召回所有精确近邻，跨租户共用图也可能影响性能和召回，当前有界迭代及补齐不等于完整的多租户分区方案。

真实测试曾发现：只建HNSW索引并不代表优化器会使用，说明匹配条件的选择率估计使其选择全表排序。现仅在明确ANN的短事务内设置enable_sort=off，降低显式排序优先级；小目录、精确补齐和其他事务不继承该设置。实际千工具查询的EXPLAIN已确认使用ix_tool_search_hnsw_256，不以索引存在冒充索引命中。

## 三、更新、冷启动和边界

不再使用进程内工具向量LRU。工具说明没有变化时读取持久条目，暖目录每个问题只调用一次query embedding；问题向量及问题正文不存入工具索引。类别/说明变化清空该条旧向量；网络返回后仅在原说明仍一致时保存，迟到Embedding不能覆盖新说明。索引保存同一用户/配置下可见工具说明，项目权限不写死在向量中，而由每次查询的当前允许集合限制。删除/禁用后的历史条目不再进入查询，但旧配置和已删除工具的派生索引目前没有自动定期清理，后续可加保留期维护。

Chat总召回截止6秒，当前安全上限10000工具，超过时退回规则并记录原因。大冷目录每轮最多补31个工具向量，加当前问题合计不超过32条输入；优先当前关键词命中的条目。未完成时记录pending_tools/index_complete，不声称已完成整个目录的语义覆盖。大型目录上线或批量安装后应先预建：

```bash
cd /disk2/gengnan/ai_web_studio
PYTHONPATH=backend backend/.venv/bin/python -m scripts.build_tool_search_index --email '<账号邮箱>'
# 限定某个项目时附加 --project-id '<项目ID>'
```

预建每批最多32条，单批网络等待最多30秒；每批成功即保存，失败后重跑复用已有向量。预建不安装或启用工具，不修改权限。在线API或索引不可用/超时时返回原规则候选；取消请求向上游传播，不把取消当普通降级。禁止使用本地Ollama建索引。SQL采用独立短Session，网络等待前释放连接；SQL也有2500ms语句/500ms锁等待截止，避免取消to_thread后数据库操作无限运行。

目录当前仍需完整装载和硬过滤，准备索引也需比较工具说明，因此尚未消除Catalog装载的O(N)。本轮消除的是Web全目录向量传输/余弦遍历，并将正常路径的详细规则评分限制为粗候选数；不能宣传每次请求只读取30条工具定义。未添加轻量LLM重排，当前规则/语义融合已有验证，无需额外模型请求。
