# 线上第一层引用审计与最终证据对齐

2026-11-03。原实现有KB/T标签与来源绑定、离线标签审计及独立Judge，但在线Chat正常结束直接写done，没有逐回复校验。来源列表也在全局预算前形成，可能继续把已裁掉资料标为used_in_prompt。本次只实现确定性第一层，不增加在线语义Judge、重写或重新生成。

## 当前链路

格式化来源时记录服务端计算的正文位置 → 全局预算治理 → 按保留前缀对齐来源 → 模型流式回答 → 终态引用审计 → 回答/审计同事务CAS保存 → citation_audit事件 → done或model_error。

知识库及Tool来源的citation_span来自格式化结构，不通过扫描不可信正文中的伪KB/T标记生成。预算后只有来源完整标题之后确实保留正文，才计入本轮可引用范围；仅剩标题、整层移除、位置未对齐或没有注册位置均不视为注入。保留片段更新display_text和正文字符数，记录是否截断；不把来源曾被召回当成最终模型输入。检索日志保留原候选/选择阶段，sources_json同步最终使用标记，并另记knowledge_sources_in_final_prompt。

来源metadata中的位置用于服务端对齐后移除，不交由模型提供权限或判定可引用。Parent-Child去重后的代表来源及命中ID沿用194的约束，不把所有兄弟命中都当成已注入全文。

## 审计规则与状态

当前规范标签为`[KB数字]`和`[T数字]`，允许大小写/数字前空格并归一化；按整份最终回答检查，因此标签跨Provider token或网络分片不影响解析。重复标签去重，转义的字面标签、围栏代码和行内代码示例不作为正文引用。未做任意论文引用格式或引用链接目标合法性的通用解析。

| 情况 | 结果 |
| --- | --- |
| 标签存在且对应正文在最终上下文 | passed，仅标签/范围有效 |
| 本轮没有该编号 | needs_review / unknown_citation |
| 编号存在但正文被裁掉或未进入最终输入 | needs_review / source_not_in_final_prompt |
| 有最终证据、普通非空正文却没有标签 | needs_review / missing_citation |
| 原有来源全部未注入，仍输出非拒答正文 | needs_review / no_injected_evidence |
| 无证据也无引用、简单寒暄、代码示例、规则能明确识别的纯拒答 | not_applicable，不强迫虚构引用 |
| 模型失败、超时或用户停止 | incomplete，不能算完整回答审计通过 |

寒暄只按短的明确query模式豁免；纯拒答仅用窄规则识别，不把包含“资料不足”又给出事实的回答自动放行。其他复杂回答可能出现需人工复核提示，不能把规则当成通用语义分类器。代码示例中仍可能有重要事实，忽略其中标签只是避免误报，不证明代码内容正确。

生成状态与审计状态分开。正常完成但有坏引用的Message仍为done，audit为needs_review；前端保留原回答并解释具体问题。流式内容此前可能已展示，本实现是结束时审计，不宣称错误内容从未发给用户，也不静默删除引用制造“修好”的假象。passed界面明确写“引用标签有效 · 未核验证据是否支持结论”。所有结果support_checked=false。

## 持久化与前端

迁移`20261103_01`新增可空messages.citation_audit TEXT。审计JSON和正文、状态、来源一起按message_id/generation_id条件更新，异步PostgreSQL与SQLite路径均覆盖。旧generation不能覆盖新答案或其审计；重生成/编辑重答清除旧审计。旧消息保持null，不回填通过；任务状态通知等非本次Chat生成的assistant消息也不冒充已审计。

正常流在持久化成功后发citation_audit，再发done；失败流发incomplete审计和model_error。断开连接后无法依赖事件继续送达，但保存成功时刷新历史仍能看到未完成状态。原纯文本流接口仍保存审计，不往纯文本里混入NDJSON；当前网页事件接口消费新增事件。若持久化本身失败，不承诺还能可靠保存审计。

前端聊天新生成与重生成路径均接收事件、渲染提示；加载历史通过MessageResponse.citation_audit恢复。引用需要复核显示黄色提示，标签通过仅显示中性说明；无适用引用检查时不额外占据页面。
