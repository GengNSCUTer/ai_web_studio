# P0-B 沙箱环境可行性探测

2026-11-17。本轮只做环境探测和最小隔离烟测，不执行用户脚本、不修改宿主机配置、不改变插件或脚本的可用状态。

## 已验证

当前进程 UID 为1007，内核为5.4.0-216-generic。服务器安装了`/usr/bin/bwrap` 0.4.0和`unshare`；`unshare`创建 user/mount/net/pid/ipc/uts namespace 的固定测试通过。Bubblewrap最小测试通过：

- 只绑定`/usr`、`/lib`、`/lib64`和本次合成输入；宿主`/home`、`/etc/shadow`、Docker socket不可见；
- 输入文件可读但不可写，根目录写入失败；
- 网络命名空间内无法连接本机32007和35433端口；
- `NoNewPrivs=1`、有效 capabilities为0，已传入`--die-with-parent`；父退出和整组清理尚需专项验收；
- 诊断环境只保留`PATH`、`LC_ALL`和进程工作目录；宿主合成输入未被修改。

固定探测脚本为`scripts/probe_sandbox_environment.py`，结果保存在`backend/evals/results/p0b-environment-20261117.json`。它只接受固定诊断参数，脚本超时或工具缺失会记录失败，不会退回宿主执行。首轮环境白名单因Bubblewrap加入`PWD`而失败；核查只存在PATH/LC_ALL/PWD后纳入工作目录字段，再运行全部通过，未放行宿主凭据。

## 当前阻断

这还不能宣布脚本沙箱可用。当前服务器仍存在以下缺口：

- `/sys/fs/cgroup/unified/cgroup.controllers`为空，尚不能使用原Docker方案要求的v2任务资源配额；现有控制器主要是cgroup v1挂载。原生路线能否以单进程seccomp和rlimit限制达到限定场景要求尚未验证，不能先宣布资源限制完成；
- 没有`newuidmap`/`newgidmap`，也没有独立的`aiws-sandbox`系统账号；Web和探测进程仍是同一用户。这阻断现有Rootless Docker部署要求，**不等于Bubblewrap本身必须安装uidmap**；本轮已实测普通账号可运行它；
- 未发现NsJail、Wasmtime或可供独立Worker使用的Rootless Docker socket；系统Docker socket归root/docker所有，不能交给Web；
- 尚未有独立沙箱Worker、固定镜像摘要和真实产物交付链路。

因此当前结论是：**B0环境探测部分完成，执行能力保持关闭（fail closed）**。Bubblewrap能证明“在这组最小挂载下可以建立一个受限进程”，不能证明共享内核上的任意Python代码已经安全，也不能替代CPU/内存/pids限制、进程清理、依赖审核和管理员威胁模型。

## 后续进入条件

下一步先验证原生Bubblewrap的**固定依赖、离线、单进程计算原型**：限制CPU/地址空间/时长/输出，阻止子进程与危险系统调用，验证取消和父进程退出能清理干净。不因最小挂载通过就开放任意Python、联网或动态安装。沿用现有任务/产物结构，避免再造并行状态系统。

若原生路线不能证明限定场景所需的资源与进程边界，再选择管理员提供可委派cgroup/独立账号，或明确授权的远端隔离服务。原Rootless Docker路线仍需独立非root账号、subuid/subgid、uidmap和可用v2控制器；不通过修改其旧检查冒充新后端。无论路线如何，都不能直接覆盖工作区或传入业务凭据。

本轮相关测试：沙箱策略、插件控制面和环境探测共34项通过。测试只验证策略和关闭边界，没有把最小Bubblewrap烟测当成真实业务验收。P0-B尚未通过，P0-C安全对抗和真实脚本执行不启动。
