# Bubblewrap离线审核脚本沙箱

2026-11-17。继234环境探测后，首版已接入原有插件中心、SandboxJob、用户确认和产物保存流程。不是任意Python执行入口：目前只运行仓库审核的`document_inventory`，不支持联网、动态依赖、Shell和覆盖原文件。

## 用户实际能做什么

在插件中心安装并启用“知识整理”，勾选项目资料，预览本次文件副本和权限，批准后由独立sandbox-worker生成资料清单。产出Markdown和JSON，可预览；点击保存才创建新的工作区草稿并下载。原文件不修改。页面显示Bubblewrap离线限制、禁用动态依赖选项，支持取消任务。

## 执行链与源码

`/plugins/sandbox/preview`固定授权文本副本、脚本摘要和后端类型；确认时复查用户/项目/插件版本、脚本及后端，禁止把Docker授权静默换成Bubblewrap。Worker短事务领取，释放事务后运行，入库前再查owner/version/expiry及插件版本；复用既有表，不新增任务状态体系。

| 文件 | 职责 |
| --- | --- |
| `sandbox/bwrap_runner.py` | 仅审核脚本、校验实际执行字节、只读副本挂载、受限输出、超时/取消清理、文本产物验证 |
| `sandbox/bwrap_bootstrap.py` | 隔离内可信引导：先设资源上限、加载默认拒绝seccomp，再执行脚本 |
| `sandbox/scripts/document_inventory.py` | 原Docker文件产物路径保留；原生后端通过stdout传回受控JSON/Markdown，不开可写目录 |
| `scripts/run_sandbox_worker.py`（backend目录内） | 显式选择后端，启动实际预检，复用租约和状态；取消或版本不匹配不导入结果 |
| `app/services/sandbox_service.py`、`app/api/routes/plugins.py` | 原预览/确认、后端能力检查、取消接口和产物资源 |
| `frontend/src/components/plugin-center.tsx` | 后端限制提示、批准/刷新/取消、产物保存入口 |

沙箱内仅挂载只读系统运行库、审核代码及合成/授权输入副本，不挂载HOME、工作区、数据库、Redis、Provider配置、Docker socket或宿主环境；不挂载proc。没有可写临时目录。主机临时输入目录在进程退出后删除，输出只走有上限管道。Web不导入执行器或获得Docker权限。

系统调用默认EPERM，只允许Python基本运行所需集合，禁止fork/clone/exec、socket、ptrace、挂载、提权及修改限额。Python3.8文件打开需要的FIOCLEX/TCGETS仅按请求号放行，不放开其他ioctl。seccomp在加载任一审核代码前生效，不能靠Python异常处理绕过。

## 本版资源语义

- 单进程、无线程/子进程；不是Docker的64进程额度。
- 地址空间硬上限256MiB（RLIMIT_AS），不冒充cgroup RSS或聚合内存限额。
- CPU累计时间45秒、墙钟45秒；不声称cgroup CPU带宽配额。
- 文件大小上限0、根和输入只读，无持久磁盘写入；最多32个FD。
- stdout和stderr累计最多1MiB；合格产物再检查名称、后缀、数量、UTF-8/空字符及大小。
- 超时、输出超量、取消、异常均终止执行并丢弃未发布产物；已取消任务不能被迟到Worker改回成功。

这是原生单进程的受限方案，没有伪造旧Docker的cgroup v2/独立账号条件。当前Worker为同一非root账号的独立进程，任务代码在namespace/seccomp里运行，不声称已完成独立系统账号隔离。

## 部署与验证

Supervisor新增唯一`sandbox-worker`角色，明确设置`AIWS_SANDBOX_BACKEND=bubblewrap`，默认autostart=false；本机已手动启动并验证。其他部署需先运行真实预检，通过后`bash deploy/run_services.sh ctl start sandbox-worker`，不支持环境会启动失败，不降级宿主执行。Docker旧入口默认仍是docker，原检查未删除。

40项相关测试通过，包括真实Bubblewrap生成中文清单、系统调用拒绝、宿主文件/环境隔离、输出洪泛、超时、512MiB内存分配失败、运行中取消和子进程回收、依赖拒绝与审批取消幂等。浏览器实测安装/项目启用/文件预览/批准/独立Worker执行/两份产物/保存新草稿/真实下载，原文件未变、页面错误0、移动端无横向溢出，临时项目及全局安装状态恢复。该流程不需要LLM，不把确定性脚本验收说成模型成功率。

首轮真实脚本曾因FIOCLEX未放行失败；定位后仅增加上述两种文件ioctl，重新执行通过。未通过放开seccomp或改为宿主执行解决。旧200题成绩和原P0-A报告保持不变。

验证记录见`backend/evals/results/bubblewrap-sandbox-20261117.json`。开发期间全量后端回归1453项通过；最终后端绑定、界面和取消细节再次通过40项定向测试及浏览器实测，前端lint/build和12项Node测试通过。全量开发回归与最终定向验证分开记录，最终提交还需通过GitHub CI。

## 当前范围与后续

已完成限定审核脚本的原生沙箱及业务闭环；尚未开放用户任意脚本、第三方未知脚本、网络、动态安装、并发线程或完整cgroup任务树配额。共享内核、系统Python和Bubblewrap版本较旧，不能宣传为面向恶意公网用户的生产强隔离。后续增加脚本须审核、更新授权摘要并重跑隔离/产物测试；泛化脚本和P0-C更广泛安全对抗另行验收。
