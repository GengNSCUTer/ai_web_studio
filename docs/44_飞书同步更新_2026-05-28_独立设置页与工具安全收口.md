## 本轮代码实现

### 1. 独立设置页第一版

- 新增独立路由：`/settings`
- 新增前端组件：`frontend/src/components/settings-center.tsx`
- 主聊天页左侧用户卡片中的“设置”按钮已切到独立设置页
- 旧设置弹窗暂时保留为“高级”入口，避免一次性移除旧能力导致回归

当前独立设置页已承接：

- 模型服务
- 生成参数
- 上下文策略
- 长期记忆概览
- 系统提示
- 工具与集成
- 工作区默认设置
- 外观
- 隐私概览

### 2. Provider / Tool API Key 安全增强

- 新增 `backend/app/services/secret_service.py`
- 用户模型 provider API Key 与工具 provider API Key 已改为加密存储
- 接口响应不再回显明文，只返回：
  - `has_api_key`
  - `api_key_masked`
- 兼容历史旧明文记录，避免数据迁移前立即报错

密钥来源：

- 优先 `SECRET_ENCRYPTION_KEY`
- 未配置时 fallback 到 `AUTH_SECRET_KEY`

### 3. 工具目录切到本地 manifest

- 新增：`backend/app/tool_manifests/default_tools.json`
- `ToolRegistry` 改为从 manifest 读取内置工具定义

当前内置工具：

- Tavily 搜索
- 高德天气
- 高德地图

这一步的价值是把“工具定义”从业务代码中抽出来，为后续：

- 补充 schema
- 扩展更多只读工具
- 引入自定义 HTTP 工具 / MCP 映射

打基础。

### 4. 设置页里的工具与工作区配置收口

- 工具 provider 支持：
  - 启用 / 禁用
  - 输入新 API Key
  - 清空已保存 API Key
  - 连通性测试
- 工作区默认模型与 System Prompt 已可在独立设置页保存回后端项目配置
- 当前工作区工具开关会随选中工作区重新加载

## 代码审查结论

本轮发现并确认的主要结构性问题：

1. 设置系统仍处于双轨过渡期

- 新的 `/settings` 已经是主入口
- 但旧设置弹窗仍保留大量历史逻辑
- 这保证了短期稳定，但也意味着后续需要继续迁移并最终删除旧逻辑

2. `chat-app.tsx` 仍然偏大

- 当前设置相关历史逻辑仍占据较大篇幅
- 下一轮最值得做的不是加更多功能，而是继续把已迁移能力从 `chat-app.tsx` 中抽离

3. 旧弹窗内仍有少量基于旧 provider key 字段的过渡逻辑

- 当前不会阻塞运行
- 但后续应继续迁移到“掩码 + draft + clear flag”这一套统一语义

## 当前遗留

- Prompt 模板完整编辑能力还没有迁入独立设置页
- 长期记忆完整 CRUD 还没有迁入独立设置页
- 导出细项仍主要依赖聊天页旧入口
- 工具目录还只是默认 manifest，尚未扩展出更完整 schema
- 暂未实现自定义 HTTP 工具、MCP Client、插件市场

## 建议下一步

1. 继续收口独立设置页

- 迁移 Prompt 模板
- 迁移长期记忆完整管理
- 迁移更多隐私 / 导出细项
- 最终删除旧设置弹窗双轨逻辑

2. 清理 `chat-app.tsx`

- 删除已被 `/settings` 替代的历史状态和表单逻辑
- 降低后续回归风险

3. 继续推进工具层

- 扩展 manifest 字段
- 再考虑自定义 HTTP 工具
- 最后再考虑 MCP Client
