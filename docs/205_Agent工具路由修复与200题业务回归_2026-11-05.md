每题保存业务类型、输入文件/版本、必需能力组、事实/来源和副作用条件。结构化分析只读取合成文本，不运行沙箱；工单只是整理交付，不连接真实业务平台。RAG的40题是原Gold的子集，不能与历史两库各100题加总成240道新的独立知识问题。

## 3. 如何真实执行

`evaluate_agent_tasks.py`是命令入口；`agent_task_batch_runner.py`按题隔离临时项目/会话，执行Chat/后台任务，逐题写JSON和HTML后清理。并发2与现有账号Chat上限一致，不改服务配置；`--case-ids`只做明确标记的子集冒烟，不能计为完整200条。

`agent_task_approval_runner.py`先请求真实在线Chat生成Diff/审批，再打开实际会话页面点击“确认并应用Diff”或“拒绝”。校验确认前不写、正文精确替换、版本只增一次、审批consumed、拒绝/旧版本不覆盖；重复确认的令牌只在内存中使用。修改后通过真实ToolExecutor再次读取工作区规范正文，不以数据库状态或文字宣称代替内容核对。旧版本题只在本题合成文件上注入一次外部修订。此处编辑对象是ProjectFile/FileRevision规范正文，不是任意宿主路径写入或覆盖原始上传文件。

`agent_task_fault_runner.py`调用实际API并检查具体拒绝分类，不能仅看到HTTP409就算安全通过；跨项目题只使用本轮两个临时项目。文档重复任务要求同Run且一个导出产物，取消要求取消终态。它们属于受控HTTP异常验证，不经过完整在线模型链的题独立标记runner，不和Chat延时混在一起比较。

### 代码与职责对照

| 文件 | 本轮关键入口/分支 | 输出或边界 |
|---|---|---|
| `backend/app/services/tools/selector.py` | `_knowledge_only`、`_eligible`、`select_async` | 仅知识库请求给空候选；混合文件请求仍保留本地能力 |
| `backend/app/services/tools/planner.py` | `LLMToolPlanner.plan`的空候选分支 | 空计划及Trace，不发规划请求、不走兜底搜索 |
| `backend/app/services/tools/action_guard.py` | `ToolActionGuard.check` | 执行前重查原用户禁令，不能从工具正文取得权限 |
| `backend/app/services/external_context_service.py` | `build_context`中的拒绝收口 | 停止换工具试探；已有有效来源保留 |
| `scripts/build_agent_tasks_200.py` | `build` | 六类题本和输入，不读答案或历史分数 |
| `scripts/agent_task_batch_runner.py` | `execute_batch`、`run_chat`、`run_document`、`cleanup` | 实际请求→持久化快照→逐题落盘→定点清理 |
| `scripts/agent_task_approval_runner.py` | `run_approval` | 真实浏览器决策→版本/正文复核→修改后工具回读 |
| `scripts/agent_task_fault_runner.py` | `run_probe` | 实际API异常分类、重复/取消边界，不新增生产故障注入接口 |
| `backend/app/services/agent_task_evaluation.py` | `summarize`、`render_html` | 保留分子/分母、负例不误算召回、只读报告 |

执行器有三类结果：`passed`表示预先写明的检查全部满足，`partial`表示仍有未满足项，`failed`表示关键安全条件失败或执行异常；`skipped`表示未实际执行。即使`passed`也只覆盖这些检查，不能推出没有其他语义错误。执行中的`not_run`占位不是最终缺前提跳过。
