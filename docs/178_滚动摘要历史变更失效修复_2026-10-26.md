# 滚动摘要：历史变更与并发写回修复

用户指出摘要边界可被删除。本次同时修复：边界仍在，但它之前已被摘要的内容发生变化。保留授权删除能力，不用禁止删除来维持摘要。

## 实际行为

1. 删除、批量删除、编辑重答和重生成先锁定所属会话。若变更落在摘要覆盖范围，在同一事务清空摘要、边界和摘要更新时间；失败一起回滚。仅变更边界之后的消息保留有效摘要。边界本身已缺失时保守失效。
2. Durable 重放或终态投影改写旧结果消息时也检查。幂等投影正文未变，不清空有效摘要。
3. Chat 组装入口固定历史文字、generation 与图片元数据副本。摘要调用前核对数据库历史并提交短事务释放锁；网络返回后重新锁定会话，直接读取数据库列核对原文、角色、顺序、消息 ID 和 generation，避免 ORM 缓存掩盖变化。
4. 历史、本轮 generation 或摘要状态变化时，不保存旧摘要，不启动本次最终回答流，返回 HTTP 409 请用户重试；现有 prepare 失败收口将占位消息标记 failed。普通摘要 Provider 异常仍回退规则摘要。
5. 有效摘要写回至最终 Prompt 组装提交之间保持短行锁，使并发删除随后能清空刚保存的摘要；网络等待不占该锁。

链路：消息变更入口 → 会话行锁 → 判断是否触及摘要范围 → 同事务失效/提交；摘要生成入口 → 固定历史 → 释放事务 → 模型/规则摘要 → 锁定并核对数据库 → 保存或 409。

## 边界

已发送给外部模型或工具的内容不能撤回；已开始的流也不承诺追溯取消。修复保护未来摘要使用及写回，不自动审计修复前已失去来源变更记录的旧摘要，不代替长期记忆撤销。绕过服务层手工改库不属于这些事务入口的覆盖范围。
