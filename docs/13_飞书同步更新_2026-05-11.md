# 2026-05-11 更新：上下文治理摘要压缩升级

## 本次完成

- 上下文治理进入“模型驱动摘要压缩”阶段。
- 滚动摘要刷新时，后端会优先调用当前会话使用的 provider/model 做一次非流式摘要生成。
- 摘要 prompt 会要求保留用户目标、明确约束、重要事实、已完成决策和待办事项，并删除低价值重复内容。
- 如果模型摘要调用失败、超时或返回空内容，系统会自动回退到原有规则式结构摘要，不影响正常聊天流式回答。
- 上下文诊断面板新增摘要观测字段：
  - 模型摘要是否使用
  - 规则摘要是否回退

## 技术变化

- `ChatProviderService` 新增统一的 `complete_chat` 非流式调用，兼容 `ollama` 和 `openai-compatible`。
- `OllamaService` 新增非流式 `/api/chat` 调用。
- `ContextGovernanceService.build_incremental_summary` 改为异步函数，支持传入摘要生成器。
- 聊天主链路保留现有滚动摘要边界机制：
  - `conversations.context_summary`
  - `conversations.context_summary_boundary_message_id`
  - `conversations.context_summary_updated_at`

## 当前边界

- 当前仍然是字符级预算估算，还不是 tokenizer 级精确预算。
- 摘要质量依赖当前 provider/model 的能力和稳定性。
- 模型摘要会在触发刷新时额外消耗一次模型调用，但不会每轮都触发。
